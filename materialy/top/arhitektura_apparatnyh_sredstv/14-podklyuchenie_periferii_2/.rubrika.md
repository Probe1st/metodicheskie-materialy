## 3. Закрытые эталонные решения практической работы (zanyatie.html)

### Вариант 1. Сетевое многофункциональное устройство
1. **Паспорт и идентификаторы:**
   - Модель: Сетевое офисное лазерное МФУ (например, HP LaserJet Pro MFP 4103fdw или Kyocera ECOSYS M2040dn).
   - Сетевой стек: IP-адрес `192.168.10.250` (статический, маска `/24`, шлюз `192.168.10.1`), MAC: `00:1E:0B:4F:A1:88`.
   - Сетевой адаптер МФУ: встроенный Ethernet 1000BASE-T, Hardware ID: `PCI\VEN_8086&DEV_15F3`.
2. **Конфигурация порта печати:**
   - **Выбор порта:** Standard TCP/IP Port, протокол **RAW**, номер порта **9100**.
   - **Отказ от WSD (Web Services on Devices):** служба WSD использует мультикаст UDP 3702 для динамического поиска. В корпоративной сети рабочие станции и оргтехника находятся в разных VLAN. Мультикаст между сегментами отсекается маршрутизатором, что приводит к периодическому переходу принтера в статус «Автономный / Не в сети» (Offline). Порт RAW 9100 передает данные через одноадресный (unicast) TCP-поток напрямую на статический IP, обеспечивая 100% надежность.
3. **Драйвер печати:**
   - Выбор: **PCL6 (PCL XL)** для ежедневного офисного документооборота (быстрая генерация промежуточного файла в Spooler, малый объем передаваемых данных по сети). Для задач верстки чертежей САПР и графики дополнительно разворачивается очередь **PostScript 3** с аппаратным RIP-растрированием.
   - Использование **Universal Print Driver (UPD)** вендора позволяет централизованно через GPO развернуть единый пакет, опрашивающий MIB-структуры принтера по протоколу SNMP и автоматически активирующий дуплекс и лотки.
4. **Верификация:**
   - Отправка тестовой страницы. Спулер Windows (`spoolsv.exe`) формирует задание `SPL`, задание отправляется на порт 9100 принтера за 0.8 с, очередь очищается мгновенно, страница печатается с двух сторон (Duplex).

### Вариант 2. Профессиональный графический планшет
1. **Паспорт и дескрипторы:**
   - Модель: Wacom Intuos Pro / Huion Inspiroy.
   - Hardware ID: `USB\VID_056A&PID_0357&REV_0100` (Wacom Co., Ltd).
   - Класс: USB HID (Base Class 03h), драйвер: вендорный KMDF (с сертификатом WHQL) + виртуальный драйвер пера.
   - Характеристики: координатная сетка электромагнитного резонанса (EMR), частота опроса 250–300 RPS, 8192 уровня градации силы нажатия, распознавание наклона пера $\pm 60^\circ$.
2. **Конфликт Windows Ink:**
   - По умолчанию Windows обрабатывает координаты дигитайзера через службу сенсорного ввода Windows Ink API.
   - **Коллизии:** при удержании пера на месте ОС запускает таймер распознавания правой кнопки мыши (появляется круговая анимация), что блокирует начало штриха (штрих запаздывает на 150–200 мс). В ряде редакторов (Photoshop, SAI) отключается нажим пера.
   - **Решение:** в панели управления драйвера планшета снимается флаг «Использовать Windows Ink» (Use Windows Ink). В графическом редакторе создается конфигурационный файл `PSUserConfig.txt` с директивой `UseSystemStylus 0`, принудительно активирующей классический библиотечный интерфейс **WinTab API** без системных задержек.
3. **Калибровка и маппинг:**
   - Установка соответствия сторон: включение опции «Пропорциональное масштабирование» (Force Proportions) для исключения сплющивания кругов в эллипсы при несовпадении пропорций планшета и широкоформатного экрана.
   - Калибровка кривой нажима: установка мягкого старта (мягкая кривая от 0 до 50 грамм силы) для тонких линий и плавного перехода к плотному закрашиванию на 8192 уровнях.
4. **Верификация:**
   - В тестовом поле драйвера проводится непрерывная спиральная линия с плавным изменением нажима от микрокасания до упора. Фиксируется динамическое изменение толщины штриха без ступеней и артефактов; задержка начала линии отсутствует.

### Вариант 3. Аудиоинтерфейс USB Audio Class 2.0
1. **Паспорт и дескрипторы:**
   - Модель: Focusrite Scarlett 2i2 4th Gen / MOTU M2.
   - Hardware ID: `USB\VID_1235&PID_8210&REV_0300` (Focusrite Audio Engineering Ltd.).
   - Класс устройства: USB Audio Class 2.0 (High-Speed 480 Мбит/с), режим тактирования — Asynchronous (асинхронный ЦАП управляет передачей пакетов от хоста через шину обратной связи).
2. **Архитектура драйвера и расчет латентности:**
   - Встроенный стек Windows WASAPI пропускает звук через программный микшер, Resampler и буферы ОС, давая общую задержку 40–80 мс.
   - Протокол **ASIO (Audio Stream Input/Output)** организует прямой доступ памяти DMA между приложением (DAW) и аппаратным буфером аудиоконтроллера.
   - **Расчет задержки:** при частоте дискретизации $F_s = 48000$ Гц:
     - Размер буфера $N = 64$ сэмпла: время буфера $T_{buf} = 64 / 48000 \approx 1.33$ мс.
     - Размер буфера $N = 128$ сэмплов: $T_{buf} = 128 / 48000 \approx 2.67$ мс.
     - Сквозная задержка (Round-Trip Latency): $RTL = T_{in\_buf} + T_{out\_buf} + T_{safety} + T_{AD/DA} \approx 1.33 + 1.33 + 1.0 + 1.2 \approx 4.86$ мс (норматив $\le 6$ мс выполнен).
3. **Борьба с дропаутами (DPC Latency):**
   - Выпадения звука (щелчки, треск) вызваны ситуацией Buffer Underrun, когда драйвер другого устройства (например, Wi-Fi адаптера или видеокарты) блокирует процессор длительным вызовом отложенной процедуры (DPC — Deferred Procedure Call).
   - Тестирование утилитой LatencyMon: все процедуры DPC должны выполняться быстрее 1000 мкс. Отключение режима энергосбережения USB Selective Suspend.
4. **Верификация:**
   - Входной сигнал гитары/микрофона воспроизводится через мониторы в реальном времени с наложенным программным эффектом; задержка не ощущается на слух, щелчки в тракте отсутствуют.

### Вариант 4. Промышленный сканер штрихкодов в режиме Virtual COM
1. **Паспорт и дескрипторы:**
   - Модель: Промышленный фотосканер Honeywell Voyager 1400g / Datalogic Gryphon.
   - Hardware ID в режиме VCP: `USB\VID_0C2E&PID_0B30` (Honeywell) или чип моста FTDI `USB\VID_0403&PID_6001`.
   - В дереве устройств: узел «Порты (COM и LPT)» &rarr; «Honeywell Scanning and Mobility Virtual COM Port (COM4)».
2. **Отказ от режима клавиатуры (USB HID POS):**
   - Режим HID эмулирует нажатие физических клавиш. Если на компьютере оператора склада включена русская раскладка клавиатуры, цифры штрихкода или буквы серийного номера сканируются кракозябрами (например, вместо буквы `A` передается скан-код `Ф`).
   - Если окно товароучетной программы потеряло фокус, штрихкод будет напечатан в случайный документ или строку поиска браузера.
   - Режим **Virtual COM Port** шлет непрерывный поток «сырых» байтов на виртуальный порт COM4. Приложению безразличен язык ОС и фокус окна: служба слушает сокет порта в фоновом режиме.
3. **Настройка параметров UART и суффиксов:**
   - Скорость: **115200** бод (или 9600 бод), биты данных: **8**, четность: **None**, стоп-биты: **1**, аппаратное управление потоком: **None** (8-N-1).
   - Программирование суффиксов: путем считывания настроечных штрихкодов из сервисного буклета в память сканера заносится суффикс `[CR][LF]` (шестнадцатеричные коды `0x0D` `0x0A`). Это заставляет программное обеспечение автоматически зафиксировать завершение передачи штрихкода.
4. **Верификация:**
   - Запуск терминала PuTTY (Connection Type: Serial, Serial line: COM4, Speed: 115200). Считывание штрихкода маркировки Datamatrix «Честный Знак». В консоль мгновенно выводится строка с автоматическим переносом каретки на новую строку.

### Задание 2. Пошаговый офлайн-алгоритм инсталляции драйвера без интернета
1. **Подготовка и распаковка:**
   - На доверенном изолированном ПК администратор открывает инсталлятор `Installer.exe` через архиватор (7-Zip / WinRAR) либо распаковывает ключом командной строки (например, `Installer.exe /extract C:\Drivers\Package\`).
   - Находится каталог, содержащий файлы манифеста (`.inf`), цифровой подписи (`.cat`) и исполнимых модулей (`.sys` / `.dll`).
2. **Проверка цифровой подписи:**
   - В контекстном меню файла `.cat` или `.sys` открывается вкладка «Цифровые подписи». Проверяется наличие валидной подписи Microsoft Windows Hardware Compatibility Publisher (WHQL) и цепочки доверенных корневых сертификатов.
3. **Инсталляция в системное хранилище Driver Store:**
   - В командной строке от имени администратора выполняется команда:
     ```cmd
     pnputil.exe /add-driver "C:\Drivers\Package\*.inf" /install
     ```
   - Ключ `/add-driver` копирует пакет в `C:\Windows\System32\DriverStore\FileRepository`, а ключ `/install` принудительно монтирует его на все подключенные совместимые устройства.
4. **Верификация в PowerShell:**
   - Выполняется опрос состояния:
     ```powershell
     Get-PnpDevice -Status OK | Where-Object { $_.InstanceId -like "*VID_0403*" }
     ```
   - Убеждаемся в наличии статуса `OK` и отсутствии предупреждающих знаков.

### Задание 3. Анализ сбоя «Код 43: Сбой дескриптора устройства»
1. **Природа сбоя:**
   - Ошибка Код 43 (`CM_PROB_FAILED_POSTING` / `STATUS_DEVICE_DATA_ERROR`) возникает на этапе аппаратного зондирования шины хост-контроллером xHCI. Контроллер отправляет запрос `GET_DESCRIPTOR` на Control Endpoint 0, но в ответ получает таймаут, сигнал обрыва линии или битые байты CRC.
   - На данном этапе операционная система еще **не приступала к поиску драйверов**, так как она не смогла вычитать даже Vendor ID и Product ID. Следовательно, переустановка программных драйверов принципиально не способна исправить ошибку Код 43.
2. **Три обязательных аппаратных действия для устранения:**
   - **Замена кабеля USB:** устранение вероятного обрыва дифференциальных линий данных D+ или D-, отказ от длинных пассивных удлинителей (>1.8–3 м).
   - **Проверка питания шины +5V:** подключение устройства в корневой порт материнской платы на задней панели ПК (минуя передние корпусные разъемы) либо использование активного USB-хаба с внешним блоком питания.
   - **Осмотр и очистка контактной группы:** устранение окисления контактов, механического люфта разъема или диагностика целостности защитных супрессоров (TVS-диодов) от статического электричества на плате периферии.

## 5. Типовые ошибки студентов и маркеры недостоверных отчетов

1. **Маркер формализма:** Студент утверждает, что для сетевого принтера "лучше всего подходит WSD, потому что он сам всё находит". Неспособность объяснить мультикаст-природу WS-Discovery и риски потери связи при смене IP.
2. **Маркер непонимания звуковых драйверов:** Указание размера аудиобуфера в 10–16 сэмплов с формулировкой "чем меньше, тем быстрее". Отсутствие понимания предела DPC Latency и неизбежности Buffer Underrun.
3. **Маркер путаницы шин:** Указание префикса `PCI\` для USB-устройств или непонимание назначения Subsystem ID у дискретных плат расширения.
4. **Маркер подмены ошибки:** Попытка объяснить Код 43 "устаревшим драйвером" или "вирусом в системе".
