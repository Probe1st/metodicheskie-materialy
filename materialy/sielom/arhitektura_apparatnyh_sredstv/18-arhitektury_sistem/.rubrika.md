### Задание 1. Систематизация по таксономии Флинна и топологии памяти

#### 1.1. Эталонное заполнение матрицы
| Класс Флинна | Потоки команд и данных | Аппаратная реализация и примеры ЭВМ | Организация памяти | Узкое место архитектуры |
| :--- | :--- | :--- | :--- | :--- |
| **SISD** | 1 поток команд (IS) / 1 поток данных (DS) | Классические одноядерные ЭВМ (PDP-11, Intel 8086), скалярные конвейерные ядра современных CPU | Единое адресное пространство, разделяемая память | Предел тактовой частоты («тепловая стена», закон Деннарда), задержки выборки из памяти |
| **SIMD** | 1 поток команд (IS) / Множество потоков данных (DS) | Векторные суперкомпьютеры (Cray-1), векторные блоки CPU (AVX-512, ARM SVE), шейдерные ядра GPU | Локальная память регистрового файла / общая память внутри блока | Расхождение ветвлений (Thread Divergence), накладные расходы загрузки данных |

| **MIMD** | Множество потоков команд (IS) / Множество потоков данных (DS) | Многоядерные процессоры (Xeon, EPYC), многосокетные серверы, MPP суперкомпьютеры (Top500) | SMP (UMA), NUMA (ccNUMA), распределенная память кластеров | Накладные расходы кэш-когерентности, латентность сети интерконнекта, барьеры |

#### 1.2. Эталонное объяснение UMA vs NUMA
**Эталонный ответ:**
В архитектуре **UMA (Uniform Memory Access)** все вычислительные ядра подключены к единому контроллеру и пулу памяти через общую шину или кроссбар. Время доступа (латентность) к любому байту физической памяти строго одинаково для любого ядра. Главное ограничение UMA — масштабируемость: при росте числа ядер общая шина быстро насыщается.
В архитектуре **NUMA (Non-Uniform Memory Access)** память физически распределена: каждый сокет (или чиплет) имеет собственный контроллер памяти и локальные модули DRAM (образуя локальный NUMA-узел). Сокеты соединены высокоскоростными когерентными интерфейсами (Intel UPI / AMD Infinity Fabric). 
Фактор **NUMA ratio** ($Latency_{Remote} / Latency_{Local}$) показывает, во сколько раз доступ к удаленной памяти соседнего сокета медленнее, чем к локальной. В современных серверах NUMA ratio составляет 1.3–2.0 (локальный доступ ~60–80 нс, удаленный ~120–160 нс). Если операционная система или планировщик СУБД случайным образом распределяют память и потоки по сокетам, постоянные транзакции через межсокетовую шину приводят к резкому падению производительности (до 30–50%).

### Задание 2. Расчет теоретической пиковой (Rpeak) и реальной (Rmax) производительности

#### 2.1. Эталонные расчеты
1. **Серверный CPU (x86-64, 2 сокета по 32 ядра = 64 ядра, 2.5 ГГц, AVX-512 FMA = 32 DP FLOP/цикл):**
   - Формула: $R_{peak} = N_{ядер} \times f \times \text{FLOP/цикл}$.
   - Расчет: $R_{peak} = 64 \times 2.5 \times 10^9 \text{ Гц} \times 32 = 5\,120 \times 10^9 \text{ FLOP/s} = \mathbf{5120 \text{ GFLOPS}} = \mathbf{5.12 \text{ TFLOPS}}$ (двойная точность FP64).
   - Эффективность Linpack при $R_{max} = 4.10 \text{ TFLOPS}$:
     $$\text{КПД} = \frac{R_{max}}{R_{peak}} \times 100\% = \frac{4.10}{5.12} \times 100\% \approx \mathbf{80.08\%}.$$

2. **Вычислительный GPU-ускоритель (6912 FP32 ядер, 1.5 ГГц, 2 SP FLOP/цикл FMA):**
   - Формула: $R_{peak} = N_{ядер} \times f \times \text{FLOP/цикл}$.
   - Расчет: $R_{peak} = 6912 \times 1.5 \times 10^9 \text{ Гц} \times 2 = 20\,736 \times 10^9 \text{ FLOP/s} = \mathbf{20\,736 \text{ GFLOPS}} = \mathbf{20.736 \text{ TFLOPS}}$ (одинарная точность FP32).
   - Эффективность Linpack при $R_{max} = 16.59 \text{ TFLOPS}$:
     $$\text{КПД} = \frac{R_{max}}{R_{peak}} \times 100\% = \frac{16.59}{20.736} \times 100\% \approx \mathbf{80.01\%}.$$

#### 2.2. Аналитическое объяснение недостатков MIPS
**Эталонный ответ:**
Метрика **MIPS (Million Instructions Per Second)** отражает лишь количество выполненных процессорных инструкций в единицу времени, но полностью игнорирует полезную работу, выполняемую одной инструкцией.
1. В архитектурах CISC (например, x86) одна комплексная инструкция может выполнять чтение из памяти, арифметическое действие и запись обратно в память. В архитектуре RISC (ARM, MIPS, RISC-V) для этого потребуется 3–4 отдельные инструкции. В результате RISC-процессор покажет формально в 3–4 раза больший MIPS, хотя прикладная задача будет решена за то же физическое время.
2. Инструкции имеют принципиально разную аппаратную стоимость: простое логическое сложение занимает 1 такт, а деление с плавающей точкой — до 15–20 тактов.
Бенчмарк **Linpack (HPL)** и пакет **SPEC CPU** объективны, поскольку измеряют время решения реальной стандартизированной математической или прикладной задачи (решение плотной системы линейных уравнений $Ax=b$ в Linpack, сборка компилятором gcc и физическое моделирование в SPEC), абстрагируясь от внутреннего набора команд процессора.

### Задание 3. Анализ масштабируемости: закон Амдала vs закон Густафсона-Барсиса

Исходные данные таблицы: доля последовательного кода $s = 0.05$, доля параллельного кода $p = 1 - s = 0.95$.
- Формула Амдала: $S_A = \frac{1}{s + \frac{p}{n}}$.
- Формула Густафсона: $S_G = s + p \times n$.

#### 3.1. Эталонная таблица расчетов
| Число процессоров ($n$) | Доля послед. кода ($s$) | Ускорение по закону Амдала ($S_A$) | Ускорение по закону Густафсона ($S_G$) |
| :--- | :--- | :--- | :--- |
| **$n = 8$** | $s = 0.05$ | $S_A = \frac{1}{0.05 + 0.95 / 8} = \frac{1}{0.05 + 0.11875} = \frac{1}{0.16875} \approx \mathbf{5.93}$ | $S_G = 0.05 + 0.95 \times 8 = 0.05 + 7.60 = \mathbf{7.65}$ |
| **$n = 64$** | $s = 0.05$ | $S_A = \frac{1}{0.05 + 0.95 / 64} = \frac{1}{0.05 + 0.01484375} \approx \mathbf{15.42}$ | $S_G = 0.05 + 0.95 \times 64 = 0.05 + 60.80 = \mathbf{60.85}$ |
| **$n = 512$** | $s = 0.05$ | $S_A = \frac{1}{0.05 + 0.95 / 512} = \frac{1}{0.05 + 0.001855} \approx \mathbf{19.28}$ | $S_G = 0.05 + 0.95 \times 512 = 0.05 + 486.40 = \mathbf{486.45}$ |
| **Предел при $n \to \infty$** | $s = 0.05$ | Предел: $\lim_{n \to \infty} S_A = \frac{1}{s} = \frac{1}{0.05} = \mathbf{20.00}$ (асимптотическое плато) | Предел: $\lim_{n \to \infty} S_G = \infty$ (линейный неограниченный рост) |

#### 3.2. Концептуальный вывод (Strong Scaling vs Weak Scaling)
**Эталонный ответ:**
- **Закон Амдала (Strong Scaling):** Предполагает фиксированный суммарный объем вычислений. С ростом числа процессоров объем работы на один процессор сокращается, а доля последовательного кода $s$ (и накладные расходы синхронизации) неизбежно начинает доминировать, жестко ограничивая предельное ускорение величиной $1/s$. Поэтому закон Амдала называют пессимистичным для суперкомпьютеров с миллионами ядер.
- **Закон Густафсона-Барсиса (Weak Scaling):** Отражает реальную практику высокопроизводительных вычислений: с ростом вычислительной мощности масштабируется и сама задача (увеличивается плотность пространственной сетки, число моделируемых частиц, размерность матриц). При этом объем полезных параллельных вычислений растет пропорционально $n$, а время выполнения последовательного кода остается практически постоянным. Это приводит к размыванию доли последовательных расходов и обеспечивает близкое к линейному ускорение ($S_G \sim n$).

### Задание 4. Эталонные решения индивидуальных кейсов (варианты 1–4)

#### Вариант 1. Симулятор аэродинамических процессов (CFD-кластер)
- **Условие:** Кластер из 128 узлов ($n = 128$). Моделирование обдува сетками Навье-Стокса. $s = 0.02$, $p = 0.98$.
- **1. Классификация и память:**
  - Класс по таксономии Флинна: **MIMD** (распределенные вычисления множества потоков команд и данных), на уровне каждого узла — гибрид MIMD (многоядерный ЦП) и SIMD (векторные инструкции AVX-512 для расчетов ячеек сетки).
  - Память: MPP (Massively Parallel Processing) — распределенная оперативная память. Каждый узел имеет собственное изолированное адресное пространство DRAM; обмен граничными значениями сетки происходит посредством отправки сообщений по протоколу MPI.
- **2. Расчет масштабируемости:**
  - По закону Амдала (Strong Scaling):
    $$S_A = \frac{1}{s + \frac{p}{n}} = \frac{1}{0.02 + \frac{0.98}{128}} = \frac{1}{0.02 + 0.00765625} = \frac{1}{0.02765625} \approx \mathbf{36.16} \text{ раз}.$$
    Эффективность параллелизации: $E_A = \frac{S_A}{n} = \frac{36.16}{128} \approx 0.2825$ или $\mathbf{28.25\%}$.
    Предел ускорения по Амдалу: $S_{max} = \frac{1}{s} = \frac{1}{0.02} = \mathbf{50}$ раз.
  - По закону Густафсона-Барсиса (Weak Scaling):
    $$S_G = s + p \times n = 0.02 + 0.98 \times 128 = 0.02 + 125.44 = \mathbf{125.46} \text{ раз}.$$
    Эффективность параллелизации: $E_G = \frac{S_G}{n} = \frac{125.46}{128} \approx 0.9802$ или $\mathbf{98.02\%}$.
- **3. Узкие места:**
  - Накладные расходы межмашинного интерконнекта при обмене граничными ячейками сетки (Halo Exchange). Задержки синхронизации глобальных барьеров (MPI_Barrier / MPI_Allreduce). Насыщение пропускной способности памяти (Memory Wall) при интенсивной выборке матриц коэффициентов.
- **4. Инженерные рекомендации:**
  - Построение неблокирующей сетевой топологии Fat-Tree (утолщенное дерево) на базе InfiniBand HDR/NDR (200–400 Gbps) с поддержкой аппаратного RDMA (прямой доступ к памяти узлов в обход стека ядра ОС).
  - Использование асинхронных неблокирующих пересылок (`MPI_Isend` / `MPI_Irecv`), перекрывающих время сетевой передачи локальными вычислениями внутренних подобластей сетки.

#### Вариант 2. Транзакционная банковская СУБД (SMP/NUMA сервер)
- **Условие:** 4-сокетный NUMA-сервер, 64 ядра ($n = 64$). Транзакционная СУБД (OLTP). $s = 0.10$, $p = 0.90$.
- **1. Классификация и память:**
  - Класс по таксономии Флинна: **MIMD** (симметричные независимые потоки транзакций).
  - Память: Архитектура **ccNUMA** (Cache-Coherent Non-Uniform Memory Access). Единое логическое 64-битное адресное пространство ОЗУ, физически разделенное на 4 NUMA-домена (по сокетам), соединенных межпроцессорными линками Intel UPI или AMD Infinity Fabric.
- **2. Расчет масштабируемости:**
  - По закону Амдала (Strong Scaling):
    $$S_A = \frac{1}{s + \frac{p}{n}} = \frac{1}{0.10 + \frac{0.90}{64}} = \frac{1}{0.10 + 0.0140625} = \frac{1}{0.1140625} \approx \mathbf{8.77} \text{ раз}.$$
    Эффективность параллелизации: $E_A = \frac{S_A}{n} = \frac{8.77}{64} \approx 0.137$ или $\mathbf{13.7\%}$.
    Предел ускорения по Амдалу: $S_{max} = \frac{1}{s} = \frac{1}{0.10} = \mathbf{10}$ раз.
  - По закону Густафсона-Барсиса (Weak Scaling):
    $$S_G = s + p \times n = 0.10 + 0.90 \times 64 = 0.10 + 57.60 = \mathbf{57.70} \text{ раз}.$$
    Эффективность параллелизации: $E_G = \frac{S_G}{n} = \frac{57.70}{64} \approx 0.9016$ или $\mathbf{90.16\%}$.
- **3. Узкие места:**
  - Высокая доля последовательного кода ($s = 0.10$) из-за жестких блокировок строк/таблиц (Row/Table Locks), очередей ожидания спинлоков (Spinlocks) и последовательного сброса журнала упреждающей записи WAL (Write-Ahead Log) на диск.
  - Межсокетовый штраф (NUMA ratio): постоянные инвалидации строк кэша по протоколу MESI при конкурентной записи в общие страницы буферного пула СУБД.
- **4. Инженерные рекомендации:**
  - Привязка процессов/пулов воркеров СУБД к конкретным NUMA-узлам (`numactl --cpunodebind=X --membind=X`) для исключения межсокетовой миграции данных.
  - Использование алгоритмов управления параллелизмом без жестких блокировок (MVCC — многоверсионность, шардирование буферных пулов).
  - Размещение журналов WAL на сверхбыстрых накопителях NVMe PCIe 4.0/5.0 или энергонезависимой памяти PMEM для минимизации задержек синхронного сброса `fsync`.

#### Вариант 3. Обучение глубоких нейросетей LLM (GPU/SIMD-ускорители)
- **Условие:** Кластер из 32 тензорных GPU ($n = 32$), масштабирование до $n = 256$. Обучение трансформеров Data Parallelism. $s = 0.04$, $p = 0.96$.
- **1. Классификация и память:**
  - Класс по таксономии Флинна: Внутри каждого GPU — массовый **SIMD / SIMT** (тысячи тензорных ядер синхронно выполняют матричные умножения GEMM над тензорами). На уровне кластера серверов — **MIMD** (независимые хост-контроллеры координируют распределенный градиентный спуск).
  - Память: Локальная высокоскоростная стековая память HBM2e/HBM3 на каждом GPU-чипе (ПСП до 2–3 ТБ/с). Межузловая память объединена через специализированную фабрику NVLink/NVSwitch с распределенным доступом.
- **2. Расчет масштабируемости:**
  - При $n = 32$:
    - По Амдалу: $S_A(32) = \frac{1}{0.04 + \frac{0.96}{32}} = \frac{1}{0.04 + 0.03} = \frac{1}{0.07} \approx \mathbf{14.29} \text{ раз}$. Эффективность: $E_A = \frac{14.29}{32} \approx \mathbf{44.64\%}$.
    - По Густафсону: $S_G(32) = 0.04 + 0.96 \times 32 = 0.04 + 30.72 = \mathbf{30.76} \text{ раз}$. Эффективность: $E_G = \frac{30.76}{32} \approx \mathbf{96.13\%}$.
  - При $n = 256$:
    - По Амдалу: $S_A(256) = \frac{1}{0.04 + \frac{0.96}{256}} = \frac{1}{0.04 + 0.00375} = \frac{1}{0.04375} \approx \mathbf{22.86} \text{ раз}$. Эффективность: $E_A = \frac{22.86}{256} \approx \mathbf{8.93\%}$ (выход на плато $\lim = 25$).
    - По Густафсону: $S_G(256) = 0.04 + 0.96 \times 256 = 0.04 + 245.76 = \mathbf{245.80} \text{ раз}$. Эффективность: $E_G = \frac{245.80}{256} \approx \mathbf{96.02\%}$.
- **3. Узкие места:**
  - Задержка фазы редукции градиентов (AllReduce) между GPU. В классической шине PCIe 4.0/5.0 пропускная способность (32–64 ГБ/с) на порядки уступает внутричиповой ПСП памяти HBM (2000–3000 ГБ/с), что делает синхронизацию градиентов главным тормозом масштабирования.
- **4. Инженерные рекомендации:**
  - Внедрение прямого интерконнекта NVLink с коммутаторами NVSwitch (до 900 ГБ/с на GPU) внутри сервера и сетевых адаптеров ConnectX InfiniBand/RoCE (400 Gbps) с поддержкой GPUDirect RDMA между серверами.
  - Использование смешанной точности FP16/BF16 и FP8 (Tensor Cores), сокращающей объем пересылаемых градиентов в 2–4 раза, а также алгоритмов ZeRO (Zero Redundancy Optimizer) для устранения дублирования весов модели в памяти.

#### Вариант 4. Бортовой комплекс космического аппарата (Fault-Tolerant MISD/MIMD)
- **Условие:** 4 независимых канала вычислений ($n = 4$) с мажоритарным голосованием (QMR). $s = 0.08$, $p = 0.92$.
- **1. Классификация и память:**
  - Класс по таксономии Флинна: Контур критического управления и ориентации реализует концепцию **MISD** (несколько вычислительных машин исполняют различные независимые программы фильтрации и расчета траектории над общим потоком телеметрии датчиков). Подсистема научной полезной нагрузки работает в режиме **MIMD**.
  - Память: Изолированная отказоустойчивая память каждого канала на базе радиационно-стойкой памяти SRAM/MRAM с аппаратным контролем четности и кодами Хэмминга (SECDED/EDAC). Разделяемая память между каналами отсутствует во избежание распространения сбоев.
- **2. Расчет масштабируемости:**
  - По закону Амдала (Strong Scaling):
    $$S_A = \frac{1}{s + \frac{p}{n}} = \frac{1}{0.08 + \frac{0.92}{4}} = \frac{1}{0.08 + 0.23} = \frac{1}{0.31} \approx \mathbf{3.23} \text{ раз}.$$
    Эффективность параллелизации: $E_A = \frac{3.23}{4} \approx 0.806$ или $\mathbf{80.65\%}$.
    Предел ускорения по Амдалу: $S_{max} = \frac{1}{s} = \frac{1}{0.08} = \mathbf{12.5}$ раз.
  - По закону Густафсона-Барсиса (Weak Scaling):
    $$S_G = s + p \times n = 0.08 + 0.92 \times 4 = 0.08 + 3.68 = \mathbf{3.76} \text{ раз}.$$
    Эффективность параллелизации: $E_G = \frac{3.76}{4} \approx 0.940$ или $\mathbf{94.00\%}$.
- **3. Узкие места:**
  - Накладные расходы времени на межпроцессорную синхронизацию циклов обмена и работу мажоритарного арбитра (Voter). Радиационные сбои (Single Event Upsets) требуют времени на перезагрузку и восстановление контекста канала (Rollback recovery).
- **4. Инженерные рекомендации:**
  - Применение аппаратного мажоритарного элемента на ПЛИС (FPGA) космического класса со схемами троирования TMR на вентильном уровне, исключающего программные задержки голосования.
  - Изоляция шин обмена данными (интерфейсы SpaceWire / MIL-STD-1553B) с гальванической развязкой, исключающая возникновение единой точки отказа (No Single Point of Failure).

## 4. Эталонные решения домашнего задания (domashnee_zadanie.html)

### Упражнение 1. Классификация и метрики
1. **1.1. Классификация систем:**
   - а) *Суперскалярный одноядерный ЦП:* Класс **SISD**. Один программный счетчик инструкций (Instruction Stream) выбирает команды, исполняемые конвейером над одним потоком данных (Data Stream).
   - б) *Тензорные ядра видеокарты:* Класс **SIMD**. Одна инструкция (например, матричное умножение-накопление FMA) одновременно выполняется над массивом числовых операндов.
   - в) *Дублированный комплекс со сверкой:* Класс **MISD**. Несколько процессоров выполняют различные алгоритмы над одним и тем же потоком входных данных с последующим голосованием.
   - г) *Суперкомпьютерный кластер:* Класс **MIMD**. Множество автономных серверов выполняют различные независимые потоки инструкций над распределенными массивами данных.
2. **1.2. Физика NUMA-штрафа:**
   - При обращении к оперативной памяти соседнего сокета запрос вынужден покидать кристалл локального процессора и передаваться через межпроцессорную шину (Intel UPI / AMD Infinity Fabric). Это добавляет физическую задержку сериализации пакетов, прохождения через коммутаторы и арбитры, а также накладные расходы протоколов кэш-когерентности. Задержка возрастает с 60–80 нс (локально) до 120–160 нс (удаленно). Для предотвращения деградации применяют привязку потоков к локальным ядрам и выделение памяти из локального узла (CPU/Memory Affinity, `numactl`).

### Упражнение 2. Расчетная задача
- **Исходные данные:** 16 узлов по 2 процессора по 16 ядер = 512 ядер ($n = 512$). Частота 2.0 ГГц, 16 DP FLOP/цикл на ядро. Доля последовательного кода $s = 0.01$ ($p = 0.99$).
1. **Расчет пиковой производительности ($R_{peak}$):**
   $$R_{peak} = N_{ядер} \times f \times \text{FLOP/цикл} = 512 \times 2.0 \times 10^9 \text{ Гц} \times 16 \text{ оп/цикл} = 16\,384 \times 10^9 \text{ FLOP/s}.$$
   $$R_{peak} = \mathbf{16\,384 \text{ GFLOPS}} = \mathbf{16.384 \text{ TFLOPS}} \text{ (двойная точность FP64)}.$$
2. **Расчет по закону Амдала ($S_A$):**
   $$S_A = \frac{1}{s + \frac{p}{n}} = \frac{1}{0.01 + \frac{0.99}{512}} = \frac{1}{0.01 + 0.0019336} = \frac{1}{0.0119336} \approx \mathbf{83.80} \text{ раз}.$$
   Эффективность: $E_A = \frac{83.80}{512} \approx 0.1637$ или $\mathbf{16.37\%}$.
   Предел ускорения при $n \to \infty$: $S_{max} = \frac{1}{s} = \frac{1}{0.01} = \mathbf{100}$ раз.
3. **Расчет по закону Густафсона-Барсиса ($S_G$):**
   $$S_G = s + p \times n = 0.01 + 0.99 \times 512 = 0.01 + 506.88 = \mathbf{506.89} \text{ раз}.$$
   Эффективность: $E_G = \frac{506.89}{512} \approx 0.9900$ или $\mathbf{99.00\%}$.
   *Вывод:* Закон Амдала показывает жесткое ограничение ускорения при неизменном объеме задачи (эффективность падает до 16.4%), тогда как закон Густафсона доказывает, что при увеличении сложности расчетной модели параллелизм 512 ядер используется почти со 100% эффективностью ($506.89\times$).
