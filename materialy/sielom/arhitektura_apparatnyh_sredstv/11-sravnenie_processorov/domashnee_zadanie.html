Разобранный образец: Выбор процессора для параллельной сборки ПО по закону Амдала

Условие задачи:

Инженер-разработчик выбирает серверный процессор для конвейера сборки проекта (CI/CD). Профиль компиляции: доля идеально распараллеливаемого кода (компиляция независимых .cpp модулей) составляет p = 0.85 (85%), а строго последовательная часть (линковка библиотек, финальная компоновка исполняемого файла) составляет 1 - p = 0.15 (15%).

Сравниваются два процессора с одинаковой микроархитектурой и идентичным показателем IPC:

  • Процессор А (Высокочастотный): 8 ядер, базовая частота под нагрузкой 4.50 ГГц, TDP 125 Вт.
  • Процессор Б (Многоядерный плотный): 16 ядер, базовая частота под нагрузкой 3.00 ГГц, TDP 125 Вт.
Пошаговое решение:
Шаг 1. Расчёт ускорения многоядерности по закону Амдала для обоих процессоров.
Формула: S(N) = 1 / ((1 - p) + p / N).
Для Процессора А (N = 8 ядер):
S_A(8) = 1 / (0.15 + 0.85 / 8) = 1 / (0.15 + 0.10625) = 1 / 0.25625 ≈ 3.902x (ускорение в 3.90 раза относительно 1 ядра той же частоты).
Для Процессора Б (N = 16 ядер):
S_B(16) = 1 / (0.15 + 0.85 / 16) = 1 / (0.15 + 0.053125) = 1 / 0.203125 ≈ 4.923x (ускорение в 4.92 раза относительно 1 ядра той же частоты).
Шаг 2. Сопоставление с учётом тактовой частоты (формула времени ЦП).
Время выполнения вычислений: T = T_seq + T_par / N = T_1 / S(N). При одинаковом IPC время на 1 ядре обратно пропорционально частоте: T_1 ∝ 1 / f.
Следовательно, суммарная относительная производительность процессора равна: Perf ∝ f × S(N).
Производительность чипа А: Perf_A = 4.50 × 3.902 ≈ 17.56 усл. ед.
Производительность чипа Б: Perf_B = 3.00 × 4.923 ≈ 14.77 усл. ед.
Отношение скорости: Perf_A / Perf_B = 17.56 / 14.77 ≈ 1.189 (+18.9% в пользу Процессора А!).
Шаг 3. Инженерно-архитектурный вывод.
Несмотря на то, что Процессор Б имеет в 2 раза больше ядер (16 против 8), он проигрывает Процессору А почти 19% скорости! Причина кроется в последовательной доле задачи (15% на линковку). Согласно закону Амдала, на 16 ядрах последовательная доля занимает 0.15 / 0.203125 = 73.8% всего времени сборки. В течение этой фазы 15 ядер чипа Б простаивают, а оставшееся активное ядро работает на низкой частоте 3.0 ГГц, уступая ядру чипа А (4.5 ГГц). Для сборки проектов выгоднее чип с меньшим числом более быстрых ядер.

Упражнение 1. Расчёт пределов ускорения серверных задач по закону Амдала

Веб-сервер СУБД обрабатывает независимые транзакции. Профиль нагрузки: p = 0.80 (80% времени занимают параллельные потоки чтения/записи, 20% — глобальные блокировки таблицы, журнал WAL и координация соединений).

Упражнение 2. Архитектурные компромиссы: IPC vs Частота vs Кэш 3D V-Cache

Сравниваются два процессора для двух различных задач: 1) профессиональный рендеринг в Blender Cycles (чистые вычисления с плавающей запятой, SIMD/AVX); 2) физическая симуляция в динамичной игре с непредсказуемыми переходами и обращением к случайным массивам памяти.

Параметр Процессор X (Флагман частоты) Процессор Y (Большой кэш 3D V-Cache)
Конфигурация ядер 16 ядер / 32 потока 8 ядер / 16 потоков
Частота всех ядер 5.40 ГГц 4.60 ГГц
Кэш L3 32 МБ 96 МБ (технология прямого стекирования)
Потребление энергии 230 Вт (PL2) 70 Вт (реальное среднее)

Упражнение 3. Расчёт энергоэффективности и выбор кулера под лимиты мощности

Процессор Intel Core i7 имеет паспортный базовый TDP (PL1) = 125 Вт и максимальный турбо-лимит (PL2) = 253 Вт при времени удержания Tau = 56 секунд. Системный администратор установил кулер с рассеиваемой мощностью до 130 Вт.

  • Объяснение (1 балл): глубокое физико-архитектурное раскрытие природы Compute-bound и Cache-bound нагрузок, влияния латентности памяти и механизмов троттлинга ЦП в Упражнениях 2 и 3.
  • Проверка (1 балл): обоснованное решение инженерного кейса по подбору охлаждения и анализу эффективности параллелизации при 64 ядрах.
