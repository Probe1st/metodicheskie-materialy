#### 1.2. Разграничение уровней параллелизма: ILP, DLP, TLP
**Эталонный ответ:**
- **ILP (Instruction-Level Parallelism — параллелизм уровня инструкций):** Реализуется аппаратно внутри одного процессорного ядра. Процессор автоматически анализирует поток скалярных инструкций, выявляет независимые операции и параллельно направляет их на разные функциональные исполнительные блоки (АЛУ, FPU, AGU). Механизмы: глубокий конвейер (Pipeline), суперскалярность, внеочередное исполнение (Out-of-Order Execution), спекулятивное выполнение с предсказанием переходов (Branch Prediction). Программист не создает отдельные потоки.
- **DLP (Data-Level Parallelism — параллелизм уровня данных):** Одна команда одновременно применяется к целому массиву независимых числовых элементов данных (принцип SIMD). Реализуется через векторные регистры и векторные АЛУ процессора (Intel AVX-512, ARM SVE) либо через массивно-параллельные потоковые мультипроцессоры GPU (CUDA cores). Требует векторизации циклов в коде.
- **TLP (Thread-Level Parallelism — параллелизм уровня потоков):** Параллельное исполнение нескольких независимых потоков управления (потоков инструкций с собственными счетчиками команд PC и наборами регистров). Реализуется аппаратно через технологию одновременной многопоточности (SMT / Intel Hyper-Threading — несколько логических потоков на ядре), симметричные физические ядра многоядерных ЦП, многопроцессорные сокеты и распределенные узлы кластера. Управляется планировщиком операционной системы или средой параллельного программирования (OpenMP, MPI, pthreads).

### Задание 2. Анализ протокола когерентности кэш-памяти MESI

#### 2.1. Эталонное заполнение таблицы состояний MESI
Каждая строка кэша в протоколе MESI может находиться в одном из 4 состояний:
- **M (Modified / Модифицированная):** Строка присутствует только в кэше текущего процессора (ядра), ее значение изменено (dirty) относительно оперативной памяти. Текущий процессор обязан записать ее в ОЗУ перед вытеснением или передать другим ядрам.
- **E (Exclusive / Эксклюзивная):** Строка присутствует только в кэше текущего ядра, ее значение совпадает с оперативной памятью (clean). Ядро может мгновенно перезаписать строку, переведя ее в состояние M без оповещения шины.
- **S (Shared / Разделяемая):** Строка может присутствовать в кэшах одного или нескольких ядер одновременно; значение идентично оперативной памяти. Запись запрещена без инвалидации копий в других кэшах.
- **I (Invalid / Недействительная):** Строка не содержит валидных данных. Любое обращение к ней вызывает кэш-промах (Cache Miss).

| Исходное состояние строки в Кэше 1 | Событие (действие) | Новое состояние в Кэше 1 | Состояние строки в Кэше 2 | Действие на шине / в ОЗУ |
| :--- | :--- | :--- | :--- | :--- |
| **I (Invalid)** | Процессор 1 выполняет чтение (Local Read), в Кэше 2 строки нет | **E (Exclusive)** | I (Invalid) | Чтение блока из ОЗУ через шину (BusRd). Кэш 1 получает монопольную копию. |
| **I (Invalid)** | Процессор 1 выполняет чтение (Local Read), в Кэше 2 строка в состоянии E | **S (Shared)** | **S (Shared)** | Кэш 2 фиксирует чтение на шине (снупинг) и переводит свою копию из E в S; Кэш 1 загружает блок как S. |
| **S (Shared)** | Процессор 1 выполняет запись (Local Write) | **M (Modified)** | **I (Invalid)** | Процессор 1 отправляет по шине сигнал инвалидации (BusInval / BusRdX). Кэш 2 сбрасывает свою копию в I. Кэш 1 обновляет данные локально. |
| **M (Modified)** | Процессор 2 инициирует чтение (BusRd от CPU 2) | **S (Shared)** | **S (Shared)** | Кэш 1 перехватывает запрос шины, передает актуальные данные Процессору 2 и сбрасывает их в ОЗУ (Write-Back), после чего обе копии становятся S. (В MOESI переход шел бы в Owner). |

#### 2.2. Анализ деградации производительности: «ложное разделение данных» (False Sharing)
**Эталонный ответ:**
**Ложное разделение данных (False Sharing)** возникает, когда два независимых потока, исполняющихся на разных процессорных ядрах, непрерывно модифицируют две логически независимые переменные (например, `count1` и `count2`), которые случайно оказались размещены компилятором в пределах одной физической строки кэш-памяти (обычно 64 байта).
- Механизм деградации:
  1. Ядро 1 выполняет запись в `count1`. Протокол MESI требует монопольного владения всей 64-байтной строкой. Ядро 1 генерирует на шине сигнал инвалидации (Invalidate), переводя строку в состояние **M** у себя и сбрасывая ее в **I (Invalid)** в кэше Ядра 2.
  2. Ядро 2 пытается модифицировать переменную `count2`. Обнаружив кэш-промах (состояние I), Ядро 2 принудительно запрашивает строку через шину, заставляя Ядро 1 выполнить обратную запись (Write-Back) в ОЗУ или пересылку Cache-to-Cache, после чего инвалидирует строку у Ядра 1.
  3. Возникает эффект «кэш-пинг-понга» (Cache Bouncing): строка непрерывно мигрирует между кэшами ядер через системную шину. Процессорные конвейеры простаивают в ожидании когерентности, реальная скорость вычислений падает в десятки и сотни раз.
- Инженерное решение: Аппаратное выравнивание критических переменных на границу кэш-линии (64 байта) с помощью директив компилятора (`alignas(64)` в C++, `__attribute__((aligned(64)))`), либо добавление искусственного заполнителя (padding), разводящего переменные в разные строки кэша.

### Задание 3. Анализ масштабируемости параллельных систем и топологий интерконнекта

#### 3.1. Эталонный расчет ускорения (Strong vs Weak Scaling)
Исходные данные: задача численного интегрирования с долей последовательного кода $s = 0.04$ ($4\%$), соответственно доля параллельного кода $p = 1 - s = 0.96$ ($96\%$).
- Формула Амдала: $S_A = \frac{1}{s + \frac{p}{n}}$.
- Предел Амдала: $S_{max} = \frac{1}{s} = \frac{1}{0.04} = \mathbf{25.00}$.
- Формула Густафсона-Барсиса: $S_G = s + p \times n = 0.04 + 0.96 \times n$.

| Число вычислительных узлов / ядер ($n$) | Ускорение по закону Амдала ($S_A$) | Эффективность по Амдалу ($E_A = S_A / n$) | Ускорение по Густафсону ($S_G$) | Эффективность по Густафсону ($E_G = S_G / n$) |
| :--- | :--- | :--- | :--- | :--- |
| **$n = 4$** | $S_A = \frac{1}{0.04 + \frac{0.96}{4}} = \frac{1}{0.04 + 0.24} = \frac{1}{0.28} \approx \mathbf{3.57}$ | $E_A = \frac{3.57}{4} \approx \mathbf{89.29\%}$ | $S_G = 0.04 + 0.96 \times 4 = \mathbf{3.88}$ | $E_G = \frac{3.88}{4} = \mathbf{97.00\%}$ |
| **$n = 16$** | $S_A = \frac{1}{0.04 + \frac{0.96}{16}} = \frac{1}{0.04 + 0.06} = \frac{1}{0.10} = \mathbf{10.00}$ | $E_A = \frac{10.00}{16} = \mathbf{62.50\%}$ | $S_G = 0.04 + 0.96 \times 16 = \mathbf{15.40}$ | $E_G = \frac{15.40}{16} = \mathbf{96.25\%}$ |
| **$n = 64$** | $S_A = \frac{1}{0.04 + \frac{0.96}{64}} = \frac{1}{0.04 + 0.015} = \frac{1}{0.055} \approx \mathbf{18.18}$ | $E_A = \frac{18.18}{64} \approx \mathbf{28.41\%}$ | $S_G = 0.04 + 0.96 \times 64 = \mathbf{61.48}$ | $E_G = \frac{61.48}{64} \approx \mathbf{96.06\%}$ |
| **$n = 256$** | $S_A = \frac{1}{0.04 + \frac{0.96}{256}} = \frac{1}{0.04 + 0.00375} = \frac{1}{0.04375} \approx \mathbf{22.86}$ | $E_A = \frac{22.86}{256} \approx \mathbf{8.93\%}$ | $S_G = 0.04 + 0.96 \times 256 = \mathbf{245.80}$ | $E_G = \frac{245.80}{256} \approx \mathbf{96.02\%}$ |

#### 3.2. Сравнение кластерных интерконнектов: Ethernet vs RoCE v2 vs InfiniBand
**Эталонный ответ:**
1. **Стандартный Ethernet (TCP/IP):** Протокол ориентирован на надежность в глобальных сетях, сопряжен с колоссальными накладными расходами. Передача каждого сообщения требует переключения контекста процессора в режим ядра (Kernel Space), прерываний, многократного копирования данных между буферами ядра и приложения, а также программного расчета контрольных сумм. Задержка (latency) составляет **10–50 мкс**, что неприемлемо для частых барьеров синхронизации MPI.
2. **RoCE v2 (RDMA over Converged Ethernet):** Позволяет использовать прямое чтение/запись в память удаленного узла (RDMA) поверх стандартной коммутационной инфраструктуры Ethernet с протоколом UDP/IP. Аппаратный сетевой адаптер (RNIC) передает данные напрямую из памяти одного приложения в память другого без участия процессора хоста и ядра ОС (Zero-Copy, Kernel-Bypass). Задержка снижается до **1.5–3 мкс**. Требует настройки бескомпенсационного управления потоком (PFC — Priority Flow Control) на коммутаторах для предотвращения потерь пакетов.
3. **InfiniBand (HDR 200G / NDR 400G):** Специализированная высокоскоростная фабрика интерконнекта для суперкомпьютеров. Аппаратный уровень управления потоком по кредитам (Credit-based Flow Control) гарантирует полное отсутствие потерь пакетов на уровне среды (Lossless Network). Обладает сверхнизкой аппаратной задержкой (**0.6–1.0 мкс**), пропускной способностью до 400 Гбит/с на порт и аппаратной поддержкой коллективных операций редукции MPI прямо в сетевых коммутаторах (NVIDIA SHARP). Оптимальный выбор для высокопроизводительных кластеров Top500.

### Задание 4. Эталонные решения индивидуальных расчетно-аналитических кейсов (варианты 1–4)

#### Вариант 1. Кластер молекулярной динамики и квантовой химии (GROMACS / VASP)
- **Условие:** 32 вычислительных узла ($n = 32$), расчет взаимодействия 5 000 000 атомов. $s = 0.03$, $p = 0.97$.
- **1. Архитектурная модель:**
  - Многомашинный кластер (MIMD) с распределенной памятью, узлы которого представляют собой 2-сокетные SMP/NUMA серверы.
  - На межузловом уровне используется модель передачи сообщений MPI (Message Passing Interface). Внутри каждого узла применяется многопоточность OpenMP (TLP) и векторные инструкции AVX-512 (DLP) для расчета межатомных сил.
- **2. Расчет масштабируемости:**
  - По закону Амдала (Strong Scaling при фиксированном числе атомов 5 млн):
    $$S_A = \frac{1}{s + \frac{p}{n}} = \frac{1}{0.03 + \frac{0.97}{32}} = \frac{1}{0.03 + 0.0303125} = \frac{1}{0.0603125} \approx \mathbf{16.58} \text{ раз}.$$
    Эффективность параллелизации: $E_A = \frac{16.58}{32} \approx 0.5181$ или $\mathbf{51.81\%}$.
    Предел масштабирования по Амдалу: $S_{max} = \frac{1}{s} = \frac{1}{0.03} \approx \mathbf{33.33}$ раза.
  - По закону Густафсона-Барсиса (Weak Scaling при пропорциональном росте сложности модели):
    $$S_G = s + p \times n = 0.03 + 0.97 \times 32 = 0.03 + 31.04 = \mathbf{31.07} \text{ раз}.$$
    Эффективность: $E_G = \frac{31.07}{32} \approx 0.9709$ или $\mathbf{97.09\%}$.
- **3. Критическое узкое место:**
  - Синхронизация пространственных границ ячеек на каждом шаге интегрирования (Halo Exchange) и вычисление глобальной электростатики методом Ewald/PME, требующее глобальных коллективных операций `MPI_Alltoall` и 3D Fast Fourier Transform (3D FFT). #### Вариант 2. Многопоточный сервер высоконагруженной СУБД (PostgreSQL / ClickHouse)
- **Условие:** 4-процессорный SMP/ccNUMA сервер (всего 128 ядер, $n = 128$). Обработка параллельных аналитических запросов OLAP. $s = 0.06$, $p = 0.94$.

- **2. Расчет масштабируемости:**

## 4. Эталонные решения домашнего задания (domashnee_zadanie.html)

### Упражнение 1. Архитектурное сопоставление
1. **1.1. Заполнение таблицы:**
   - а) *Многопрограммность в ядре Linux:* Изоляция через виртуальную память (MMU); разделяемой физической памяти у независимых процессов нет; обмен через pipes, unix-сокеты, shm; узкое место — переключение контекста, сохранение регистров и инвалидация TLB.
   - б) *Двухсокетный сервер AMD EPYC:* Симметричная разделяемая память (NUMA); обмен через прямые операции LOAD/STORE в ОЗУ; когерентность поддерживается аппаратно по шине Infinity Fabric (протокол MESI/MOESI); узкое место — задержка межсокетового доступа (NUMA ratio) и конкуренция за кэш-линии.
   - в) *Кластер из 16 узлов Gigabit Ethernet:* Полная изоляция памяти; обмен только через явные пакеты сетевого стека по протоколу MPI; узкое место — огромная задержка стека TCP/IP ядра ОС (десятки микросекунд) и ограниченная полоса пропускания 1 Гбит/с.
2. **1.2. Протокол MESI:**
   - Если ядро 1 считывает адрес, который уже находится в состоянии `Modified` в кэше ядра 2, возникает конфликт когерентности. Ядро 2 отслеживает адрес на шине (Bus Snooping), перехватывает операцию, задерживает ответ памяти и передает актуальное измененное значение ядру 1, одновременно записывая его в оперативную память (Write-Back). После этой операции строка переходит в состояние **Shared (S)** в обоих кэшах.

### Упражнение 2. Расчетная задача масштабирования
- **Исходные данные:** Кластер из 64 узлов ($n = 64$). Доля последовательного кода $s = 0.05$ ($5\%$), доля параллельного кода $p = 0.95$ ($95\%$).
1. **Расчет по закону Амдала ($S_A$):**
   $$S_A = \frac{1}{s + \frac{p}{n}} = \frac{1}{0.05 + \frac{0.95}{64}} = \frac{1}{0.05 + 0.01484375} = \frac{1}{0.06484375} \approx \mathbf{15.42} \text{ раз}.$$
   Эффективность: $E_A = \frac{15.42}{64} \approx 0.2409$ или $\mathbf{24.09\%}$.
   Асимптотический предел: $S_{max} = \frac{1}{0.05} = \mathbf{20.00}$ раз.
2. **Расчет по закону Густафсона-Барсиса ($S_G$):**
   $$S_G = s + p \times n = 0.05 + 0.95 \times 64 = 0.05 + 60.80 = \mathbf{60.85} \text{ раз}.$$
   Эффективность: $E_G = \frac{60.85}{64} \approx 0.9508$ или $\mathbf{95.08\%}$.
3. **Аналитический вывод:**
   При решении задачи постоянного размера (Strong Scaling) кластер из 64 узлов используется крайне неэффективно: ускорение составляет лишь 15.42 раза из 64 возможных, а эффективность падает до 24% из-за фиксированных последовательных накладных расходов. Однако при масштабировании размера решаемой задачи (Weak Scaling по закону Густафсона) вычислительная емкость кластера используется на 95%, обеспечивая ускорение в 60.85 раз.
