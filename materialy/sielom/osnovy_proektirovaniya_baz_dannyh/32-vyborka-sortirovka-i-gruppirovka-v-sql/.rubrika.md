# Закрытая критериальная рубрика — занятие 32

**Только для преподавателя. Не выдавать студентам до завершения оценивания.** Рубрика оценивает один аналитический запрос рабочего листа и краткое объяснение. Максимум — 4 балла.

| Критерий | Баллы | Полный уровень | Частичный уровень / ошибка |
|---|---:|---|---|
| Группировка и агрегатные функции | 0–2 | **2:** верно заданы ключи `GROUP BY`; требуемые агрегаты `COUNT`, `SUM`, `AVG` и/или нужные `MIN`, `MAX` вычислены на подходящем наборе; соблюдено правило для неагрегированных полей. **1:** группировка по существу верна, но отсутствует/ошибочно задан один агрегат или измерение; либо неверно объяснена семантика `COUNT(*)` и `COUNT(column)`. **0:** группировки нет или итоговые показатели относятся не к требуемым группам. | Типовые ошибки: в список `SELECT` попало неагрегированное поле вне ключа группировки; `COUNT(column)` принят за количество всех строк при возможных `NULL`; процент рассчитан из несовместимых единиц измерения. |
| Фильтрация групп, оконная функция, вывод | 0–1 | **1:** групповой порог правильно помещён в `HAVING`, не подменяет `WHERE`; оконная функция соответствует условию и упорядочена требуемым образом; итоговая сортировка/доля объяснена корректно. Для варианта без требуемого ранжирования балл подтверждается точным объяснением строковой фильтрации и группового фильтра. | **0:** агрегатный предикат помещён в `WHERE`; окно использовано вместо `GROUP BY` или неверно трактуются пропуски рангов; доля сравнивает неверные итоги; нет осмысленного вывода о результате. |
| Самопроверка и обоснование | 0–1 | **1:** студент называет этапы логического конвейера, объясняет отличие `WHERE` от `HAVING`, формулирует вывод по полученной выборке и самостоятельно находит/исправляет одну правдоподобную ошибку. | **0:** нет объяснения причин выбора этапов либо итоговый вывод не следует из запроса. |

## Эталонные решения

Схемы таблиц заданы в рабочем листе. Названия полей и форматирование могут отличаться, если семантика запроса сохранена. Ниже — один корректный вариант для каждого случая.

### Вариант 1 — ритейл

```sql
WITH receipt_category AS (
  SELECT sale_id, category,
         SUM(quantity * unit_price) AS check_amount
  FROM sales
  GROUP BY sale_id, category
)
SELECT category,
       SUM(check_amount) AS revenue,
       AVG(check_amount) AS avg_check,
       COUNT(*) AS receipt_count
FROM receipt_category
GROUP BY category
HAVING SUM(check_amount) > 1000000
ORDER BY revenue DESC, category ASC;
```

Сначала рассчитывается сумма товарных позиций данного чека в категории; затем `SUM` даёт оборот категории, а `AVG` — средний чек в категории. Чек с позициями разных категорий участвует в каждой соответствующей группе.

### Вариант 2 — стационар

```sql
SELECT department,
       COUNT(*) AS admission_count,
       AVG(bed_days) AS avg_bed_days,
       RANK() OVER (ORDER BY COUNT(*) DESC) AS department_rank
FROM admissions
GROUP BY department
HAVING COUNT(*) > 50
ORDER BY department_rank, department;
```

Совпавшие значения количества получают одинаковый ранг с пропуском следующего номера. Если нужна сортировка по рангу с дополнительным ключом, он задаётся во внешнем `ORDER BY`, а не в `RANK`, чтобы не разрушить равенство.

### Вариант 3 — колледж

```sql
SELECT department,
       semester,
       AVG(grade) AS average_grade,
       ROW_NUMBER() OVER (
         ORDER BY AVG(grade) ASC, department ASC, semester ASC
       ) AS result_row
FROM grades
GROUP BY department, semester
HAVING AVG(grade) < 3.8
ORDER BY result_row;
```

Если СУБД не разрешает агрегатное выражение в спецификации окна после группировки, обернуть групповой запрос в CTE и пронумеровать его строки внешним запросом.

### Вариант 4 — автопарк

```sql
WITH by_model AS (
  SELECT tractor_model,
         SUM(cargo_tons) AS total_tons,
         SUM(distance_km) AS total_km,
         SUM(cargo_tons * distance_km) AS total_tkm
  FROM trips
  GROUP BY tractor_model
), eligible_models AS (
  SELECT tractor_model
  FROM trips
  GROUP BY tractor_model
  HAVING SUM(distance_km) > 100000
), fleet_total AS (
  SELECT SUM(total_tkm) AS all_tkm
  FROM by_model
)
SELECT e.tractor_model,
       m.total_tons,
       m.total_km,
       m.total_tkm,
       100.0 * m.total_tkm / NULLIF(f.all_tkm, 0) AS turnover_pct
FROM eligible_models AS e
JOIN by_model AS m ON m.tractor_model = e.tractor_model
CROSS JOIN fleet_total AS f
ORDER BY m.total_km DESC, e.tractor_model;
```

Грузооборот выражен в тонно-километрах: масса груза умножается на расстояние рейса. `HAVING` отбирает модели по суммарному пробегу. Знаменатель доли рассчитан отдельно по всем моделям до фильтра; `NULLIF` предотвращает деление на ноль, `100.0` исключает целочисленное деление.

Во время оценивания принимать эквивалентное решение, если доля рассчитана от общего грузооборота всех моделей, а не только прошедших порог пробега.

## Калибровка оценки

- **4 балла:** запрос семантически верен, групповые и оконные расчёты объяснены, вывод обоснован.
- **3 балла:** решение в основном верно, но есть одна локальная ошибка в агрегате, фильтре, сортировке или объяснении.
- **2 балла:** студент понимает группировку, но допускает существенную путаницу между строковым и групповым фильтром или некорректно использует окно.
- **1 балл:** есть попытка построить запрос, однако его группировка не даёт требуемого результата.
- **0 баллов:** решение отсутствует либо не относится к условию.

Снижение балла не дублируется за одну и ту же ошибку в нескольких формулировках критерия; оценивается проявленная компетенция, а не форматирование SQL.
