Тема 5. Организация запросов SQL — Выборка, сортировка и группировка в SQL

Фундаментальные основы аналитической обработки данных: логический конвейер выполнения SELECT, агрегация данных, операторы GROUP BY и HAVING, расширенная аналитика и базовые оконные функции.

1. Логический конвейер выполнения оператора SELECT

В отличие от языков императивного программирования (C++, C#, Python), где инструкции исполняются строго сверху вниз в порядке написания, язык SQL является декларативным. Программист описывает какой результат он желает получить, а реляционный оптимизатор СУБД самостоятельно определяет оптимальный физический план выполнения.

Однако с логической точки зрения оператор SELECT всегда обрабатывается по строго фиксированному конвейеру фаз. Нарушение понимания этой последовательности приводит к 90% распространенных ошибок новичков.

1. FROM & JOIN
Определяется источник данных: базовые таблицы, представления, подзапросы. Выполняются операции соединений (INNER, LEFT, RIGHT, FULL) с проверкой предикатов ON. Формируется виртуальная рабочая таблица.
2. WHERE
Построчная фильтрация исходных кортежей. Каждая строка проверяется на соответствие предикату. Строки, вернувшие FALSE или NULL, исключаются. Агрегатные функции здесь запрещены!
3. GROUP BY
Формирование групп строк на основе идентичности значений в указанных колонках группировки. Множество строк с одинаковым ключом сворачивается в одну агрегированную строку.
4. HAVING
Фильтрация сформированных групп. Проверяются предикаты, оперирующие агрегатными функциями над группами. Группы, не удовлетворяющие условию, удаляются из набора.
5. SELECT
Вычисление выражений выходной проекции: расчет математических выражений, вычисление оконных функций (OVER), назначение пользовательских псевдонимов (алиасов).
6. DISTINCT
Устранение дублирующихся строк из сформированного набора данных (если модификатор указан явно).
7. ORDER BY
Сортировка результирующего набора строк (ASC / DESC). Здесь разрешено использовать алиасы, объявленные в SELECT!
8. LIMIT / OFFSET
Ограничение физического количества возвращаемых строк клиенту и пропуск первых N записей.
Закон видимости алиасов: Почему в секции WHERE нельзя написать WHERE total_amount > 500, если в SELECT объявлено SELECT price * qty AS total_amount? Потому что на момент работы фазы WHERE (фаза №2) секция SELECT (фаза №5) еще даже не начинала выполняться, и СУБД ничего не знает о псевдониме total_amount.

2. Агрегатные функции SQL и работа со значениями NULL

Агрегатная функция вычисляет скалярное значение на основе набора значений столбца. В реляционном стандарте SQL определены 5 базовых агрегатных функций:

Функция Назначение Поведение при наличии NULL
COUNT(*) Подсчет общего числа физических строк в группе Включает абсолютно все строки, даже если все поля равны NULL
COUNT(колонка) Подсчет количества заполненных значений в колонке Игнорирует NULL! Строки с NULL в данной колонке не учитываются
SUM(колонка) Суммирование числовых значений Игнорирует NULL. Если все значения в группе NULL — возвращает NULL
AVG(колонка) Вычисление среднего арифметического значения Игнорирует NULL: сумма делится только на количество не-NULL строк!
MIN(колонка) / MAX(колонка) Поиск минимального / максимального значения Игнорирует NULL. Работает с числами, датами и текстовыми строками
Внимание к семантике NULL: если в предметной области NULL означает отсутствие сведений о стипендии, AVG(stipend) усредняет известные значения, но не включает пропуски в знаменатель. Только если NULL по принятому правилу означает нулевую стипендию, выражение AVG(COALESCE(stipend, 0)) добавляет такие значения как нули (в примере результат 7 500.00 вместо 10 000.00).

3. Группировка строк: оператор GROUP BY

Предложение GROUP BY объединяет кортежи таблицы, имеющие одинаковые значения в указанных столбцах, в единую логическую запись-группу. После этого к каждой группе применяются агрегатные функции.

Важно: диаграмма показывает логическое преобразование набора. Реальная СУБД может выбрать другой физический алгоритм, но обязана сохранить семантику запроса.

Фундаментальное правило колонок:

Любая колонка, указанная в списке выборки SELECT, обязана либо входить в предложение GROUP BY, либо находиться внутри аргумента агрегатной функции (SUM, COUNT и др.).

-- Демонстрационная схема: заказы интернет-магазина
-- orders (id, customer_id, category, amount, order_date)

-- Расчет суммарного оборота и среднего чека по категориям товаров
SELECT 
  category,
  COUNT(*) AS total_orders,
  SUM(amount) AS total_revenue,
  ROUND(AVG(amount), 2) AS avg_ticket,
  MIN(amount) AS min_order,
  MAX(amount) AS max_order
FROM orders
GROUP BY category
ORDER BY total_revenue DESC;

4. Фильтрация агрегированных данных: HAVING против WHERE

Критически важно различать область ответственности предикатов WHERE и HAVING:

  • WHERE: фильтрует исходные физические строки таблицы ДО момента группировки. В секции WHERE невозможно использовать агрегатные функции.
  • HAVING: фильтрует готовые группы ПОСЛЕ того, как группировка и расчет агрегатов завершены. В секции HAVING используются агрегатные функции и поля группировки.
-- Комплексный аналитический запрос:
-- Найти категории товаров, у которых суммарная выручка по ОПЛАЧЕННЫМ заказам превысила 1 000 000 руб.
SELECT 
  category,
  COUNT(*) AS paid_orders_count,
  SUM(amount) AS category_revenue
FROM orders
WHERE status = 'PAID'              -- 1. Фильтруем строки ДО группировки (только оплаченные)
GROUP BY category                  -- 2. Сворачиваем строки в группы по категориям
HAVING SUM(amount) > 1000000       -- 3. Фильтруем группы ПОСЛЕ агрегации (оборот > 1 млн)
ORDER BY category_revenue DESC;    -- 4. Сортируем итоговый отчет

5. Расширенные средства группировки: ROLLUP, CUBE, GROUPING SETS

При построении многомерных отчетов (OLAP) часто требуется получить агрегаты разного уровня детализации в одном результирующем наборе:

  • ROLLUP(a, b) — вычисляет иерархические подытоги: (a, b) → (a) → () (общий итог).
  • CUBE(a, b) — строит многомерный куб: вычисляет все возможные комбинации: (a, b), (a), (b), ().
  • GROUPING SETS ((a), (b)) — вычисляет только явно перечисленные группировки.
-- Иерархический отчет по продажам с промежуточными и общими итогами
SELECT 
  branch_city,
  product_type,
  SUM(sales_volume) AS total_sales
FROM company_sales
GROUP BY ROLLUP (branch_city, product_type);

6. Введение в аналитические оконные функции

Оконная функция производит расчет по набору строк (называемому окном), связанному с текущей строкой. Главное отличие от GROUP BY: строки не схлопываются, количество строк на выходе строго равно количеству строк на входе.

Общая структура окна:
FUNCTION() OVER ( PARTITION BY [поле_деления] ORDER BY [поле_сортировки] )
• PARTITION BY — делит таблицу на независимые логические группы (окна).
• ORDER BY — упорядочивает строки внутри каждого окна.

Функции нумерации и ранжирования

  • ROW_NUMBER() — генерирует строгий непрерывный порядковый номер записи внутри окна (1, 2, 3, 4...).
  • RANK() — присваивает ранг. Одинаковые значения получают одинаковый ранг, при этом следующий ранг перескакивает через пропущенные позиции (1, 2, 2, 4...).
  • DENSE_RANK() — «плотный» ранг. Одинаковые значения получают один номер, но следующий ранг не перескакивает (1, 2, 2, 3...).
Студент Балл ROW_NUMBER() RANK() DENSE_RANK()
Иванов 95 1 1 1
Петров 90 2 2 2
Сидоров 90 3 2 2
Кузнецов 82 4 4 (номер 3 пропущен) 3 (без пропуска)

7. Вопросы и тестовые задания для самопроверки

Вопрос 1: В каком логическом порядке СУБД исполняет секции SQL-запроса?

Варианты: А) SELECT → FROM → WHERE → GROUP BY; Б) FROM → WHERE → GROUP BY → HAVING → SELECT; В) FROM → SELECT → WHERE → ORDER BY.

Показать правильный ответ и пояснение

Ответ: Б. Логический порядок: FROM (выбор таблиц) → WHERE (построчный фильтр) → GROUP BY (группировка) → HAVING (фильтр групп) → SELECT (вычисление проекции) → DISTINCT → ORDER BY → LIMIT.

Вопрос 2: В чем ключевая разница между COUNT(*) и COUNT(column_name)?

Как поведет себя каждая функция, если в таблице из 10 строк у 3 записей в поле column_name содержится значение NULL?

Показать правильный ответ и пояснение

Ответ: COUNT(*) вернет 10 (считает все кортежи физически), а COUNT(column_name) вернет 7, так как игнорирует строки, где проверяемое поле равно NULL.

Вопрос 3: Почему запрос SELECT dept, AVG(salary) FROM emp WHERE AVG(salary) > 50000 GROUP BY dept; вызовет синтаксическую ошибку?
Показать правильный ответ и пояснение

Ответ: Потому что секция WHERE выполняется до того, как строки сгруппированы по отделам. Агрегатную функцию AVG(salary) можно использовать для фильтрации групп только в секции HAVING.

Вопрос 4: Чем отличается результат RANK() от DENSE_RANK() при наличии двух вторых мест?
Показать правильный ответ и пояснение

Ответ: RANK() после двух вторых мест присвоит следующему участнику 4-е место (пропустив 3). DENSE_RANK() присвоит следующему участнику 3-е место без образования пропусков в ранжировании.
