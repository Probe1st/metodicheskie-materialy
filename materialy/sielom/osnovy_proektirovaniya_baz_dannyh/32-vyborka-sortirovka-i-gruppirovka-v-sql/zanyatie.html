Рабочий лист: выборка, сортировка и группировка в SQL

ОП.08 Основы проектирования баз данных · занятие 32 · аналитический запрос: сформируйте итоговую выборку, объясните фильтры и прочитайте результат.

Ответы сохраняются только в этом браузере на этом устройстве. Экспортируйте или распечатайте страницу перед очисткой браузерных данных.

Алгоритм работы

  1. Определите исходную таблицу и условие отбора строк для WHERE.
  2. Укажите измерения в GROUP BY и нужные агрегаты.
  3. Отберите готовые группы через HAVING; агрегат не помещайте в WHERE.
  4. Задайте понятную сортировку через ORDER BY; оконную функцию применяйте к сохранённым строкам.
  5. Проверьте, что каждый выбранный неагрегированный столбец входит в GROUP BY.

Схемы ниже — учебные предположения: названия таблиц и полей заданы в условиях, создание физической базы не требуется. Денежные поля предполагаются числовыми, суммы в примерах — в рублях.

Вариант 1. Аналитика продаж ритейл-сети

sales(sale_id, sold_at, category, product_id, quantity, unit_price). Одна строка — позиция товара в чеке; цена фиксируется в поле unit_price.

Составьте запрос, который по категориям рассчитывает суммарный оборот через SUM(quantity * unit_price) и средний чек категории через AVG суммы позиций в одном чеке. Также выведите количество чеков в каждой категории. Оставьте категории с оборотом больше 1 000 000 рублей с помощью HAVING; отсортируйте оборот по убыванию, затем название категории по возрастанию.

Чтобы посчитать средний чек по категории, сначала агрегируйте позиции до уровня sale_id, category, затем сгруппируйте суммы чеков по категории. Один чек, содержащий разные категории, даёт отдельную сумму для каждой пары «чек — категория».

Вариант 2. Статистика медицинского стационара

admissions(admission_id, department, admitted_at, discharged_at, bed_days). Одна строка — завершённая или текущая госпитализация; bed_days содержит длительность в койко-днях.

По отделениям посчитайте количество госпитализаций через COUNT(*) и средний койко-день через AVG(bed_days). Оставьте отделения с числом госпитализаций больше 50, используя HAVING COUNT(*) > 50. Добавьте RANK() по убыванию числа госпитализаций и сортировку по рангу, затем по названию отделения.

Оконный ранг рассчитывается после группировки: примените RANK() OVER (ORDER BY COUNT(*) DESC). При равном числе госпитализаций отделения получают одинаковый ранг.

Вариант 3. Аналитика образовательных результатов колледжа

grades(student_id, department, semester, discipline, grade, assessed_at). Одна строка — оценка студента за дисциплину в семестре; числовая шкала оценок — от 2 до 5.

Для каждой кафедры и семестра рассчитайте средний балл. Оставьте группы, где среднее меньше 3.8, условием HAVING AVG(grade) < 3.8. Пронумеруйте строки результата через ROW_NUMBER() так, чтобы сначала шёл самый низкий средний балл, затем кафедра, затем семестр. Выведите кафедру, семестр, среднее и номер строки.

Группировка выполняется по двум полям. Для детерминированной нумерации используйте одинаковый полный порядок в оконном выражении и финальном ORDER BY.

Вариант 4. Логистический учёт автопарка

trips(trip_id, tractor_model, trip_date, distance_km, cargo_tons). Одна строка — рейс; distance_km — пробег тягача в рейсе, cargo_tons — масса груза.

По моделям тягачей рассчитайте суммарный тоннаж SUM(cargo_tons), общий пробег SUM(distance_km) и грузооборот в тонно-километрах SUM(cargo_tons * distance_km). Оставьте модели с общим пробегом больше 100 000 км через HAVING. Рассчитайте долю модели в общем грузообороте всего автопарка в процентах.

Сначала получите агрегаты по всем моделям, включая total_tkm (тонно-километры); знаменатель доли должен включать все модели до фильтра по пробегу. Затем оставьте модели выше порога через групповой отбор. Обратите внимание на деление на ноль и целочисленное деление; используйте точный числовой тип.

Самопроверка

  • В каждом запросе условие по агрегату находится в HAVING, а не в WHERE.
  • Выбранные неагрегированные измерения перечислены в GROUP BY.
  • Порядок сортировки указан явно, включая направление и разрешение равенств.
  • В окне заданы необходимые разделение и порядок; оконная функция не подменяет групповую агрегацию.
  • В варианте 4 доля рассчитана относительно всех моделей, а отбор по пробегу не сужает знаменатель.
