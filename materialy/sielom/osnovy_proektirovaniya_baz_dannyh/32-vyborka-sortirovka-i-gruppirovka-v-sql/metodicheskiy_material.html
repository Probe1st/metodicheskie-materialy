2. Фундаментальный логический конвейер выполнения SELECT

Одной из ключевых концептуальных трудностей для обучающихся является противоречие между лексическим порядком написания оператора SELECT и реальным логическим порядком его выполнения ядром СУБД. Преподаватель обязан зафиксировать строгую последовательность фаз:

1
FROM & JOIN: Идентификация целевых таблиц, вычисление декартова произведения и применение предикатов соединения (ON). Формируется базовый виртуальный набор кортежей.
2
WHERE: Построчная строгая фильтрация кортежей. Отбрасываются строки, для которых булево выражение не возвращает TRUE (включая NULL). Агрегатные функции здесь категорически недопустимы, так как группы еще не сформированы!
3
GROUP BY: Сворачивание отфильтрованных строк в агрегированные кортежи по уникальным комбинациям значений указанных столбцов. Множество строк с одинаковым ключом сжимается в одну группу.
4
HAVING: Фильтрация сформированных групп на основе предикатов, оперирующих агрегатными функциями или полями группировки. Группы, не удовлетворяющие условию, удаляются из результирующего потока.
5
SELECT: Вычисление выражений проекции, применение математических функций, присвоение псевдонимов колонкам (алиасов) и вычисление оконных функций (OVER). Именно поэтому алиасы, объявленные в SELECT, НЕ видны в секциях WHERE и HAVING.
6
DISTINCT: Устранение дублирующихся строк из сформированного набора проекции (если указано).
7
ORDER BY: Финальная сортировка сформированного набора данных. На этой фазе разрешено использовать псевдонимы колонок, вычисленные на этапе SELECT, а также порядковые номера столбцов.
8
LIMIT / OFFSET: Ограничение физического количества возвращаемых клиенту строк и смещение курсора выборки.
Педагогический акцент: Студенты часто пытаются написать WHERE SUM(amount) > 1000. Следует визуализировать это на доске: «СУБД читает строки по одной. Она еще не знает общей суммы, потому что не прочитала таблицу целиком и не сгруппировала строки. Поэтому WHERE не может работать с суммами групп!».

3. Агрегатные функции и группировка GROUP BY

Агрегатная функция принимает множество значений столбца и возвращает единственное скалярное значение. Преподавателю необходимо разобрать особенности обработки значений NULL:

  • COUNT(*) — подсчитывает общее физическое количество кортежей в группе, включая строки со значениями NULL во всех полях.
  • COUNT(column_name) — подсчитывает количество кортежей, где значение конкретного столбца НЕ равно NULL.
  • SUM(column_name) — вычисляет арифметическую сумму числовых значений. Если в группе все значения NULL, возвращает NULL (не ноль!). Для надежности рекомендуется оборачивать в COALESCE(SUM(col), 0).
  • AVG(column_name) — среднее арифметическое. В знаменателе учитывается только количество не-NULL значений! Пропуск NULL может исказить статистику, если NULL семантически означал нулевой результат.
  • MIN(column_name) / MAX(column_name) — нахождение минимального и максимального значения. Применимы не только к числам, но и к датам, меткам времени и текстовым строкам (лексикографический порядок).

Синтаксическое правило одиночных колонок в GROUP BY

Если в предложении SELECT указана колонка, не обернутая в агрегатную функцию, она обязана присутствовать в секции GROUP BY. Исключение в стандарте SQL:1999/PostgreSQL — если группировка выполняется по первичному ключу таблицы, функционально зависимые колонки этой же таблицы можно не дублировать в GROUP BY.

-- ОШИБКА: колонка category_name не входит в GROUP BY
SELECT category_name, product_name, AVG(price)
FROM products
GROUP BY category_name; -- СУБД отвергнет запрос!

-- КОРРЕКТНЫЙ ЗАПРОС:
SELECT category_name, AVG(price) AS avg_price, COUNT(*) AS items_cnt
FROM products
GROUP BY category_name;

Расширенная группировка: GROUPING SETS, ROLLUP, CUBE

Для построения отчетов с промежуточными и общими итогами без применения ресурсоемких объединений UNION ALL используются расширения стандарта:

  • GROUP BY ROLLUP (year, quarter, region) — формирует иерархические подытоги: (year, quarter, region) → (year, quarter) → (year) → () [общий итог]. Число группировок: N + 1.
  • GROUP BY CUBE (category, region) — строит гиперкуб данных, вычисляя все возможные комбинации подмножеств: (category, region), (category), (region), (). Число группировок: 2^N.
  • GROUP BY GROUPING SETS ((category), (region), ()) — позволяет явно задать требуемые срезы агрегации, исключая ненужные промежуточные вычисления.

4. Базовые оконные функции (Window Functions)

Оконные функции производят вычисления над набором строк, логически связанных с текущей строкой, но, в отличие от GROUP BY, не приводят к схлопыванию строк в одну. Каждая строка сохраняет свою индивидуальность.

Синтаксис оконного вызова:
FUNCTION() OVER ( [PARTITION BY partition_col] [ORDER BY sort_col [ASC|DESC]] )

Ключевые функции ранжирования

  • ROW_NUMBER() — возвращает последовательный непрерывный порядковый номер строки внутри партиции, начиная с 1 (1, 2, 3, 4...). При равенстве значений сортировки порядок строк недетерминирован (если нет дополнительных полей сортировки).
  • RANK() — присваивает ранг строке с учетом совпадений. При одинаковых значениях строки получают одинаковый ранг, а следующий номер пропускается (1, 2, 2, 4...). Образуются «дыры» в нумерации.
  • DENSE_RANK() — плотный ранг. При совпадении строки получают одинаковый номер, но следующий ранг не пропускается (1, 2, 2, 3...). «Дыры» отсутствуют.
-- Пример ранжирования сотрудников внутри каждого отдела по зарплате
SELECT 
  employee_id,
  department_id,
  salary,
  ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS row_num,
  RANK()       OVER (PARTITION BY department_id ORDER BY salary DESC) AS rnk,
  DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS dense_rnk
FROM employees;

5. Каталог типичных студенческих ошибок и антипаттернов

Антипаттерн 1: Агрегатная функция внутри секции WHERE
Ошибка: SELECT dept, AVG(salary) FROM emp WHERE AVG(salary) > 50000 GROUP BY dept;
Диагностика СУБД: ERROR: aggregate functions are not allowed in WHERE.
Причина: WHERE фильтрует строки до построения групп. На фазе WHERE агрегат не существует.
Исправление: Перенести условие в секцию HAVING AVG(salary) > 50000.
Антипаттерн 2: Обращение к псевдониму (алиасу) из SELECT в HAVING
Ошибка: SELECT dept, SUM(sales) AS total_sales FROM orders GROUP BY dept HAVING total_sales > 100000;
Диагностика СУБД: ERROR: column "total_sales" does not exist.
Причина: По конвейеру SQL секция HAVING исполняется ДО секции SELECT, в которой задается псевдоним.
Исправление: Продублировать агрегатное выражение: HAVING SUM(sales) > 100000.
Антипаттерн 3: Вызов оконной функции внутри WHERE или HAVING
Ошибка: SELECT * FROM sales WHERE ROW_NUMBER() OVER (ORDER BY amount DESC) <= 5;
Диагностика СУБД: ERROR: window functions are not allowed in WHERE.
Причина: Оконные функции вычисляются на этапе SELECT. Для фильтрации по их результату требуется подзапрос или CTE (Common Table Expression).
Исправление: Обернуть в CTE: WITH ranked AS (SELECT *, ROW_NUMBER() OVER(...) as rn FROM sales) SELECT * FROM ranked WHERE rn <= 5;.
Антипаттерн 4: Необоснованное применение HAVING вместо WHERE
Неоптимальный код: SELECT dept, COUNT(*) FROM emp GROUP BY dept HAVING dept = 'IT';
Инженерный анализ: Запрос логически верен, но крайне неэффективен: СУБД сначала группирует абсолютно все отделы предприятия, тратя оперативную память и процессорное время, и лишь затем отбрасывает лишние группы. Условие по неагрегированному полю обязано быть в WHERE: WHERE dept = 'IT' GROUP BY dept.

6. Эффективные педагогические приемы

  • Метод трассировки «Виртуальный конвейер»: Преподаватель рисует на доске ленту конвейера завода. Входящие кортежи сыплются из бункера FROM, сито WHERE отсеивает бракованные детали, контейнеры GROUP BY фасуют детали по коробкам, контроллер HAVING выбрасывает полупустые коробки, и только затем наклеиваются этикетки SELECT. Этот образ навсегда устраняет путаницу с порядком выполнения.
  • Прием визуализации «Окно vs Группа»: На примере ведомости студентов показать, что GROUP BY превращает группу из 25 студентов в одну строку со средней оценкой, а оконная функция оставляет всех 25 студентов на своих местах, просто дописывая каждому в отдельную колонку средний балл его группы и его личное место в рейтинге.
  • Контрастный сравнительный анализ: Разбор на реальных данных разницы между RANK() и DENSE_RANK() в ситуации олимпиадных соревнований при одинаковом количестве баллов у участников.
