## 3. Полные закрытые эталоны решений по 4 практическим сценариям

### Вариант 1. Каталог интернет-магазина электроники

#### Задание 1.1. SQL-запрос первой страницы каталога:
```sql
SELECT id, category_id, title, price, stock_quantity, rating
FROM Products
WHERE is_active = TRUE
  AND stock_quantity > 0
  AND price BETWEEN 15000.00 AND 120000.00
ORDER BY category_id ASC,
         rating DESC NULLS LAST,
         price ASC,
         id ASC
LIMIT 20;
```

#### Задание 1.2. Обоснование NULLS LAST и детерминизма:
1. **Поведение NULL:** В СУБД PostgreSQL и Oracle по умолчанию значение `NULL` трактуется как наибольшее возможное («позитивная бесконечность»). При сортировке `ORDER BY rating DESC` без явного спецификатора все товары с `rating IS NULL` (товары без отзывов и новинки) окажутся на самых первых позициях каталога, вытеснив товары с рейтингом 5.0. Спецификатор `NULLS LAST` принудительно перемещает товары без рейтинга в конец выборки.
2. **Детерминизм пагинации:** Поля `category_id`, `rating` и `price` могут иметь абсолютно одинаковые значения у десятков товаров. Без уникального tie-breaker порядка строки с одинаковыми параметрами могут возвращаться планировщиком в произвольном порядке при каждом перезапросе, приводя к эффекту мерцания и дублирования товаров на разных страницах. Добавление первичного ключа `id ASC` гарантирует строгую однозначность порядка.

#### Задание 1.3. Оптимизация пагинации и составной индекс (ESR):
1. **DDL составного индекса (ESR: Equality -> Sort -> Range):**
```sql
CREATE INDEX idx_products_catalog_esr 
ON Products (is_active, category_id, rating DESC NULLS LAST, price ASC, id ASC)
WHERE is_active = TRUE AND stock_quantity > 0;
```
*(Или классический составной B-Tree индекс без предикатов: `CREATE INDEX idx_products_esr ON Products (is_active, category_id, rating DESC, price ASC, id ASC);`)*.

2. **Запрос 2-й страницы (Keyset Cursor):**
```sql
SELECT id, category_id, title, price, stock_quantity, rating
FROM Products
WHERE is_active = TRUE
  AND stock_quantity > 0
  AND price BETWEEN 15000.00 AND 120000.00
  AND (category_id, rating, price, id) > (5, 4.8, 45000.00, 10421)
ORDER BY category_id ASC,
         rating DESC NULLS LAST,
         price ASC,
         id ASC
LIMIT 20;
```

### Вариант 2. База авиарейсов международного аэропорта

#### Задание 2.1. SQL-запрос оперативного табло вылета:
```sql
SELECT flight_id, flight_number, departure_time, destination, terminal, gate, status
FROM Flights
WHERE status IN ('ON_TIME', 'DELAYED')
  AND departure_time >= '2026-10-01 08:00:00'
  AND departure_time <= '2026-10-01 20:00:00'
ORDER BY departure_time ASC,
         terminal ASC,
         gate ASC NULLS FIRST,
         flight_id ASC
LIMIT 30;
```

#### Задание 2.2. Анализ поведения NULLS FIRST и трехзначной логики:
1. **Диалекты и NULL:** В PostgreSQL по умолчанию при `ASC` значения `NULL` помещаются в конец (`NULLS LAST`). Если диспетчеру требуется отслеживать рейсы с нераспределенными стоянками (`gate IS NULL`) на самом верху списка для оперативного вмешательства, без `NULLS FIRST` эти рейсы потеряются внизу экрана. В MySQL же `NULL` при `ASC` по умолчанию идет в начале. Явное указание `NULLS FIRST` гарантирует переносимость логики.
2. **Трехзначная логика SQL:** Условие `WHERE gate != 'A1'` отсечет не только рейсы у гейта A1, но и **все рейсы, где гейт еще не назначен (`gate IS NULL`)**, поскольку сравнение `NULL != 'A1'` возвращает `UNKNOWN`, а предикат `WHERE` пропускает только строки со значением `TRUE`. Для корректного учета неопределенности требуется писать: `WHERE (gate != 'A1' OR gate IS NULL)`.

#### Задание 2.3. Частичный индекс и Keyset-пагинация:
1. **Частичный индекс (Partial Index):**
```sql
CREATE INDEX idx_flights_active_board
ON Flights (departure_time ASC, terminal ASC, gate ASC, flight_id ASC)
WHERE status IN ('ON_TIME', 'DELAYED');
```
*Экономит 95% дискового пространства и кэша RAM, полностью исключая архивные рейсы.*
2. **Преимущество Keyset:** При интенсивном добавлении новых рейсов в расписание использование `OFFSET` приводит к сдвигу позиций: рейс, отображавшийся на 30-й строке первой страницы, может оказаться на 1-й строке второй страницы при ее открытии. Keyset опирается на точный кортеж времени и ID, гарантируя отсутствие дублей.

### Вариант 3. Реестр договоров страховой компании

#### Задание 3.1. SQL-запрос реестра убыточности:
```sql
SELECT contract_id, policy_number, region_code, sign_date, total_payout, premium_sum, loss_ratio, branch_id
FROM InsuranceContracts
WHERE sign_date >= '2026-01-01'
  AND sign_date < '2026-04-01'
  AND total_payout > 500000.00
ORDER BY region_code ASC,
         loss_ratio DESC NULLS LAST,
         contract_id ASC
LIMIT 25;
```

#### Задание 3.2. Алгоритмический анализ: Quicksort vs External Merge Sort:
1. **Причина Disk Spill:** Размер выборки, подлежащей сортировке, превысил лимит оперативной памяти, выделенный процессу через параметр `work_mem` (например, 4 МБ). В результате СУБД была вынуждена сбросить отсортированные блоки (runs) во временные файлы на диск (`external merge Disk: 48MB`) и затем производить многопутевое дисковое слияние (Multi-way Merge Pass).
2. **Устранение проблемы:**
   - Локальное увеличение рабочей памяти для сессии формирования отчета: `SET work_mem = '64MB';` (позволит выполнить In-Memory Quicksort);
   - Создание составного B-Tree индекса, который выдает строки в готовом упорядоченном виде, полностью устраняя этап `Sort` из плана выполнения.

#### Задание 3.3. DDL-индекс и Keyset-пагинация:
1. **DDL-скрипт индекса:**
```sql
CREATE INDEX idx_insurance_payout_loss
ON InsuranceContracts (region_code ASC, loss_ratio DESC NULLS LAST, contract_id ASC)
WHERE total_payout > 500000.00;
```
2. **Запрос второй страницы (Keyset):**
```sql
SELECT contract_id, policy_number, region_code, sign_date, total_payout, premium_sum, loss_ratio, branch_id
FROM InsuranceContracts
WHERE sign_date >= '2026-01-01'
  AND sign_date < '2026-04-01'
  AND total_payout > 500000.00
  AND (region_code, loss_ratio, contract_id) < ('RU-KHM', 3.45, 89104)
ORDER BY region_code ASC,
         loss_ratio DESC NULLS LAST,
         contract_id ASC
LIMIT 25;
```

### Вариант 4. Электронный журнал оценок колледжа

#### Задание 4.1. SQL-запрос ведомости задолженностей:
```sql
SELECT record_id, student_id, last_name, first_name, group_code, debts_count, gpa
FROM StudentGrades
WHERE is_expelled = FALSE
  AND group_code = 'СА-201'
  AND debts_count > 0
ORDER BY last_name COLLATE "ru_RU" ASC,
         gpa DESC NULLS LAST,
         record_id ASC
LIMIT 30;
```

#### Задание 4.2. Анализ Collation и буквы «Ё»:
1. **Проблема COLLATE "C":** Бинарное сопоставление "C" (или POSIX) упорядочивает символы строго по их численным шестнадцатеричным кодам в кодировке UTF-8. В кодовой таблице заглавная русская буква «Ё» имеет код `U+0401`, тогда как диапазон основных букв «А»–«Я» начинается с кода `U+0410`. Из-за этого строка «Ёлкин» (код 0401) при бинарной сортировке встает перед строкой «Абрамов» (код 0410).
2. **Решение ru_RU:** Локаль `ru_RU` (на основе правил Unicode Collation Algorithm / ICU) использует многоуровневые веса символов, где буква «ё» имеет первичный вес, эквивалентный букве «е», и позиционируется в строгом алфавитном порядке между «е» и «ж».

#### Задание 4.3. Оптимизация индексами и самопроверка:
1. **DDL-скрипт составного индекса:**
```sql
CREATE INDEX idx_student_grades_group_debt
ON StudentGrades (group_code, last_name COLLATE "ru_RU" ASC, gpa DESC NULLS LAST, record_id ASC)
WHERE is_expelled = FALSE AND debts_count > 0;
```
2. **Самопроверка (Non-SARGable):** Оборачивание колонки в функцию `lower(group_code)` делает предикат не-SARGable. B-Tree индекс построен по исходным неизмененным значениям строки `group_code`, поэтому СУБД не может выполнить спуск по дереву и вынуждена переключиться на полное последовательное чтение всей таблицы (Sequential Scan). Для поддержки такого поиска требуется либо писать точное совпадение с исходным регистром, либо создавать функциональный индекс `CREATE INDEX ... ON StudentGrades (lower(group_code))`.

## 4. Эталон решения резервного домашнего задания (domashnee_zadanie.html)

### Задание 1. Комплексный комбинированный запрос:
```sql
SELECT contract_id, client_id, region_code, vehicle_category, contract_status, 
       contract_sum, monthly_payment, signing_date, credit_rating
FROM LeaseContracts
WHERE contract_status = 'ACTIVE'
  AND vehicle_category IN ('TRUCK', 'SPECIAL')
  AND contract_sum BETWEEN 3000000.00 AND 25000000.00
  AND signing_date >= '2024-01-01' 
  AND signing_date <= '2025-12-31'
ORDER BY region_code COLLATE "C" ASC,
         credit_rating DESC NULLS LAST,
         contract_sum DESC,
         contract_id ASC
LIMIT 25;
```

### Задание 2. Инженерное обоснование NULLS LAST и Collation:
1. В PostgreSQL по умолчанию при `DESC` неопределенные значения `NULL` ставятся первыми (`NULLS FIRST`). Без явного `NULLS LAST` договоры с непроверенными клиентами (где скоринг риска отсутствует и поле равно `NULL`) окажутся в самом верху отчета службы безопасности, имитируя заемщиков с наивысшим скоринговым баллом (10.0), что создает критический финансовый риск ошибочной оценки кредитного портфеля.
2. Коды регионов стандарта ISO (`'RU-MOW'`, `'RU-SPE'`) состоят из символов ASCII и цифр в фиксированном формате. Для них бинарная сортировка `COLLATE "C"` полностью корректна и выполняется на уровне CPU значительно быстрее. Для кириллических строк (ФИО) `COLLATE "C"` недопустим из-за аномалий кодировки UTF-8 (вынос буквы «Ё» в начало списка и изоляция заглавных букв от строчных).

### Задание 3. Оптимизация и переход на Keyset:
1. **DDL-скрипт составного B-Tree индекса (ESR):**
```sql
CREATE INDEX idx_lease_security_report
ON LeaseContracts (contract_status, region_code, credit_rating DESC NULLS LAST, contract_sum DESC, contract_id ASC);
```
2. **Запрос 2-й страницы через Keyset Cursor:**
```sql
SELECT contract_id, client_id, region_code, vehicle_category, contract_status, 
       contract_sum, monthly_payment, signing_date, credit_rating
FROM LeaseContracts
WHERE contract_status = 'ACTIVE'
  AND vehicle_category IN ('TRUCK', 'SPECIAL')
  AND contract_sum BETWEEN 3000000.00 AND 25000000.00
  AND signing_date >= '2024-01-01' 
  AND signing_date <= '2025-12-31'
  AND (region_code, credit_rating, contract_sum, contract_id) < ('RU-MOW', 8.5, 12500000.00, 948120)
ORDER BY region_code COLLATE "C" ASC,
         credit_rating DESC NULLS LAST,
         contract_sum DESC,
         contract_id ASC
LIMIT 25;
```

## 5. Классификатор типичных студенческих ошибок и штрафные баллы

| Код ошибки | Описание выявленного дефекта | Штрафной вычет |
| :---: | :--- | :---: |
| **ERR-01** | **Пропуск NULLS LAST при сортировке по убыванию:** не указано явное позиционирование `NULL`, что приводит к искажению выдачи в PostgreSQL/Oracle. | **-0.5 балла** |
| **ERR-02** | **Отсутствие детерминирующего первичного ключа:** `ORDER BY` не завершен полем `id ASC`, что делает пагинацию недетерминированной. | **-0.5 балла** |
| **ERR-03** | **Разрушение SARGability (Non-SARGable):** применение функций к колонкам в блоке WHERE (например, `YEAR(date) = 2026` вместо диапазона). | **-0.5 балла** |
| **ERR-04** | **Нарушение правила ESR в составном индексе:** постановка диапазонного столбца левее столбцов точного равенства или сортировки. | **-0.5 балла** |
| **ERR-05** | **Игнорирование Collation кириллицы:** отсутствие `COLLATE "ru_RU"` в Варианте 4, приводящее к сбою алфавитного порядка буквы «Ё». | **-0.5 балла** |
| **ERR-06** | **Пропуск блока самопроверки:** отсутствие ответов на контрольные вопросы в рабочем листе или ДЗ. | **-0.5 балла** |
