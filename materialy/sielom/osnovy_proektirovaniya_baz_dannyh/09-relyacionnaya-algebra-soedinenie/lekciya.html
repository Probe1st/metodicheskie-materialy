Конспект лекции: Реляционная алгебра — Соединение

Дисциплина: ОП.08 Основы проектирования баз данных
Раздел: Тема 2. Взаимосвязи в моделях и реляционный подход к построению моделей (§2.2 с.7 программы)

1. Введение: почему соединение — центральная операция РМД

В реляционных базах данных соблюдение принципов нормализации требует декомпозиции предметной области на множество независимых таблиц-сущностей. Клиенты, заказы, товары, платежи и филиалы хранятся раздельно, чтобы исключить избыточность и аномалии данных.

Однако для пользователя базы данных ценность представляют не изолированные идентификаторы, а целостные информационные сводки: «Какой клиент, когда, какой товар приобрел и через какой филиал банка оплатил покупку?».

Операция соединения (JOIN) — это математический инструмент реляционной алгебры, который восстанавливает смысловую взаимосвязь между кортежами раздельных отношений на основе логического предиката связывания.

2. Пошаговая блок-схема: от декартова произведения к соединению

Теоретический фундамент любого соединения — это композиция двух базовых операций: Декартова произведения (Cartesian Product, ×) и Селекции (Selection, σ).

1
Отношения на входе: Заданы два отношения R(A1, ..., An) мощностью |R| и S(B1, ..., Bm) мощностью |S|.
2
Вычисление декартова произведения (R × S): Формируется множество из всех возможных комбинаций кортежей. Мощность результата составляет |R| · |S|, а степень (число атрибутов) — n + m.
3
Проверка логического предиката (θ): К каждой строке применяется условие связи θ (например, R.ID\_клиента = S.Клиент\ID). Строки, дающие FALSE или UNKNOWN, отбрасываются.
4
Проекция (для Natural Join): При естественном соединении одноименные атрибуты сливаются в один столбец, устраняя дублирование ключа.

4. Проблема NULL и трехзначная логика (3VL)

Фундаментальное правило: Значение NULL означает «неизвестно» (UNKNOWN). В связи с этим:
  • NULL = NULL дает результат UNKNOWN, а не TRUE!
  • NULL <> 5 дает результат UNKNOWN!
  • В реляционной фильтрации кортеж попадает в результат только тогда, когда логическое выражение дает строго TRUE.
Именно поэтому два кортежа, содержащие NULL в ключевых атрибутах, при обычном соединении не соединятся. Для проверки отсутствия данных используется специальный предикат IS NULL.

5. Физические алгоритмы реализации соединения в СУБД

Когда СУБД получает декларативный запрос, оптимизатор выбирает один из трех физических алгоритмов:

  • Nested Loop Join: Вложенный цикл. Для каждой строки таблицы R СУБД ищет совпадение в таблице S. Если в S есть B-Tree индекс по ключу соединения, сложность составляет O(|R| log |S|).
  • Hash Join: В оперативной памяти строится хэш-таблица по ключам меньшей таблицы (Build-фаза). Затем большая таблица последовательно сканируется (Probe-фаза). Идеально для больших объемов данных при равенстве ключей.
  • Sort Merge Join: Обе таблицы сортируются по ключу соединения, после чего параллельно сканируются курсорами. Эффективно, если данные уже физически отсортированы на диске (кластерный индекс).

6. Вопросы для самопроверки

Вопрос 1: В чем ключевое отличие эквисоединения от естественного соединения?
Ответ: В схеме эквисоединения сохраняются оба ключевых атрибута из обоих отношений (с дублированием). В естественном соединении одноименные атрибуты сливаются в один столбец.
Вопрос 2: Чему равна мощность естественного соединения двух отношений, если они не имеют общих атрибутов?
Ответ: Мощность равна |R| · |S|, так как естественное соединение при отсутствии общих атрибутов вырождается в декартово произведение.
Вопрос 3: Почему операция соединения по условию равенства не связывает строки, у которых ключ равен NULL?
Ответ: Потому что предикат равенства NULL = NULL в трехзначной логике вычисляется в UNKNOWN, а операторы реляционной селекции отбирают только строки со значением TRUE.
Вопрос 4: Чем полусоединение (Semi-Join) отличается от обычного внутреннего соединения?
Ответ: Полусоединение возвращает только атрибуты левого отношения и никогда не размножает строки левого отношения, даже если в правом отношении найдено несколько совпадающих строк.
