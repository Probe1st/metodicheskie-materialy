1. Учебно-методический паспорт и цели занятия

Занятие 09 посвящено фундаментальной реляционной операции — соединению отношений (JOIN). В реляционной модели данных Эдгара Кодда нормализованные сущности декомпозируются по отдельным отношениям, чтобы избежать аномалий обновления, удаления и вставки. Однако для решения прикладных аналитических и транзакционных задач данные необходимо собирать воедино. Операция соединения связывает кортежи двух и более отношений по определенному логическому предикату.

Цели занятия:

  • Образовательная: Сформировать строгое математическое и инженерное понимание операции соединения как композиции декартова произведения и селекции (σP(R × S)); изучить тета-соединение, эквисоединение, естественное соединение, внешние соединения (LEFT, RIGHT, FULL OUTER JOIN), полусоединение (SEMIJOIN) и антисоединение (ANTIJOIN); раскрыть суть проблемы трехзначной логики и маркера NULL; разобрать физические алгоритмы выполнения соединений в ядрах СУБД (Nested Loop, Hash Join, Sort Merge Join).
  • Развивающая: Развить алгоритмическое мышление обучающихся при анализе структуры запросов, умение сопоставлять схемы отношений, определять кардинальность результирующего множества и оптимизировать вычислительные затраты.
  • Воспитательная: Воспитать профессиональную культуру проектирования баз данных, понимание катастрофических последствий ложных декартовых произведений (картезианского взрыва) и искажения финансовых/учетных отчетов из-за неверной обработки NULL.

3. Теоретический базис и классификация операций соединения

3.1. Тета-соединение (θ-Join) и Эквисоединение (Equi-Join)

В реляционной алгебре общее соединение (тета-соединение) определяется как операция над отношениями R(A1, ..., An) и S(B1, ..., Bm), задаваемая выражением:

R ⋈_θ S = σ_θ (R × S)
где θ — логическое условие вида Ai odot Bj, а оператор сравнения odot ∈ \{=, <, ≤, >, ≥, ≠\}.

Если оператор сравнения — строго равенство (odot есть =), операция называется эквисоединением (Equi-Join). Важно подчеркнуть студентам, что в схеме результирующего отношения эквисоединения сохраняются оба атрибута: и Ai, и Bj, значения которых идентичны.

3.2. Естественное соединение (Natural Join, ⋈)

Естественное соединение R ⋈ S — частный случай эквисоединения по всем атрибутам с одинаковыми именами в схемах R и S, при котором:

  1. Вычисляется декартово произведение кортежей;
  2. Отбираются кортежи, для которых значения всех одноименных атрибутов равны;
  3. Проводится проекция с удалением дублирующихся одноименных столбцов.
Методическое предупреждение: Студенты часто забывают, что если схемы R и S не имеют общих имен атрибутов, естественное соединение R ⋈ S математически вырождается в декартово произведение R × S!

3.3. Внешние соединения (Outer Joins) и феномен маркера NULL

Внутреннее соединение (Inner Join) отбрасывает кортежи одного отношения, для которых не найдено пары в другом отношении. Это приводит к безвозвратной потере информации при формировании сводок. Для сохранения «одиноких» кортежей Кодд ввел внешние соединения:

  • Левое внешнее соединение (Left Outer Join, R ⟕ S): Результирующее отношение включает все кортежи R ⋈ S, а также все неподошедшие кортежи из R, дополненные специальным маркером отсутствующего значения NULL во всех атрибутах отношения S.
  • Правое внешнее соединение (Right Outer Join, R ⟖ S): Включает все кортежи внутреннего соединения и все непарные кортежи из S, дополненные NULL в атрибутах R. Симметрично: R ⟖ S equiv S ⟕ R.
  • Полное внешнее соединение (Full Outer Join, R ⟗ S): Объединяет результаты левого и правого внешних соединений (R ⟕ S ∪ R ⟖ S). Сохраняет все кортежи из обоих отношений, подставляя NULL с соответствующей стороны при отсутствии соответствия.
Проблема NULL в реляционной теории: Маркер NULL — это не число 0, не пустая строка "" и не пробел. Это индикатор отсутствия значения или неопределенности. В реляционной алгебре NULL порождает трехзначную логику Лукасевича (3VL: True, False, Unknown). Предикат сравнения NULL = NULL возвращает UNKNOWN, а не TRUE. Поэтому кортежи со значением NULL в ключевых атрибутах никогда не соединяются между собой в классическом эквисоединении.

3.4. Полусоединение (Semi-Join) и Антисоединение (Anti-Join)

Эти операции критически важны для понимания работы предикатов EXISTS / IN и оптимизации запросов в СУБД:

  • Полусоединение (R ⋉ S): Возвращает только те кортежи из отношения R, для которых существует хотя бы один соответствующий кортеж в S по предикату соединения. При этом схема результата содержит только атрибуты отношения R, а кортежи из R не дублируются, даже если в S найдено несколько совпадений.
  • Антисоединение (R rhd S): Возвращает те кортежи отношения R, для которых нет ни одного соответствия в отношении S. Это фундаментальный реляционный инструмент поиска «потерянных» сущностей: клиентов без заказов, товаров без движения, студентов без оценок.

4. Физические алгоритмы соединений в ядрах СУБД

Преподаватель обязан показать студентам разрыв между декларативной реляционной формулой и физическим исполнением на дисках и в оперативной памяти:

Алгоритм соединения Принцип работы Временная сложность Оптимальные условия применения
Nested Loop Join (Вложенные циклы) Для каждой строки внешнего отношения сканируется внутреннее отношение. При наличии индекса по ключу соединения во внутренней таблице — Index Nested Loop. O(|R| · |S|) в наивном виде; O(|R| · log |S|) с индексом. Одно отношение мало (десятки строк), а на втором есть B-Tree индекс; высокоселективные OLTP-запросы.
Hash Join (Хэш-соединение) Фаза Build: по меньшему отношению в оперативной памяти строится хэш-таблица по ключу соединения. Фаза Probe: сканируется второе отношение, вычисляется хэш ключа и проверяются кортежи. O(|R| + |S|) в идеале при помещении хэш-таблицы в RAM. Большие неиндексированные таблицы, эквисоединения в OLAP и хранилищах данных (DWH). Не работает для неравенств (<, >).
Sort Merge Join (Слияние сортировкой) Оба отношения предварительно сортируются по ключам соединения, затем два курсора одновременно движутся по потокам, выполняя слияние за один проход. O(|R| log |R| + |S| log |S|); если уже отсортированы — O(|R| + |S|). Данные уже отсортированы (например, читаются по кластерному индексу), либо условие соединения содержит операторы неравенства (≤, ≥).

5. Типовые ошибки студентов и педагогические приемы

  • Ошибка 1: Картезианский взрыв (забытое условие соединения).
    Проявление: Студент выполняет соединение отношений из 100 и 1 000 строк и вместо ожидаемых 100 строк получает 100 000. В реальных базах это приводит к исчерпанию tempdb и зависанию сервера.
    Педагогический прием: Потребовать обязательного расчета кардинальности перед написанием запроса: «Каков теоретический минимум и максимум строк в результате?».
  • Ошибка 2: Потеря непарных сущностей в INNER JOIN.
    Проявление: При расчете балансов или списков должников студент использует естественное/внутреннее соединение, из-за чего из отчета полностью выпадают клиенты с нулевым числом операций.
    Педагогический прием: Визуализация на диаграммах Венна и демонстрация реального кейса: «Бухгалтерия потеряла 40 филиалов, потому что в этом месяце они не совершали платежей».
  • Ошибка 3: Сравнение NULL через знак равенства.
    Проявление: Попытка фильтровать отсутствующие кортежи условием WHERE department_id = NULL.
    Педагогический прием: Эксперимент с трехзначной логикой. Преподаватель показывает, что результат выражения NULL = NULL равен UNKNOWN, и СУБД отфильтровывает такие строки. Корректная конструкция — IS NULL.
  • Ошибка 4: Дублирование атрибутов в результате Natural Join.
    Проявление: Включение ключевого поля дважды в результирующую схему таблицы.
    Педагогический прием: Сравнение определения Natural Join и Equi-Join на доске.

6. Рекомендации по работе с интерактивным рабочим листом

На практическом этапе обучающиеся открывают файл zanyatie.html в браузере. Лист содержит 4 индивидуальных варианта, покрывающих все типы соединений:

  1. Вариант 1 (Клиенты и Счета): Вычисление естественного соединения и Left Outer Join для нахождения клиентов без открытых счетов.
  2. Вариант 2 (Преподаватели и Кафедры): Построение эквисоединения с сохранением дублирующихся ключей и Right Outer Join для выявления кафедр без штатных сотрудников.
  3. Вариант 3 (Студенты и Сданные экзамены): Построение Full Outer Join для выявления как несдававших студентов, так и экзаменов, на которые никто не пришел, с точной фиксацией NULL.
  4. Вариант 4 (Склад и Поставки): Применение операции антисоединения (R rhd S) для фильтрации неликвидных товарных позиций.

Оценивание решений осуществляется строго по закрытой 4-балльной рубрике (.rubrika.md). Рабочий лист сохраняет введенные данные в localStorage и адаптирован для печати на формате А4.
