## 3. Полные эталонные решения для 4 вариантов (zanyatie.html)

### Вариант 1: Биллинговая система ЖКХ

#### Задание 1.1. DDL схемы, последовательности и таблицы квитанций
```sql
-- 1. Создание схемы биллинга
CREATE SCHEMA IF NOT EXISTS billing;

-- 2. Создание последовательности для номеров квитанций
CREATE SEQUENCE billing.receipt_num_seq
    START WITH 100000
    INCREMENT BY 1
    MINVALUE 100000
    MAXVALUE 999999999
    CACHE 20;

-- 3. Создание таблицы абонентов
CREATE TABLE billing.subscribers (
    subscriber_id SERIAL PRIMARY KEY,
    district_id INT NOT NULL,
    account_number VARCHAR(20) NOT NULL UNIQUE,
    full_name VARCHAR(150) NOT NULL,
    address TEXT NOT NULL
);

-- 4. Создание таблицы квитанций с автоматической привязкой SEQUENCE
CREATE TABLE billing.receipts (
    receipt_id BIGINT PRIMARY KEY DEFAULT nextval('billing.receipt_num_seq'),
    subscriber_id INT NOT NULL REFERENCES billing.subscribers(subscriber_id),
    billing_period DATE NOT NULL,
    accrued_amount NUMERIC(10, 2) NOT NULL CHECK (accrued_amount >= 0),
    paid_amount NUMERIC(10, 2) NOT NULL DEFAULT 0.00 CHECK (paid_amount >= 0),
    issue_date TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

#### Задание 1.2. DDL материализованного представления с уникальным индексом и обновлением
```sql
-- Создание материализованной витрины задолженностей
CREATE MATERIALIZED VIEW billing.mv_district_debt_summary AS
SELECT 
    s.district_id,
    date_trunc('month', r.billing_period)::date AS report_month,
    count(DISTINCT s.subscriber_id) AS total_subscribers,
    sum(r.accrued_amount) AS total_accrued,
    sum(r.paid_amount) AS total_paid,
    sum(r.accrued_amount - r.paid_amount) AS total_debt
FROM billing.subscribers s
JOIN billing.receipts r ON s.subscriber_id = r.subscriber_id
GROUP BY s.district_id, date_trunc('month', r.billing_period)::date;

-- Обязательный уникальный индекс для неблокирующего обновления
CREATE UNIQUE INDEX idx_mv_district_debt_pk 
ON billing.mv_district_debt_summary (district_id, report_month);

-- Регламентная команда фонового обновления
REFRESH MATERIALIZED VIEW CONCURRENTLY billing.mv_district_debt_summary;
```

#### Задание 1.3. Архитектурный анализ
1. **Выбор MATERIALIZED VIEW:** сводный отчет запрашивается массово сотрудниками аналитического отдела. При обычном VIEW СУБД выполняла бы тяжелое соединение JOIN и агрегацию миллионов строк при каждом клике, перегружая CPU. В MATERIALIZED VIEW результат предварительно посчитан на диске, а индекс обеспечивает мгновенный отклик $O(\log N)$.
2. **Пропуски в SEQUENCE:** пропуски в последовательности абсолютно допустимы и неизбежны. Генератор работает в Shared Memory вне контекста пользовательских транзакций ради исключения взаимных блокировок. Если транзакция вставки завершилась сбоем (`ROLLBACK`), инкрементированное число не возвращается. Для строгой фискальной нумерации без пропусков используются отдельные пессимистические механизмы блокировок.

### Вариант 2: Медицинская радиологическая система PACS

#### Задание 2.1. DDL схемы, типа ENUM и таблицы исследований
```sql
CREATE SCHEMA IF NOT EXISTS imaging;

-- Перечислимый тип модальностей лучевой диагностики
CREATE TYPE imaging.modality_type AS ENUM (
    'CT', 'MRI', 'XRAY', 'ULTRASOUND', 'MAMMOGRAPHY'
);

CREATE TABLE imaging.patients (
    patient_id SERIAL PRIMARY KEY,
    full_name VARCHAR(150) NOT NULL,
    birth_date DATE NOT NULL,
    passport_data VARCHAR(50) NOT NULL,
    gender CHAR(1) CHECK (gender IN ('M', 'F'))
);

CREATE TABLE imaging.dicom_studies (
    study_id BIGSERIAL PRIMARY KEY,
    study_uid VARCHAR(64) NOT NULL UNIQUE,
    patient_id INT NOT NULL REFERENCES imaging.patients(patient_id),
    modality imaging.modality_type NOT NULL,
    study_date TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    body_part VARCHAR(64) NOT NULL,
    doctor_conclusion TEXT
);
```

#### Задание 2.2. Защищенное динамическое VIEW со скрытием ПДн
```sql
CREATE OR REPLACE VIEW imaging.v_anonymized_studies AS
SELECT 
    s.study_id,
    s.study_uid,
    md5(p.patient_id::text || 'salt_secret_key') AS pseudo_patient_hash,
    p.gender,
    extract(year from age(s.study_date, p.birth_date))::int AS patient_age_at_study,
    s.modality,
    s.body_part,
    s.study_date,
    s.doctor_conclusion
FROM imaging.patients p
JOIN imaging.dicom_studies s ON p.patient_id = s.patient_id;
```

#### Задание 2.3. Безопасность и DCL
1. **Почему динамическое VIEW:** при маскировании ПДн критически важно, чтобы внешние исследователи видели только деперсонализированные данные в реальном времени. В динамическом VIEW не создается физических дубликатов конфиденциальной информации на диске, исключая риск утечки устаревших снапшотов.
2. **DCL-скрипт:**
```sql
CREATE ROLE ai_researcher WITH LOGIN PASSWORD 'strong_pass_123';
GRANT USAGE ON SCHEMA imaging TO ai_researcher;
REVOKE ALL ON imaging.patients FROM ai_researcher;
REVOKE ALL ON imaging.dicom_studies FROM ai_researcher;
GRANT SELECT ON imaging.v_anonymized_studies TO ai_researcher;
```

### Вариант 3: Служба экспресс-доставки посылок

#### Задание 3.1. Генератор трек-номеров через SEQUENCE
```sql
CREATE SCHEMA IF NOT EXISTS logistics;

CREATE SEQUENCE logistics.tracking_seq
    START WITH 10000000
    INCREMENT BY 1
    MINVALUE 10000000
    MAXVALUE 99999999
    CACHE 50;

CREATE TABLE logistics.parcels (
    parcel_id BIGSERIAL PRIMARY KEY,
    tracking_number VARCHAR(24) NOT NULL UNIQUE DEFAULT ('RU' || nextval('logistics.tracking_seq')::text || 'CN'),
    sender_id INT NOT NULL,
    receiver_address TEXT NOT NULL,
    weight_kg NUMERIC(6, 3) NOT NULL CHECK (weight_kg > 0),
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

#### Задание 3.2. Партиционированная таблица и материализованная витрина
```sql
-- Таблица трекинга с партиционированием по диапазону дат
CREATE TABLE logistics.tracking_events (
    event_id BIGSERIAL,
    parcel_id BIGINT NOT NULL,
    warehouse_id INT NOT NULL,
    event_type VARCHAR(32) NOT NULL, -- 'RECEIVED', 'DISPATCHED'
    event_time TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (event_id, event_time)
) PARTITION BY RANGE (event_time);

-- Создание партиции
CREATE TABLE logistics.tracking_events_2026_10 PARTITION OF logistics.tracking_events
    FOR VALUES FROM ('2026-10-01') TO ('2026-11-01');

-- Материализованная витрина загрузки складов
CREATE MATERIALIZED VIEW logistics.mv_warehouse_daily_load AS
SELECT 
    warehouse_id,
    event_time::date AS op_date,
    count(*) FILTER (WHERE event_type = 'RECEIVED') AS parcels_in,
    count(*) FILTER (WHERE event_type = 'DISPATCHED') AS parcels_out
FROM logistics.tracking_events
GROUP BY warehouse_id, event_time::date;

CREATE UNIQUE INDEX idx_mv_wh_daily_pk 
ON logistics.mv_warehouse_daily_load (warehouse_id, op_date);

REFRESH MATERIALIZED VIEW CONCURRENTLY logistics.mv_warehouse_daily_load;
```

#### Задание 3.3. Анализ производительности
1. **Партиционирование:** таблица событий растет на десятки миллионов записей в месяц. Партиционирование позволяет отсекать ненужные блоки (Partition Pruning) при запросах за конкретные даты и мгновенно очищать устаревшие архивы через <code>DROP TABLE ... PARTITION</code> вместо тяжелого <code>DELETE</code>.
2. **SEQUENCE:** генерация на стороне СУБД через последовательность атомарна, не зависит от количества серверов приложений (бэкендов) и исключает риск генерации коллизий трек-номеров.

### Вариант 4: Электронный деканат университета

#### Задание 4.1. Многосхемная архитектура
```sql
CREATE SCHEMA IF NOT EXISTS personal;
CREATE SCHEMA IF NOT EXISTS academic;

CREATE TABLE personal.students (
    student_id SERIAL PRIMARY KEY,
    full_name VARCHAR(150) NOT NULL,
    passport_series_num VARCHAR(20) NOT NULL UNIQUE,
    snils CHAR(14) NOT NULL UNIQUE,
    phone VARCHAR(20)
);

CREATE TABLE academic.student_registry (
    registry_id SERIAL PRIMARY KEY,
    student_id INT NOT NULL REFERENCES personal.students(student_id),
    record_book_num VARCHAR(20) NOT NULL UNIQUE,
    specialty_code VARCHAR(20) NOT NULL,
    study_status VARCHAR(20) DEFAULT 'ACTIVE'
);
```

#### Задание 4.2. Защищенное представление ведомости
```sql
CREATE TABLE academic.exam_grades (
    grade_id SERIAL PRIMARY KEY,
    registry_id INT NOT NULL REFERENCES academic.student_registry(registry_id),
    subject_name VARCHAR(100) NOT NULL,
    exam_date DATE NOT NULL,
    grade INT CHECK (grade BETWEEN 2 AND 5)
);

CREATE OR REPLACE VIEW academic.v_exam_grade_sheet AS
SELECT 
    r.record_book_num,
    r.specialty_code,
    g.subject_name,
    g.exam_date,
    g.grade
FROM academic.exam_grades g
JOIN academic.student_registry r ON g.registry_id = r.registry_id;
```

#### Задание 4.3. DCL и обоснование
```sql
CREATE ROLE teacher_role WITH LOGIN PASSWORD 'teacher_secure_pass';
GRANT USAGE ON SCHEMA academic TO teacher_role;
REVOKE ALL ON SCHEMA personal FROM teacher_role;
GRANT SELECT ON academic.v_exam_grade_sheet TO teacher_role;
```
Витрина MATERIALIZED VIEW потребуется деканату для построения семестровых отчетов успеваемости по институту (средний балл по кафедрам, процент отличников и должников), когда расчет по тысячам студентов выполняется один раз в сессию и не требует посекундной актуализации.

## 4. Эталон резервного домашнего задания (domashnee_zadanie.html)

```sql
-- 1. Схема, SEQUENCE и ENUM
CREATE SCHEMA IF NOT EXISTS rnd_archive;

CREATE SEQUENCE rnd_archive.report_reg_seq
    START WITH 100000
    INCREMENT BY 1
    MINVALUE 100000
    MAXVALUE 999999999
    CACHE 10;

CREATE TYPE rnd_archive.security_level_enum AS ENUM (
    'PUBLIC', 'RESTRICTED', 'CONFIDENTIAL', 'TOP_SECRET'
);

-- 2. Таблица и VIEW
CREATE TABLE rnd_archive.scientific_reports (
    report_id BIGINT PRIMARY KEY DEFAULT nextval('rnd_archive.report_reg_seq'),
    topic_code VARCHAR(32) NOT NULL,
    security_level rnd_archive.security_level_enum NOT NULL DEFAULT 'PUBLIC',
    author_name VARCHAR(150) NOT NULL,
    page_count INT NOT NULL CHECK (page_count > 0),
    reg_date DATE NOT NULL DEFAULT CURRENT_DATE
);

CREATE OR REPLACE VIEW rnd_archive.v_public_catalog AS
SELECT 
    report_id,
    topic_code,
    page_count,
    reg_date
FROM rnd_archive.scientific_reports
WHERE security_level = 'PUBLIC';

-- 3. MATERIALIZED VIEW
CREATE MATERIALIZED VIEW rnd_archive.mv_department_statistics AS
SELECT 
    topic_code,
    count(*) AS total_reports,
    sum(page_count) AS total_pages
FROM rnd_archive.scientific_reports
GROUP BY topic_code;

CREATE UNIQUE INDEX idx_mv_dept_stat_pk 
ON rnd_archive.mv_department_statistics (topic_code);

REFRESH MATERIALIZED VIEW CONCURRENTLY rnd_archive.mv_department_statistics;
```

## 5. Классификатор ошибок и штрафные баллы

| Тип ошибки | Описание дефекта | Штраф |
| :--- | :--- | :---: |
| **Смешение VIEW и MATERIALIZED VIEW** | Использование обычного VIEW вместо материализованной витрины в задачах агрегации и отчетов. | **-1.0 б.** |
| **Отсутствие UNIQUE INDEX при REFRESH CONCURRENTLY** | Попытка выполнить неблокирующее обновление без уникального индекса по витрине. | **-0.5 б.** |
| **Игнорирование изоляции схем (Namespaces)** | Сваливание всех объектов в схему `public` без создания схемы предметной области. | **-0.5 б.** |
| **Ошибочная логика SEQUENCE** | Утверждение, что при откате транзакции номер возвращается, или использование MAX()+1. | **-0.5 б.** |
| **Отсутствие DCL защиты персональных данных** | Предоставление прямого доступа к таблицам с конфиденциальными полями вместо защищенного VIEW. | **-0.5 б.** |
