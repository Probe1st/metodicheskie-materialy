Задание 2. Анализ правила левого префикса для составного индекса (Composite Index)

Для таблицы Товары (id, категория_id, бренд_id, цена, рейтинг, остаток) спроектирован составной B-Tree индекс: 

CREATE INDEX idx_goods_filter ON Товары (категория_id, бренд_id, цена);

Проанализируйте 4 запроса и определите для каждого из них: сможет ли СУБД использовать данный индекс для быстрого поиска по дереву B-Tree? Обоснуйте ответ правилом левого префикса (Left-Prefix Rule).

  1. SELECT * FROM Товары WHERE категория_id = 5 AND бренд_id = 12 AND цена < 5000;
  2. SELECT * FROM Товары WHERE категория_id = 5 AND цена < 5000;
  3. SELECT * FROM Товары WHERE бренд_id = 12 AND цена < 5000;
  4. SELECT * FROM Товары WHERE категория_id = 5 AND бренд_id = 12;

Задание 3. Анализ плана выполнения запроса EXPLAIN и синтез индекса

В высоконагруженной системе логистики выполняется критический запрос поиска активных доставок: 

SELECT * FROM deliveries 
WHERE courier_id = 42 AND delivery_date = '2026-10-01' AND status = 'IN_TRANSIT';

Команда EXPLAIN ANALYZE вернула следующий план выполнения: 

Seq Scan on deliveries (cost=0.00..89240.00 rows=3 width=110) (actual time=12.420..184.210 rows=3 loops=1)
  Filter: ((courier_id = 42) AND (delivery_date = '2026-10-01'::date) AND (status = 'IN_TRANSIT'::text))
  Rows Removed by Filter: 4999997
Total runtime: 184.320 ms

Задание:

  1. Проанализируйте метрики плана (тип узла, cost, Rows Removed by Filter, время). В чем заключается критический дефект?
  2. Напишите SQL-команду создания оптимального индекса для этого запроса.
  3. Опишите, как изменится план выполнения запроса после добавления индекса (тип сканирования, стоимость, время отклика).
