Домашнее задание - Практическое занятие №11: форма и внешний вид

1. Постановка проектной задачи

Вы работаете ведущим инженером баз данных в региональном логистическом центре «Югра-Транс». Руководство компании поставило задачу разработать регламентированное аналитическое представление (VIEW) и параметризованный SQL-запрос для экранной формы диспетчера грузоперевозок «Ежедневный сводный реестр рейсов и оплат».

В исходной реляционной таблице fleet_shipments данные хранятся в сыром нормализованном виде:

Поле Тип данных Описание
shipment_id BIGSERIAL PRIMARY KEY Уникальный номер рейса
driver_fio VARCHAR(150) Полное ФИО водителя ('Смирнов Алексей Викторович')
departure_time TIMESTAMPTZ Точное время отправления рейса
delivery_status CHAR(1) Статус рейса: 'W' (в ожидании), 'T' (в пути), 'D' (доставлен), 'C' (отменен)
cargo_weight_kg NUMERIC(10, 2) Вес груза в килограммах
contract_price NUMERIC(14, 2) Сумма по договору фрахтования (руб.)
advance_paid NUMERIC(14, 2) Фактически внесенный аванс (руб.)

2. Технические требования к SQL-отчету

Вам необходимо составить один оптимизированный SQL-запрос, формирующий экранный реестр со следующими правилами презентации:

  1. Форматирование идентификатора рейса: сформировать визуальный трек-номер вида #SH-00000042 с лидирующими нулями до 8 разрядов через '#SH-' | LPAD(shipment_id::text, 8, '0').
  2. Преобразование времени отправления: представить метку departure_time строго по ГОСТ в виде ДД.ММ.ГГГГ ЧЧ:МИ с помощью функции TO_CHAR(departure_time, 'DD.MM.YYYY HH24:MI').
  3. Форматирование финансовых сумм: столбец contract_price и вычисляемый остаток долга (contract_price - advance_paid) представить с разделением групп разрядов и суффиксом рубля ('FM999G999G999D00' | ' руб.'). Обязательно устранить паразитный лидирующий пробел модификатором FM!
  4. Логическая стилизация статусов (CASE):
    • Создать читаемый текстовый статус: 'D' → 'Доставлен', 'T' → 'В пути', 'W' → 'Ожидает погрузки', 'C' → 'Отменен', иначе 'Неизвестно'.
    • Создать цветовой индикатор (CSS-бейдж): если рейс отменен или долг превышает 150 000 руб. → 'badge-danger' (красный); если рейс в пути → 'badge-warning' (желтый); если доставлен и долг равен 0 → 'badge-success' (зеленый); иначе 'badge-secondary'.
  5. Организация пагинации и сортировки: вывести первую страницу отчета на 20 рейсов (LIMIT 20 OFFSET 0), упорядочив строки строго по исходному числовому полю departure_time DESC (ни в коем случае не сортировать по текстовой строке с датой!).

3. Шаблон структуры сдаваемого SQL-запроса

-- Диспетчерский отчет «Югра-Транс»: Форма и внешний вид реестра рейсов
SELECT 
 '#SH-' | LPAD(shipment_id::text, 8, '0') AS formatted_shipment_no,
 driver_fio,
 TO_CHAR(departure_time, 'DD.MM.YYYY HH24:MI') AS ru_departure_date,
 
 -- Форматирование договорной суммы и остатка
 TRIM(TO_CHAR(contract_price, 'FM999G999G999D00')) | ' руб.' AS formatted_price,
 TRIM(TO_CHAR(contract_price - COALESCE(advance_paid, 0), 'FM999G999G999D00')) | ' руб.' AS formatted_balance,
 
 -- Читаемый статус рейса
 CASE delivery_status
 WHEN 'D' THEN 'Доставлен'
 WHEN 'T' THEN 'В пути'
 WHEN 'W' THEN 'Ожидает погрузки'
 WHEN 'C' THEN 'Отменен'
 ELSE 'Неизвестно'
 END AS status_title,
 
 -- Цветовой CSS-бейдж для интерфейса DataGrid
 CASE 
 WHEN delivery_status = 'C' OR (contract_price - COALESCE(advance_paid, 0)) > 150000.00 THEN 'badge-danger'
 WHEN delivery_status = 'T' THEN 'badge-warning'
 WHEN delivery_status = 'D' AND (contract_price - COALESCE(advance_paid, 0)) <= 0.00 THEN 'badge-success'
 ELSE 'badge-secondary'
 END AS ui_badge_class

FROM fleet_shipments
ORDER BY departure_time DESC
LIMIT 20 OFFSET 0;
Критерии оценивания (максимум 4 балла):
  • 2 балла: безошибочные шаблоны TO_CHAR, наличие FM, корректное форматирование даты и трек-номера;
  • 1 балл: правильная условная логика CASE с веткой ELSE и корректное порционирование LIMIT/OFFSET;
  • 1 балл: сортировка по исходному типизированному полю и защита от значений NULL через COALESCE.
