Оформление журнала учета пациентов стационара с точным форматированием даты/времени по ГОСТ, расчетом койко-дней и подсветкой тяжелых состояний.

Схема таблицы hospital_stays

КолонкаТипОписание
stay_idBIGINT PRIMARY KEYНомер карты госпитализации
patient_nameVARCHAR(120)ФИО пациента
admission_timestampTIMESTAMPTZВремя поступления
discharge_dateDATEДата выписки (или NULL если лечится)
severity_levelINTСтепень тяжести: 1 (легкая), 2 (средняя), 3 (тяжелая)
Задание 2.1: Проектирование SQL-запроса журнала (TO_CHAR + CASE) 2 балла
Требования:
  • Время поступления admission_timestamp отформатировать по стандарту DD.MM.YYYY HH24:MI.
  • Рассчитать длительность лечения в сутках: COALESCE(discharge_date, CURRENT_DATE) - admission_timestamp::date.
  • Реализовать статус тяжести: CASE WHEN severity_level = 3 THEN 'Тяжелое (ОИТР)' WHEN severity_level = 2 THEN 'Средней тяжести' ELSE 'Удовлетворительное' END.

Формирование стипендиальной ведомости деканата: расчет вычисляемого поля 'Стипендия' по среднему баллу через CASE, сортировка по успеваемости, форматирование ФИО в виде Фамилия И.О.

Схема таблицы student_grades

КолонкаТипОписание
student_idBIGINT PRIMARY KEYНомер зачетной книжки
last_nameVARCHAR(50)Фамилия
first_nameVARCHAR(50)Имя
patronymicVARCHAR(50)Отчество
avg_scoreNUMERIC(3, 2)Средний академический балл (от 2.00 до 5.00)
Задание 4.1: Проектирование SQL-запроса ведомости (TO_CHAR + CASE) 2 балла
Требования:
  • Сконкатенировать краткое ФИО: last_name | ' ' | LEFT(first_name, 1) | '.' | LEFT(patronymic, 1) | '.'.
  • Рассчитать стипендию через поисковый CASE: балл >= 4.75 → 'Повышенная (10 000 руб.)', балл >= 4.00 → 'Академическая (4 500 руб.)', иначе 'Не начисляется'.
  • Отформатировать средний балл с точностью до сотых через TO_CHAR(avg_score, 'FM9D00').
