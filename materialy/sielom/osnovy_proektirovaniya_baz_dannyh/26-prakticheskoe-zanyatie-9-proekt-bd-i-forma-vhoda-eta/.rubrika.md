## 2. Критериальная шкала оценивания (0–4 балла)

| Балл | Критерий | Показатели выполнения и дескрипторы требований к решению |
| :---: | :--- | :--- |
| **2** | **Логика верификации пароля (отлично)** | Безупречно спроектирована структура таблицы пользователей с атрибутами соленого хэширования (`password_hash`, `salt`). Разработана транзакционная хранимая процедура/функция верификации: точечный поиск по логину, вычисление `SHA256(password \|\| salt)`, константное сравнение хэшей. Предусмотрена защита от перечисления пользователей (User Enumeration) через нейтральный ответ «Неверный логин или пароль». |
| **1** | **Логика верификации пароля (хорошо / частично)** | Процедура верификации составлена верно в целом, однако допущены неточности (например, соль не генерируется индивидуально, либо допущена ошибка в передаче параметров), при этом ключевой принцип соленого хэширования соблюден. |
| **0** | **Логика верификации пароля (неудовлетворительно)** | Пароли сравниваются открытым текстом (`WHERE password = p_pass`); соль отсутствует; процедура содержит грубые ошибки, делающие проверку неработоспособной. |
| **1** | **Журнал аудита и защита от перебора (зачтено)** | Корректно спроектирована таблица `security_audit_log` (`event_type`, `user_id`, `attempted_login`, `ip_address`, `timestamp`, `status`). Реализован инкремент счетчика `failed_attempts` при ошибках ввода, выставление временной блокировки `locked_until = NOW() + INTERVAL '15 minute'` при 3 неверных попытках, а также сброс счетчика строго после успешной аутентификации. |
| **0** | **Журнал аудита и защита от перебора (не зачтено)** | Счетчик `failed_attempts` сбрасывается до проверки пароля; блокировка по времени отсутствует; события неудачного входа не фиксируются в логе; либо в лог записывается сырой пароль пользователя. |
| **1** | **Ролевое разграничение и самопроверка (зачтено)** | Разработана логика динамического скрытия/блокировки управляющих элементов интерфейса в зависимости от роли (`role_name`). Представлены научно аргументированные, развернутые и точные ответы на все контрольные вопросы самопроверки. |
| **0** | **Ролевое разграничение и самопроверка (не зачтено)** | Ролевое управление интерфейсом не описано; блок самопроверки пропущен либо содержит грубые фактические ошибки (например: «скрыть кнопку на клиенте — это полная безопасность»). |

## 3. Полные закрытые эталоны решений по 4 практическим кейсам

### Вариант 1. Складской учет

#### 1. DDL схемы учетных записей и аудита
```sql
CREATE TABLE warehouse_users (
    user_id SERIAL PRIMARY KEY,
    login VARCHAR(50) NOT NULL UNIQUE,
    password_hash CHAR(64) NOT NULL,
    salt CHAR(32) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'STOREKEEPER',
    failed_attempts INT NOT NULL DEFAULT 0,
    locked_until TIMESTAMP NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE security_log (
    log_id BIGSERIAL PRIMARY KEY,
    event_type VARCHAR(30) NOT NULL,
    user_id INT NULL REFERENCES warehouse_users(user_id),
    attempted_login VARCHAR(50) NOT NULL,
    ip_address VARCHAR(45) NOT NULL,
    timestamp TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(20) NOT NULL,
    details TEXT NULL
);
CREATE INDEX idx_sec_log_login ON security_log(attempted_login, timestamp DESC);
```

#### 2. SQL-процедура верификации кладовщика
```sql
CREATE OR REPLACE FUNCTION verify_storekeeper_login(
    p_login VARCHAR(50),
    p_password VARCHAR(100),
    p_ip VARCHAR(45)
) RETURNS VARCHAR(50) AS $$
DECLARE
    v_user RECORD;
    v_calc_hash CHAR(64);
BEGIN
    -- 1. Поиск учетной записи
    SELECT * INTO v_user FROM warehouse_users WHERE login = p_login;
    IF NOT FOUND THEN
        INSERT INTO security_log (event_type, attempted_login, ip_address, status, details)
        VALUES ('AUTH_FAILURE', p_login, p_ip, 'FAILED', 'Пользователь не найден');
        RETURN 'ERR_INVALID_CREDENTIALS';
    END IF;

    -- 2. Проверка блокировки
    IF v_user.locked_until IS NOT NULL AND v_user.locked_until > CURRENT_TIMESTAMP THEN
        INSERT INTO security_log (event_type, user_id, attempted_login, ip_address, status, details)
        VALUES ('ACCOUNT_LOCKED', v_user.user_id, p_login, p_ip, 'BLOCKED', 'Попытка входа во время активной блокировки');
        RETURN 'ERR_ACCOUNT_LOCKED';
    END IF;

    -- 3. Проверка активности
    IF NOT v_user.is_active THEN
        INSERT INTO security_log (event_type, user_id, attempted_login, ip_address, status, details)
        VALUES ('AUTH_FAILURE', v_user.user_id, p_login, p_ip, 'FAILED', 'Учетная запись деактивирована');
        RETURN 'ERR_ACCOUNT_DISABLED';
    END IF;

    -- 4. Вычисление и проверка хэша
    v_calc_hash := encode(digest(p_password || v_user.salt, 'sha256'), 'hex');

    IF v_calc_hash = v_user.password_hash THEN
        -- Успешный вход: сброс неудач
        UPDATE warehouse_users 
        SET failed_attempts = 0, locked_until = NULL 
        WHERE user_id = v_user.user_id;

        INSERT INTO security_log (event_type, user_id, attempted_login, ip_address, status, details)
        VALUES ('AUTH_SUCCESS', v_user.user_id, p_login, p_ip, 'SUCCESS', 'Успешная аутентификация кладовщика');
        RETURN 'AUTH_OK';
    ELSE
        -- Ошибка ввода: инкремент счетчика
        IF v_user.failed_attempts + 1 >= 3 THEN
            UPDATE warehouse_users 
            SET failed_attempts = v_user.failed_attempts + 1,
                locked_until = CURRENT_TIMESTAMP + INTERVAL '15 minute'
            WHERE user_id = v_user.user_id;

            INSERT INTO security_log (event_type, user_id, attempted_login, ip_address, status, details)
            VALUES ('ACCOUNT_LOCKED', v_user.user_id, p_login, p_ip, 'BLOCKED', 'Превышен лимит 3 ошибок. Блокировка на 15 мин');
            RETURN 'ERR_ACCOUNT_LOCKED';
        ELSE
            UPDATE warehouse_users 
            SET failed_attempts = v_user.failed_attempts + 1
            WHERE user_id = v_user.user_id;

            INSERT INTO security_log (event_type, user_id, attempted_login, ip_address, status, details)
            VALUES ('AUTH_FAILURE', v_user.user_id, p_login, p_ip, 'FAILED', 'Неверный хэш пароля');
            RETURN 'ERR_INVALID_CREDENTIALS';
        END IF;
    END IF;
END;
$$ LANGUAGE plpgsql;
```

### Вариант 2. Медицинская карта

#### 1. DDL учетных записей врачей и журнала доступа к ПДн
```sql
CREATE TABLE doctors (
    doctor_id SERIAL PRIMARY KEY,
    login VARCHAR(50) NOT NULL UNIQUE,
    password_hash CHAR(64) NOT NULL,
    salt CHAR(32) NOT NULL,
    specialty VARCHAR(100) NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE medical_access_log (
    access_id BIGSERIAL PRIMARY KEY,
    event_type VARCHAR(30) NOT NULL,
    doctor_id INT NULL REFERENCES doctors(doctor_id),
    ip_address VARCHAR(45) NOT NULL,
    timestamp TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(20) NOT NULL,
    details TEXT NULL
);
```

#### 2. Процедура валидации с проверкой активности и логированием
```sql
CREATE OR REPLACE FUNCTION verify_doctor_access(
    p_login VARCHAR(50),
    p_password VARCHAR(100),
    p_workstation_ip VARCHAR(45)
) RETURNS VARCHAR(50) AS $$
DECLARE
    v_doc RECORD;
    v_hash CHAR(64);
BEGIN
    SELECT * INTO v_doc FROM doctors WHERE login = p_login;
    IF NOT FOUND THEN
        INSERT INTO medical_access_log (event_type, ip_address, status, details)
        VALUES ('ACCESS_DENIED', p_workstation_ip, 'FAILED', 'Несуществующий логин врача');
        RETURN 'INVALID_CREDENTIALS';
    END IF;

    -- Строгая проверка статуса активности (ФЗ-152)
    IF v_doc.is_active = FALSE THEN
        INSERT INTO medical_access_log (event_type, doctor_id, ip_address, status, details)
        VALUES ('DEACTIVATED_ACCESS_ATTEMPT', v_doc.doctor_id, p_workstation_ip, 'BLOCKED', 'Попытка доступа уволенного/отстраненного врача');
        RETURN 'ACCOUNT_DEACTIVATED';
    END IF;

    v_hash := encode(digest(p_password || v_doc.salt, 'sha256'), 'hex');
    IF v_hash = v_doc.password_hash THEN
        INSERT INTO medical_access_log (event_type, doctor_id, ip_address, status, details)
        VALUES ('DOCTOR_SESSION_START', v_doc.doctor_id, p_workstation_ip, 'SUCCESS', 'Вход в медицинскую карту разрешен');
        RETURN 'ACCESS_GRANTED';
    ELSE
        INSERT INTO medical_access_log (event_type, doctor_id, ip_address, status, details)
        VALUES ('AUTH_FAILURE', v_doc.doctor_id, p_workstation_ip, 'FAILED', 'Неверный пароль врача');
        RETURN 'INVALID_CREDENTIALS';
    END IF;
END;
$$ LANGUAGE plpgsql;
```

### Вариант 3. Банковский терминал

#### 1. Спецификация таблицы операторов и срока годности пароля
```sql
CREATE TABLE terminal_operators (
    operator_id SERIAL PRIMARY KEY,
    login VARCHAR(50) NOT NULL UNIQUE,
    password_hash CHAR(64) NOT NULL,
    salt CHAR(32) NOT NULL,
    password_expiry DATE NOT NULL DEFAULT (CURRENT_DATE + INTERVAL '90 day'),
    must_change_password BOOLEAN NOT NULL DEFAULT FALSE,
    failed_attempts INT NOT NULL DEFAULT 0,
    locked_until TIMESTAMP NULL
);
```

#### 2. Валидация срока пароля и первого входа
```sql
CREATE OR REPLACE FUNCTION verify_terminal_operator(
    p_login VARCHAR(50),
    p_password VARCHAR(100),
    p_terminal_ip VARCHAR(45)
) RETURNS VARCHAR(50) AS $$
DECLARE
    v_op RECORD;
    v_hash CHAR(64);
BEGIN
    SELECT * INTO v_op FROM terminal_operators WHERE login = p_login;
    IF NOT FOUND THEN RETURN 'ERR_INVALID_CREDENTIALS'; END IF;

    v_hash := encode(digest(p_password || v_op.salt, 'sha256'), 'hex');
    IF v_hash <> v_op.password_hash THEN
        RETURN 'ERR_INVALID_CREDENTIALS';
    END IF;

    -- Пароль верен, проверяем специальные банковские политики:
    IF v_op.must_change_password THEN
        RETURN 'REQUIRE_PASSWORD_CHANGE_FIRST_LOGIN';
    END IF;

    IF v_op.password_expiry < CURRENT_DATE THEN
        RETURN 'REQUIRE_PASSWORD_CHANGE_EXPIRED';
    END IF;

    RETURN 'OPERATOR_AUTH_SUCCESS';
END;
$$ LANGUAGE plpgsql;
```

## 4. Эталон резервного домашнего задания `domashnee_zadanie.html`

### 1. Аналитический SQL-запрос выявления Brute-force атак
```sql
-- Поиск IP-адресов с более чем 5 неудачными попытками за последние 15 минут
SELECT 
    ip_address,
    COUNT(*) AS total_failed_attempts,
    COUNT(DISTINCT attempted_login) AS targeted_accounts,
    MIN(timestamp) AS attack_started,
    MAX(timestamp) AS last_attempt
FROM security_audit_log
WHERE status IN ('FAILED', 'BLOCKED')
  AND timestamp >= CURRENT_TIMESTAMP - INTERVAL '15 minute'
GROUP BY ip_address
HAVING COUNT(*) > 5
ORDER BY total_failed_attempts DESC;
```

## 5. Классификатор типовых студенческих ошибок и штрафные баллы

| Код ошибки | Сущность ошибки | Снятие баллов |
| :---: | :--- | :---: |
| **ERR-01** | **Хранение открытого пароля или отсутствие соли:** Пароль хранится в `VARCHAR` без хэширования либо хэшируется без добавления `salt`. | **-2.0 балла** |
| **ERR-02** | **Преждевременный сброс счетчика неудач:** Команда `failed_attempts = 0` выполняется до успешного совпадения хэшей паролей. | **-1.0 балл** |
| **ERR-03** | **Утечка информации (User Enumeration):** Вывод в клиентский интерфейс разных сообщений: «Пользователь не существует» vs «Пароль неверен». | **-0.5 балла** |
| **ERR-04** | **Запись пароля в Security Audit Log:** Запись сырого пароля в столбец `details` таблицы аудита безопасности. | **-1.0 балл** |
| **ERR-05** | **Иллюзия безопасности интерфейса:** Утверждение, что `style.display = 'none'` для кнопки в браузере гарантирует безопасность без проверки прав в СУБД. | **-0.5 балла** |
| **ERR-06** | **Пропуск контрольных вопросов:** Не заполнен блок вопросов для самопроверки в рабочем листе. | **-0.5 балла** |
