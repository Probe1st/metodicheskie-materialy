Задание 1. Разработка скрипта прямой миграции (Forward Migration)

В рамках релиза корпоративной системы управления проектами требуется модифицировать схему базы данных. Исходная таблица сотрудников содержит базовую информацию:

CREATE TABLE project_employees (
    employee_id SERIAL PRIMARY KEY,
    full_name VARCHAR(120) NOT NULL,
    department VARCHAR(50) NOT NULL,
    salary NUMERIC(10, 2) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

Постановка задачи релиза v2.1:

  1. Создать отдельную справочную таблицу отделов company_departments (dept_id SERIAL PRIMARY KEY, dept_name VARCHAR(50) NOT NULL UNIQUE, head_officer VARCHAR(120) NOT NULL).
  2. Заполнить таблицу начальными данными (Отдел разработки, Бухгалтерия, Отдел продаж).
  3. Добавить в таблицу project_employees внешний ключ dept_id, ссылающийся на company_departments(dept_id).
  4. Требование Zero-Downtime: Новое поле dept_id не должно ломать старые операции вставки! Предусмотреть значение по умолчанию для существующих и новых сотрудников.

Задание 2. Разработка скрипта обратного отката (Undo Migration)

Смоделируйте сценарий отката релиза (Rollback) в случае выявления критических дефектов интеграции. Скрипт отката должен вернуть схему базы данных к исходному состоянию версии 1.0.

Требования к скрипту отката:

  • Соблюдение принципа зеркальности (LIFO — Last In, First Out);
  • Корректное удаление ограничений внешнего ключа перед удалением справочной таблицы во избежание ошибок нарушения целостности;
  • Исключение возникновения ошибок при повторном запуске (использование проверок IF EXISTS).

Задание 3. Заполнение метаданных в системной таблице версий

Сформируйте SQL-запрос INSERT INTO flyway_schema_history, который регистрирует применение вашей прямой миграции V2_1__add_company_departments.sql со следующими параметрами: порядковый номер installed_rank = 2, контрольная сумма хэша checksum = 148920195, время выполнения execution_time = 45 мс, статус success = TRUE.
