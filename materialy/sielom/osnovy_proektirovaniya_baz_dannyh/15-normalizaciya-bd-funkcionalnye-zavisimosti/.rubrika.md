## 3. Полные закрытые эталоны решений по 4 практическим вариантам

### Вариант 1. Формальная схема R(A, B, C, D, E)

#### 1. Исходные данные
Отношение: <code>R(A, B, C, D, E)</code>. Универсальное множество: <code>U = {A, B, C, D, E}</code>.<br>
Множество ФЗ: <code>F = { A → BC, CD → E, B → D, E → A }</code>.

#### 2. Задание 1.1. Вычисление замыкания {B}+
- **Инициализация (Шаг 0):** <code>X⁺ = {B}</code>.
- **Итерация 1:**
  * Проверяем <code>B → D</code>: детерминант <code>{B} ⊆ {B}</code> (Истина). Добавляем RHS: <code>X⁺ = {B, D}</code>.
  * Проверяем <code>A → BC</code>: <code>{A} ⊈ {B, D}</code> (Ложь).
  * Проверяем <code>CD → E</code>: <code>{C, D} ⊈ {B, D}</code> (Ложь, нет C).
  * Проверяем <code>E → A</code>: <code>{E} ⊈ {B, D}</code> (Ложь).
- **Итерация 2:**
  * Проверка всех ФЗ не дает новых атрибутов. Достигнута неподвижная точка.
- **Итоговый результат:**
  <code>{B}⁺ = {B, D}</code>.
- **Вывод:** Так как <code>{B}⁺ = {B, D} ≠ U</code>, множество <code>{B}</code> не является суперключом и не является ключом отношения <code>R</code>.

#### 3. Задание 1.2. Определение всех потенциальных ключей
1. **Классификация L-R-B-N:**
   - Левые части (LHS): <code>{A, B, C, D, E}</code>.
   - Правые части (RHS): <code>{A, B, C, D, E}</code> (так как A в E→A; B, C в A→BC; D в B→D; E в CD→E).
   - Класс L (только слева): <code>∅</code>.
   - Класс R (только справа): <code>∅</code>.
   - Класс N (ни слева, ни справа): <code>∅</code>.
   - Класс B (и слева, и справа): <code>{A, B, C, D, E}</code>.
2. **Проверка одноэлементных подмножеств:**
   - <code>{A}⁺</code>: <code>A → BC ⟹ {A, B, C}</code>; <code>B → D ⟹ {A, B, C, D}</code>; <code>CD → E ⟹ {A, B, C, D, E} = U</code>.
     **Ключ 1: {A}** (минимален, так как размер 1).
   - <code>{E}⁺</code>: <code>E → A ⟹ {E, A}</code>. Так как <code>A ∈ {E}⁺</code>, а <code>{A}⁺ = U</code>, то <code>{E}⁺ = U</code>.
     **Ключ 2: {E}** (минимален, так как размер 1).
   - <code>{B}⁺ = {B, D} ≠ U</code> (не ключ).
   - <code>{C}⁺ = {C} ≠ U</code> (не ключ).
   - <code>{D}⁺ = {D} ≠ U</code> (не ключ).
3. **Проверка двухэлементных подмножеств (не содержащих A и E):**
   - Любое надмножество <code>{A}</code> или <code>{E}</code> отбрасывается по критерию минимальности.
   - Рассмотрим пары из <code>{B, C, D}</code>:
     * Пара <code>{C, D}</code>: <code>CD → E ⟹ {C, D, E}</code>. Так как <code>E ∈ {C, D}⁺</code>, то <code>{C, D}⁺ = U</code>. Ни <code>{C}⁺</code>, ни <code>{D}⁺</code> не равны <code>U</code>.
       **Ключ 3: {C, D}**.
     * Пара <code>{B, C}</code>: <code>B → D ⟹ {B, C, D}</code>. Так как <code>{C, D} ⊆ {B, C, D}</code>, то получаем <code>E</code> и <code>A</code>, следовательно <code>{B, C}⁺ = U</code>. Ни <code>{B}⁺</code>, ни <code>{C}⁺</code> не равны <code>U</code>.
       **Ключ 4: {B, C}**.
     * Пара <code>{B, D}</code>: <code>{B, D}⁺ = {B, D} ≠ U</code> (не ключ).
4. **Проверка трехэлементных подмножеств:**
   - Единственная оставшаяся тройка без ключей — <code>{B, C, D}</code>, но она содержит кандидатные ключи <code>{C, D}</code> и <code>{B, C}</code>, поэтому не минимальна.
- **Итоговый ответ:** В отношении <code>R</code> существует ровно **4 потенциальных ключа:**
  **`{A}`, `{E}`, `{C, D}`, `{B, C}`**.

#### 4. Задание 1.3. Построение минимального покрытия (Minimal Cover)
1. **Шаг 1. Расщепление правых частей (Singleton RHS):**
   Зависимость <code>A → BC</code> расщепляем на <code>A → B</code> и <code>A → C</code>:
   <code>F₁ = { A → B, A → C, CD → E, B → D, E → A }</code>.
2. **Шаг 2. Устранение посторонних атрибутов слева (LHS):**
   Единственный составной детерминант — <code>CD → E</code>.
   - Проверяем устранение C (тестируем <code>D → E</code>): вычисляем <code>{D}⁺</code> в <code>F₁</code>: <code>{D}⁺ = {D} ∌ E</code>. Атрибут C неизбыточен.
   - Проверяем устранение D (тестируем <code>C → E</code>): вычисляем <code>{C}⁺</code> в <code>F₁</code>: <code>{C}⁺ = {C} ∌ E</code>. Атрибут D неизбыточен.
   Следовательно, посторонних атрибутов в детерминантах нет: <code>F₂ = F₁</code>.
3. **Шаг 3. Устранение избыточных зависимостей:**
   - Проверяем <code>A → B</code>: <code>{A}⁺</code> в <code>F₂ \ {A → B}</code>: <code>{A} ∪ {C} = {A, C}</code> (B не выводится). ФЗ неудаляема.
   - Проверяем <code>A → C</code>: <code>{A}⁺</code> в <code>F₂ \ {A → C}</code>: <code>{A, B, D}</code> (C не выводится). ФЗ неудаляема.
   - Проверяем <code>CD → E</code>: <code>{C, D}⁺</code> без этой ФЗ равен <code>{C, D}</code> (E не выводится). Неудаляема.
   - Проверяем <code>B → D</code>: <code>{B}⁺ = {B}</code> (D не выводится). Неудаляема.
   - Проверяем <code>E → A</code>: <code>{E}⁺ = {E}</code> (A не выводится). Неудаляема.
- **Итоговое минимальное покрытие:**
  **`F_min = { A → B, A → C, CD → E, B → D, E → A }`**.

#### 5. Задание 1.4. Ответ на вопрос самопроверки
По аксиоме транзитивности, если <code>E → A</code>, а <code>A</code> определяет все атрибуты схемы (<code>{A}⁺ = U</code>), то по цепочке <code>E → A ⟹ {E}⁺ = U</code>. Так как <code>E</code> одноэлементен, никакое его собственное непустое подмножество существовать не может, что гарантирует свойство минимальности без дополнительных проверок.

### Вариант 2. Проекты и сотрудники

#### 1. Исходные данные
Отношение: <code>R(EmpID, ProjID, DeptID, Role, Salary)</code>.<br>
Множество ФЗ:
<code>F = { EmpID → {DeptID, Salary}, {EmpID, ProjID} → Role }</code>.

#### 2. Задание 2.1. Определение потенциального ключа
1. **Анализ детерминантов:**
   - Атрибут <code>ProjID</code> не входит ни в одну правую часть ФЗ (класс L). Он **обязан** входить во все ключи.
   - Атрибут <code>EmpID</code> не входит ни в одну правую часть ФЗ (класс L). Он **обязан** входить во все ключи.
2. **Вычисление замыкания ядра:**
   <code>Core = {EmpID, ProjID}</code>.
   <code>{EmpID, ProjID}⁺</code>:
   - по <code>EmpID → {DeptID, Salary}</code> добавляем <code>DeptID, Salary</code>;
   - по <code>{EmpID, ProjID} → Role</code> добавляем <code>Role</code>;
   - <code>{EmpID, ProjID}⁺ = {EmpID, ProjID, DeptID, Role, Salary} = U</code>.
3. **Вывод:** Отношение имеет **единственный потенциальный ключ: `{EmpID, ProjID}`**. Ключ является составным из двух полей.

#### 3. Задание 2.2. Выявление частичной зависимости
- В отношении действует зависимость: <code>EmpID → {DeptID, Salary}</code>.
- Детерминант <code>EmpID</code> является **строгим собственным подмножеством** составного первичного ключа: <code>{EmpID} ⊂ {EmpID, ProjID}</code>.
- Атрибуты <code>DeptID</code> и <code>Salary</code> являются **неключевыми** (не входят в ключ).
- Следовательно, зависимость <code>EmpID → DeptID, Salary</code> является **частичной функциональной зависимостью**.
- Наличие частичной зависимости неключевых атрибутов от составного ключа является прямым **нарушением Второй нормальной формы (2НФ)**.

#### 4. Задание 2.3. Иллюстрация аномалий
- **Аномалия избыточности:** Если сотрудник участвует в 10 проектах, его отдел и зарплата дублируются в таблице 10 раз.
- **Аномалия обновления:** При повышении оклада сотрудника необходимо синхронно обновить оклад во всех 10 строках. Если одна строка будет пропущена — возникнет рассогласование оклада в рамках одного табельного номера.
- **Аномалия вставки:** Нельзя внести нового сотрудника компании, пока ему не назначен хотя бы один проект (так как <code>ProjID</code> как часть PK не может быть NULL).
- **Аномалия удаления:** Если закрывается проект и удаляются соответствующие строки, увольняется информация о проектной роли; если это был единственный проект сотрудника, будет потеряна вся информация о его назначении.

#### 5. Задание 2.4. Декомпозиция в 2НФ
Для устранения частичной зависимости отношение расщепляется на два независимых отношения:
1. **`Сотрудники(EmpID, DeptID, Salary)`** — первичный ключ: `EmpID`. (Все атрибуты функционально полно зависят от `EmpID`).
2. **`Назначения_на_проекты(EmpID, ProjID, Role)`** — первичный ключ: `(EmpID, ProjID)`. Внешний ключ: `EmpID REFERENCES Сотрудники(EmpID)`.

### Вариант 3. Логистика и доставка

#### 1. Исходные данные
Отношение: <code>R(ShipmentID, ItemID, ClientID, WarehouseID, Quantity, Address)</code>.<br>
Множество ФЗ:
<code>F = { ShipmentID → {ClientID, Address}, {ShipmentID, ItemID} → {Quantity, WarehouseID}, ClientID → Address }</code>.

#### 2. Задание 3.1. Определение потенциального ключа
1. **Классификация L-R-B-N:**
   - <code>ItemID</code> встречается только слева (L) — обязателен в ключе.
   - <code>ShipmentID</code> встречается только слева (L) — обязателен в ключе.
   - Базовое ядро: <code>Core = {ShipmentID, ItemID}</code>.
2. **Вычисление замыкания ядра:**
   <code>{ShipmentID, ItemID}⁺</code>:
   - по <code>ShipmentID → {ClientID, Address}</code> добавляем <code>ClientID, Address</code>;
   - по <code>{ShipmentID, ItemID} → {Quantity, WarehouseID}</code> добавляем <code>Quantity, WarehouseID</code>;
   - Итог: <code>{ShipmentID, ItemID}⁺ = {ShipmentID, ItemID, ClientID, WarehouseID, Quantity, Address} = U</code>.
3. **Вывод:** Единственный потенциальный (первичный) ключ: **`{ShipmentID, ItemID}`**.

#### 3. Задание 3.2. Выявление транзитивной зависимости
- В схеме присутствуют зависимости:
  1) <code>ShipmentID → ClientID</code> (отгрузка оформляется на конкретного клиента).
  2) <code>ClientID → Address</code> (у клиента есть постоянный юридический адрес).
  3) Обратная зависимость отсутствует: <code>ClientID ↛ ShipmentID</code> (у клиента много отгрузок).
- По аксиоме транзитивности получаем: <code>ShipmentID → Address</code> через промежуточный неключевой детерминант <code>ClientID</code>.
- Зависимость неключевого атрибута <code>Address</code> от ключа через другой неключевой атрибут <code>ClientID</code> является **транзитивной функциональной зависимостью**.
- Наличие транзитивной зависимости нарушает **Третью нормальную форму (3НФ)**.

#### 4. Задание 3.3. Анализ аномалии обновления
Если клиент сменит юридический адрес, сотрудникам логистической службы придется вручную переписывать поле <code>Address</code> во всех 500 архивных и текущих отгрузках этого контрагента. При ошибке оператора в отгрузках одного и того же клиента появятся конфликтующие адреса, что сорвет доставку.

#### 5. Задание 3.4. Проект декомпозиции в 3НФ
Отношение декомпозируется на три отношения без потерь информации и зависимостей:
1. **`Клиенты(ClientID, Address)`** — PK: `ClientID`.
2. **`Отгрузки(ShipmentID, ClientID)`** — PK: `ShipmentID`, FK: `ClientID REFERENCES Клиенты(ClientID)`.
3. **`Позиции_отгрузки(ShipmentID, ItemID, Quantity, WarehouseID)`** — PK: `(ShipmentID, ItemID)`, FK: `ShipmentID REFERENCES Отгрузки(ShipmentID)`.

### Вариант 4. Формальная схема R(X, Y, Z, W, V)

#### 1. Исходные данные
Отношение: <code>R(X, Y, Z, W, V)</code>.<br>
Множество ФЗ: <code>F = { X → Y, Y → Z, XZ → W, W → V }</code>.

#### 2. Задание 4.1. Доказательство X → W по аксиомам Армстронга
- **Шаг 1:** По условию даны <code>X → Y</code> и <code>Y → Z</code>.
  По аксиоме **транзитивности (А3)**:
  <code>X → Y ∧ Y → Z  ⟹  X → Z</code>.
- **Шаг 2:** Применим к зависимости <code>X → Z</code> аксиому **пополнения (А2)** атрибутом <code>X</code>:
  <code>X → Z  ⟹  XX → XZ  ⟺  X → XZ</code>.
  *(Альтернативно: по аксиоме рефлексивности X → X, затем по правилу объединения X → XZ)*.
- **Шаг 3:** Имеем зависимости <code>X → XZ</code> и заданную в условии <code>XZ → W</code>.
  По аксиоме **транзитивности (А3)**:
  <code>X → XZ ∧ XZ → W  ⟹  X → W</code>.
- **Вывод:** Зависимость <code>X → W</code> строго доказана! (Q.E.D.).

#### 3. Задание 4.2. Нахождение потенциального ключа
1. **Анализ вхождений:**
   - <code>X</code> входит только в левую часть (L) — обязан быть в ключе.
   - <code>Y, Z, W, V</code> входят в правые части (RHS).
2. **Вычисление замыкания {X}+:**
   - <code>{X}⁺ = {X}</code>;
   - <code>X → Y ⟹ {X, Y}</code>;
   - <code>Y → Z ⟹ {X, Y, Z}</code>;
   - <code>XZ → W ⟹ {X, Y, Z, W}</code>;
   - <code>W → V ⟹ {X, Y, Z, W, V} = U</code>.
3. **Вывод:** <code>{X}⁺ = U</code>. Так как <code>X</code> одноэлементен, он строго минимален.
   **Единственный потенциальный ключ: `{X}`**.

#### 4. Задание 4.3. Построение минимального покрытия (Minimal Cover)
1. **Шаг 1. Расщепление правых частей:**
   Все правые части в <code>F</code> уже атомарны (Y, Z, W, V).
2. **Шаг 2. Проверка посторонних атрибутов слева в XZ → W:**
   - Проверяем атрибут <code>Z</code>: вычисляем <code>{X}⁺</code> относительно текущего <code>F</code>:
     <code>{X}⁺ = {X, Y, Z, W, V}</code>.
   - Так как <code>Z ∈ {X}⁺</code>, атрибут <code>Z</code> в детерминанте <code>XZ</code> является **посторонним (избыточным)**!
   - Заменяем <code>XZ → W</code> на <code>X → W</code>.
   - Получаем промежуточное множество:
     <code>F' = { X → Y, Y → Z, X → W, W → V }</code>.
3. **Шаг 3. Проверка избыточных зависимостей в F':**
   - <code>X → Y</code>: замыкание <code>{X}⁺</code> в <code>F' \ {X → Y}</code> дает <code>{X, W, V}</code> (Y не выводится). Неудаляема.
   - <code>Y → Z</code>: <code>{Y}⁺</code> без этой ФЗ дает <code>{Y}</code> (Z не выводится). Неудаляема.
   - <code>X → W</code>: <code>{X}⁺</code> без этой ФЗ дает <code>{X, Y, Z}</code> (W не выводится). Неудаляема.
   - <code>W → V</code>: <code>{W}⁺</code> без этой ФЗ дает <code>{W}</code> (V не выводится). Неудаляема.
- **Итоговое минимальное покрытие:**
  **`F_min = { X → Y, Y → Z, X → W, W → V }`**.

#### 5. Задание 4.4. Ответ на вопрос самопроверки
Атрибут <code>Z</code> избыточен в левой части <code>XZ</code>, потому что наличие цепочки <code>X → Y</code> и <code>Y → Z</code> гарантирует, что везде, где известно значение <code>X</code>, значение <code>Z</code> уже однозначно предопределено. Добавление предопределенного атрибута к детерминанту не добавляет новой фильтрующей силы и является логическим балластом.

## 4. Эталон резервного домашнего задания `domashnee_zadanie.html`

### 1. Вычисление замыканий
- **`{A}⁺`**:
  * Шаг 0: `{A}`.
  * Шаг 1: `A → BC ⟹ {A, B, C}`.
  * Шаг 2: `B → D ⟹ {A, B, C, D}`.
  * Шаг 3: `CD → E ⟹ {A, B, C, D, E}`.
  * Шаг 4: `E → F ⟹ {A, B, C, D, E, F} = U`.
  * **Итог: `{A}⁺ = {A, B, C, D, E, F}`**.
- **`{B}⁺`**:
  * `B → D ⟹ {B, D}`. Другие ФЗ неприменимы.
  * **Итог: `{B}⁺ = {B, D}`**.
- **`{C, D}⁺`**:
  * `CD → E ⟹ {C, D, E}`; `E → F ⟹ {C, D, E, F}`.
  * **Итог: `{C, D}⁺ = {C, D, E, F}`**.
- **`{B, C}⁺`**:
  * `B → D ⟹ {B, C, D}`; `CD → E ⟹ {B, C, D, E}`; `E → F ⟹ {B, C, D, E, F}`.
  * **Итог: `{B, C}⁺ = {B, C, D, E, F}`**.

### 2. Определение потенциальных ключей
- Атрибут `A` входит только в LHS (класс L) — обязан входить в ключ.
- Замыкание `{A}⁺ = U`.
- **Единственный потенциальный ключ: `{A}`**.

### 3. Минимальное покрытие
1. Расщепление RHS: `F₁ = { A → B, A → C, B → D, CD → E, E → F }`.
2. Проверка детерминантов: в `CD → E` атрибуты C и D неизбыточны (ни `C⁺`, ни `D⁺` не содержат E).
3. Проверка зависимостей: ни одна ФЗ не выводится из остальных.
- **`F_min = { A → B, A → C, B → D, CD → E, E → F }`**.

### 4. Анализ нормализации и декомпозиция
- Присутствуют транзитивные зависимости неключевых полей: `A → D` (через B), `A → E` (через CD), `A → F` (через E). Это нарушает 3НФ.
- Декомпозиция в 3НФ/BCNF:
  1. `R₁(A, B, C)` — PK: `A`.
  2. `R₂(B, D)` — PK: `B`.
  3. `R₃(C, D, E)` — PK: `(C, D)`.
