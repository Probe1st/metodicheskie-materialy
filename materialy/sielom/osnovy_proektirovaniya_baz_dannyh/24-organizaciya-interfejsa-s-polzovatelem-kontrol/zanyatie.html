Часть 2. Серверный триггер остатков и перехват исключения P0001

Два покупателя одновременно нажали кнопку «Купить» на последнюю единицу товара на складе. В СУБД сработал серверный триггер:

CREATE OR REPLACE FUNCTION trg_check_inventory() RETURNS TRIGGER AS 
DECLARE vstock INT;
BEGIN
    SELECT stockquantity INTO vstock FROM warehouse WHERE productid = NEW.productid FOR UPDATE;
    IF vstock < NEW.quantity THEN
        RAISE EXCEPTION 'OUTOFSTOCK: Недостаточно товара на складе' USING ERRCODE = 'P0001';
    END IF;
    UPDATE warehouse SET stockquantity = stockquantity - NEW.quantity WHERE productid = NEW.productid;
    RETURN NEW;
END;
 LANGUAGE plpgsql;
  1. Как ядро СУБД обработает одновременную покупку благодаря FOR UPDATE? Что произойдет со вторым покупателем?
  2. Спроектируйте перехватчик исключения SQLSTATE P0001 на бэкенде: какое дружественное сообщение увидит второй покупатель на экране оформления заказа?

    booking_id BIGSERIAL PRIMARY KEY,

    stay_dates DATERANGE NOT NULL,

    )
