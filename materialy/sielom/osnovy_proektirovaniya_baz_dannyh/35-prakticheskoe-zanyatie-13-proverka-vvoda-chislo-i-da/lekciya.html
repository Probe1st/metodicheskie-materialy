Тема 5. Организация запросов SQL

Практическое занятие №13: проверка ввода, число и дата

Целостность данных означает, что сохранённые значения соответствуют структуре и правилам предметной области. Проверка в СУБД применяется ко всем путям записи: форме, импорту, API и запросу администратора.

Числовые типы

INTEGER хранит целое число в пределах диапазона типа. NUMERIC(p,s) или DECIMAL(p,s) задаёт точную десятичную точность: p — число всех цифр, s — дробных. Например, DECIMAL(10,2) подходит для денежной суммы, но точность поля должна соответствовать предметной области. Преобразование лишних дробных знаков и переполнение могут завершиться ошибкой ещё до проверки CHECK.

Ограничения CHECK

Ограничение проверяет логическое выражение для сохраняемой строки. Диапазоны записывают сравнением или BETWEEN (границы включены); допустимые множества — через IN; математические соотношения — выражениями между столбцами.

quantity INTEGER NOT NULL CHECK (quantity >= 1),
rate DECIMAL(5,2) NOT NULL CHECK (rate > 0 AND rate < 100),
status TEXT NOT NULL CHECK (status IN ('NEW', 'PAID', 'CANCELLED')),
CHECK (amount >= 0 AND discount <= amount)

Именуйте правило через CONSTRAINT chk_name CHECK (...): имя упрощает диагностику и изменение схемы. Для сравнения нескольких полей используйте табличное ограничение.

NULL и обязательность

В SQL результат сравнения с NULL — UNKNOWN. Ограничение CHECK (value > 0) не гарантирует обязательность: UNKNOWN обычно не считается нарушением. Если значение обязательно, добавьте NOT NULL. Если неизвестное значение допустимо, отдельно определите смысл этого состояния.

Дата и время

DATE хранит календарную дату; TIMESTAMP — дату и время. Для событий с часовым поясом выбирают тип и соглашение о часовом поясе согласно СУБД и системе. Текущую дату можно получить как CURRENT_DATE, текущую отметку времени — CURRENT_TIMESTAMP.

appointment_date DATE NOT NULL,
CHECK (appointment_date >= CURRENT_DATE)

started_at TIMESTAMP NOT NULL,
CHECK (started_at <= CURRENT_TIMESTAMP)

start_date DATE NOT NULL,
end_date DATE NOT NULL,
CHECK (start_date < end_date)

Проверка периода date_start < date_end исключает нулевой и обратный интервалы. Если бизнес-правило разрешает границу включительно, условие должно быть иным и явно обоснованным.

Интервалы и вычисления

Операции с интервалами зависят от диалекта. В PostgreSQL выражение AGE(timestamp1, timestamp2) возвращает календарный интервал; INTERVAL '3 months' задаёт интервал. Месяц не равен фиксированному числу дней, поэтому календарный срок договора корректнее сравнивать календарными датами, а не умножением месяцев на 30.

SELECT AGE(CURRENT_DATE, birth_date) AS age_interval;
SELECT CURRENT_DATE + INTERVAL '3 months' AS date_after_three_months;

В вычислениях с датами учитывайте високосные годы, конец месяца, точность времени и часовой пояс. Синтаксис и результат проверяйте на целевой СУБД.

Динамические ограничения и обработка ошибок

В некоторых СУБД, включая PostgreSQL, выражение CHECK должно зависеть только от строки и быть неизменным: условие с текущей датой может устареть без новой записи, поскольку время изменяется, а старые строки автоматически не перепроверяются. Для правила, которое должно оставаться актуальным со временем, рассмотрите триггер, периодическую проверку или соответствующую модель данных.

СУБД отклоняет недопустимую запись и возвращает ошибку целостности. Отдельно распознавайте ошибку преобразования типа, нарушение NOT NULL, нарушение CHECK и конфликт ключа. Точное имя класса и код ошибки зависят от СУБД; сообщение должно позволять исправить вход, но не раскрывать лишние внутренние сведения.

Алгоритм проектирования

  1. Назвать бизнес-правило и поля, к которым оно относится.
  2. Выбрать точный тип и точность.
  3. Сформулировать предикат, включая политику NULL и граничных значений.
  4. Добавить понятное имя ограничения.
  5. Проверить минимальную и максимальную границы, значения внутри и вне диапазона.
  6. Убедиться, что СУБД принимает корректный ввод и отклоняет некорректный с ожидаемой ошибкой.
