# Критериальная рубрика преподавателя — занятие 35

## Шкала
- **4 — отлично:** решение полное, правила и граничные тесты верны.
- **3 — хорошо:** основные ограничения корректны, одна несущественная неточность.
- **2 — удовлетворительно:** часть правил реализована; пропущен важный тест или ограничение.
- **1 — требуется доработка:** правила не соответствуют условиям, тесты не показывают отказ.

## Критерии (каждый 1–4 балла)
1. Типы: INTEGER для целых значений; DECIMAL/NUMERIC подходящей точности для денег; DATE/TIMESTAMP по назначению.
2. Предикаты: корректные диапазоны, IN, математические отношения и даты; правильные строгие/включённые границы.
3. Целостность: NOT NULL где необходимо; верная семантика временных периодов и актуальности текущей даты.
4. Проверка: позитивные и негативные тесты, граничные случаи, понимание ошибок преобразования и ограничения.

Сумма 16: 14–16 — «5», 11–13 — «4», 8–10 — «3», менее 8 — доработка; применять локальные правила оценивания.

## Эталоны вариантов

### 1. Биллинг
`duration_seconds INTEGER NOT NULL CHECK (duration_seconds > 0)`; `charge DECIMAL(10,2) NOT NULL CHECK (charge >= 0)`; тариф через `CHECK (tariff_code IN ('BASIC', 'PLUS', 'PREMIUM'))`; `transaction_at TIMESTAMP NOT NULL CHECK (transaction_at <= CURRENT_TIMESTAMP)` как учебный пример. Проверить нулевую длительность, отрицательную сумму, будущее и допустимую границу. Точный перечень тарифов согласовать с условием варианта.

### 2. Регистратура
`age INTEGER NOT NULL CHECK (age BETWEEN 0 AND 125)`; дата не раньше текущей; время приёма в 08:00–20:00, например `CHECK (appointment_time >= TIME '08:00' AND appointment_time <= TIME '20:00')`. Проверить оба включённых края и соседние недопустимые значения. Условие текущей даты в CHECK требует оговорки о динамичности.

### 3. Кредит
`loan_amount DECIMAL(10,2) NOT NULL CHECK (loan_amount BETWEEN 10000 AND 5000000)`; `interest_rate DECIMAL(5,2) NOT NULL CHECK (interest_rate > 0 AND interest_rate < 100)`; `term_months INTEGER NOT NULL CHECK (term_months BETWEEN 3 AND 60)`. Сумма и срок включают края; ставка 0 и 100 недопустимы.

### 4. Поставка
`quantity INTEGER NOT NULL CHECK (quantity >= 1)`; `CHECK (shipment_date >= order_date)`; срок годности позже текущей даты — учебный динамический контроль, который требует отдельного обсуждения актуальности. Равные даты заказа и отгрузки допустимы; обратный порядок и истекающий сегодня срок годности недопустимы.

## Типичные ошибки
- FLOAT для денежных значений вместо точного десятичного типа.
- Путаница точности и масштаба DECIMAL.
- Уверенность, что CHECK запрещает NULL без NOT NULL.
- Ошибочные операторы на границах; забвение включённости BETWEEN.
- Отсутствие межполевой проверки порядка дат.
- Время хранится или сравнивается как текст.
- Месяц считают фиксированным числом дней.
- Думают, что динамическое условие CHECK перепроверит старые строки после смены даты.
- Ожидают ошибку CHECK для строки, не преобразуемой в число.
- Предъявлен только позитивный тест без попытки нарушения.
