Темп, ошибки и приёмы

В полном регламенте оставлять практической работе не менее трети времени и выделить отдельные минуты на взаимопроверку. При сокращении сохранить объяснение различий типов и контроль границ, сократить число обсуждаемых примеров, а не проверку ограничений.

  • DECIMAL(p,s) хранит точную десятичную величину; FLOAT не подходит для денежных сумм.
  • CHECK принимает выражение, не равное FALSE; NULL сам по себе не отвергается, поэтому обязательность задают NOT NULL.
  • CHECK обычно относится к строке и не заменяет проверку межстрочных правил; текущую дату/время следует использовать с учётом возможностей конкретной СУБД.
  • DATE хранит календарную дату, TIMESTAMP — дату и время; часовой пояс требует осознанного выбора типа.
  • Для периода используйте date_start < date_end; проверьте равные границы, обратный порядок и високосную дату.
  • AGE и INTERVAL имеют диалектные различия; показывайте как пример PostgreSQL, просите сверяться с целевой СУБД.
  • Неверный текст может вызвать ошибку преобразования типа до CHECK; нарушение допустимого типа и ограничения — разные ошибки.

Приём: «граница — внутрь — снаружи». Для диапазона проверить нижнюю границу, верхнюю, значения за каждой границей. Для времени проверить сейчас, будущее/прошлое и равенство границ периода.

Безопасная формулировка правил

CREATE TABLE call_log (
  duration_seconds INTEGER NOT NULL CHECK (duration_seconds > 0),
  charge DECIMAL(10,2) NOT NULL CHECK (charge >= 0),
  occurred_at TIMESTAMP NOT NULL CHECK (occurred_at <= CURRENT_TIMESTAMP)
);

CREATE TABLE booking (
  date_start DATE NOT NULL,
  date_end DATE NOT NULL,
  CHECK (date_start < date_end)
);

В PostgreSQL ограничение дат прошлого/будущего через CURRENT_DATE требует осторожности: CHECK предполагает неизменность выражения для сохранённой строки. Текущие правила, меняющиеся со временем, надёжнее контролировать при записи триггером или приложением; на уроке обсуждать границу применимости.
