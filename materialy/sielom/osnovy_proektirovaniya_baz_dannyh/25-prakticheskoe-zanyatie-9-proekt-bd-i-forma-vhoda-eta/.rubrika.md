Данный документ представляет собой закрытый методический инструмент преподавателя дисциплины «ОП.08 Основы проектирования баз данных» (СИЭУиП) и содержит критериальную шкалу оценивания, полные эталонные решения для всех 4 практических кейсов интерактивного листа `zanyatie.html`, эталон резервного домашнего задания `domashnee_zadanie.html` и классификатор типовых студенческих ошибок со шкалой штрафных вычетов.

- **Критериальная шкала:** 4-балльная шкала:
  * **Часть 1. Структура таблиц безопасности (users, roles, audit_logs):** **2 балла** (1 балл за мелкие синтаксические неточности SQL при верном составе полей и связей; 0 баллов при открытом хранении паролей, отсутствии соли или игнорировании внешних ключей).

## 3. Полные эталонные решения для 4 вариантов рабочего листа

### Вариант 1: Информационная система «Оптовый склад»

#### Задание 1.1. SQL DDL-спецификация таблиц
```sql
-- 1. Справочник ролей
CREATE TABLE roles (
    id SERIAL PRIMARY KEY,
    role_name VARCHAR(50) NOT NULL UNIQUE,     -- 'Storekeeper', 'Manager', 'Accountant', 'Admin'
    role_description VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL
);

-- 2. Справочник складов/филиалов
CREATE TABLE warehouses (
    id SERIAL PRIMARY KEY,
    warehouse_name VARCHAR(100) NOT NULL UNIQUE,
    address VARCHAR(255) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE NOT NULL
);

-- 3. Таблица учетных записей сотрудников склада
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    login VARCHAR(50) NOT NULL UNIQUE,
    salt VARCHAR(64) NOT NULL,
    password_hash VARCHAR(128) NOT NULL,
    role_id INTEGER NOT NULL,
    default_warehouse_id INTEGER,
    is_active BOOLEAN DEFAULT TRUE NOT NULL,
    failed_attempts SMALLINT DEFAULT 0 NOT NULL,
    locked_until TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT fk_users_role FOREIGN KEY (role_id) 
        REFERENCES roles(id) ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_users_warehouse FOREIGN KEY (default_warehouse_id) 
        REFERENCES warehouses(id) ON UPDATE CASCADE ON DELETE SET NULL
);

-- 4. Журнал аудита безопасности
CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT,
    attempted_login VARCHAR(50) NOT NULL,
    event_type VARCHAR(30) NOT NULL, -- 'LOGIN_SUCCESS', 'LOGIN_FAILURE', 'LOCKOUT'
    ip_address VARCHAR(45) NOT NULL,
    selected_warehouse_id INTEGER,
    event_time TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT fk_audit_user FOREIGN KEY (user_id) 
        REFERENCES users(id) ON DELETE SET NULL
);

CREATE INDEX idx_users_login ON users(login);
CREATE INDEX idx_audit_time ON audit_logs(event_time);
```

#### Задание 1.2. Макет диалогового окна формы входа
```text
+-------------------------------------------------------+
|  Авторизация | Логистический комплекс «Оптовый Склад» |
+-------------------------------------------------------+
|  [ ! ] Неверный логин или пароль                      |
|                                                       |
|  Выберите склад / филиал:                             |
|  [ Центральный распределительный терминал (Склад 1) V]|
|                                                       |
|  Имя пользователя (Логин):                            |
|  [ sklad_ivanov                                      ]|
|                                                       |
|  Пароль:                                              |
|  [ ••••••••••••••••••                              (o)]|
|                                                       |
|  [           ВОЙТИ В СКЛАДСКУЮ СИСТЕМУ               ]|
+-------------------------------------------------------+
Состояния контролов:
1. Поле филиала: select с предзаполненным активным складом по умолчанию.
2. Поле пароля: type="password", справа кнопка-переключатель видимости (SVG-глаз).
3. Кнопка «Войти»:
   - disabled, если длина логина < 3 или длина пароля < 6;
   - состояние "Проверка учетных данных..." с индикатором-спиннером при клике;
4. Ошибка: красный плавающий баннер без указания, в чем именно ошибка (в логине или пароле).
```

#### Задание 1.3. Аналитическое обоснование
1. **Связка salt + hash:** Защищает базу данных от предварительно скомпилированных радужных таблиц (Rainbow tables). Даже если у Кладовщика и Бухгалтера одинаковый пароль, их хэши в базе будут абсолютно разными.
2. **Нейтральное сообщение:** Предотвращает атаку перечисления пользователей (User Enumeration). Если выводить «Логин не найден», злоумышленник быстро составит список действующих сотрудников склада.
3. **Soft Delete (`is_active = FALSE`):** При увольнении сотрудника его логин деактивируется. При этом сохраняются внешние ключи во всех накладных, приходных ордерах и аудите, которые этот сотрудник оформил за годы работы.

### Вариант 2: Медицинская система поликлиники (2FA)

#### Задание 2.1. SQL DDL-спецификация таблиц
```sql
CREATE TABLE roles (
    id SERIAL PRIMARY KEY,
    role_name VARCHAR(50) NOT NULL UNIQUE,     -- 'Doctor', 'Registrar', 'HeadPhysician'
    role_description VARCHAR(255) NOT NULL
);

CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    staff_number VARCHAR(20) NOT NULL UNIQUE,  -- Табельный номер врача (строка из-за лидирующих нулей)
    salt VARCHAR(64) NOT NULL,
    password_hash VARCHAR(128) NOT NULL,
    totp_secret VARCHAR(64) NOT NULL,          -- Секретный ключ для алгоритма RFC 6238 TOTP

    role_id INTEGER NOT NULL,
    is_active BOOLEAN DEFAULT TRUE NOT NULL,
    failed_attempts SMALLINT DEFAULT 0 NOT NULL,
    locked_until TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT fk_med_users_roles FOREIGN KEY (role_id) 
        REFERENCES roles(id) ON UPDATE CASCADE ON DELETE RESTRICT
);

CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT,
    attempted_login VARCHAR(50) NOT NULL,
    event_type VARCHAR(30) NOT NULL, -- 'AUTH_PWD_OK', 'AUTH_2FA_FAIL', 'AUTH_SUCCESS'
    ip_address VARCHAR(45) NOT NULL,
    event_time TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    details TEXT,
    CONSTRAINT fk_audit_med_user FOREIGN KEY (user_id) 
        REFERENCES users(id) ON DELETE SET NULL
);
```

```text
+-------------------------------------------------------+

ШАГ 2: Подтверждение второго фактора (2FA)
+-------------------------------------------------------+

```

#### Задание 2.3. Аналитическое обоснование
1. **VARCHAR для табельного номера:** Табельные номера часто имеют формат со стартовыми нулями (`004812`) или буквенными префиксами (`ВР-104`). В `INTEGER` лидирующие нули будут безвозвратно утеряны.
2. **Защита 2FA:** Даже если база данных медицинского учреждения утечет и пароли будут скомпрометированы, злоумышленник не сможет войти в систему без владения физическим устройством врача, генерирующим временный одноразовый TOTP-код.
3. **Lockout и аудит:** Защита от перебора паролей и кодов 2FA. При 5 неверных попытках учетная запись блокируется, а в аудит пишется событие с IP-адресом для расследования инцидента безопасности.

#### Задание 3.2. Макет терминала с виртуальной цифровой клавиатурой
```text
+-------------------------------------------------------+
|  Банковский расчетно-кассовый терминал № 14-А         |
+-------------------------------------------------------+
|  Код оператора:                                       |

|  PIN-код / Пароль (экранный ввод):                   |
|  [ • • • • • •                                       ]|
|                                                       |
|  Виртуальная клавиатура безопасности (случайный порядок):|
|  +-------+-------+-------+                           |
|  | [ 7 ] | [ 2 ] | [ 9 ] |                           |
|  +-------+-------+-------+                           |
|  | [ 0 ] | [ 5 ] | [ 3 ] |                           |
|  +-------+-------+-------+                           |
|  | [ 8 ] | [ 1 ] | [ 4 ] |                           |
|  +-------+-------+-------+                           |
|  | [ C ] | [ 6 ] | [ < ] |  C - сброс, < - стереть   |
|  +-------+-------+-------+                           |

|                                                       |
|  [            АВТОРИЗОВАТЬ ОПЕРАТОРА                 ]|
+-------------------------------------------------------+
```

#### Задание 3.3. Аналитическое обоснование
1. **Преимущество bcrypt в банках:** bcrypt использует настраиваемый фактор вычислительной сложности (`cost factor`). Даже на специализированных ASIC/GPU кластерах перебор паролей замедляется в миллионы раз по сравнению с простым SHA-256.
2. **Экранная клавиатура и Shoulder Surfing:** Случайное перемешивание кнопок разрушает привязку координат кликов к цифрам. Видеокамера за спиной оператора или вредоносный перехватчик координат тачскрина не позволяют восстановить PIN-код.
3. **Блокировка терминала:** Предотвращает автоматизированный перебор PIN-кода на рабочем месте оператора. 3 ошибки &rarr; терминал переходит в статус блокировки до подтверждения Контролером.

### Вариант 4: Образовательный портал колледжа

#### Задание 4.1. SQL DDL-спецификация таблиц
```sql
CREATE TABLE roles (
    id SERIAL PRIMARY KEY,
    role_name VARCHAR(50) NOT NULL UNIQUE,     -- 'Student', 'Teacher', 'Curator', 'Parent'
    role_description VARCHAR(255) NOT NULL
);

CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    email VARCHAR(100) NOT NULL UNIQUE,
    salt VARCHAR(64) NOT NULL,
    password_hash VARCHAR(128) NOT NULL,
    role_id INTEGER NOT NULL,
    is_active BOOLEAN DEFAULT TRUE NOT NULL,
    failed_attempts SMALLINT DEFAULT 0 NOT NULL,
    locked_until TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT fk_edu_users_role FOREIGN KEY (role_id) 
        REFERENCES roles(id) ON UPDATE CASCADE ON DELETE RESTRICT
);

-- Таблица временных одноразовых токенов сброса пароля
CREATE TABLE password_resets (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    token_hash VARCHAR(128) NOT NULL UNIQUE,   -- Храним хэш токена, а не открытый токен
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
    is_used BOOLEAN DEFAULT FALSE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT fk_resets_user FOREIGN KEY (user_id) 
        REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT,
    attempted_login VARCHAR(100) NOT NULL,
    event_type VARCHAR(30) NOT NULL, -- 'LOGIN_SUCCESS', 'PWD_RESET_REQ', 'PWD_RESET_SUCCESS'
    ip_address VARCHAR(45) NOT NULL,
    event_time TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT fk_audit_edu_user FOREIGN KEY (user_id) 
        REFERENCES users(id) ON DELETE SET NULL
);
```

#### Задание 4.3. Аналитическое обоснование
1. **Хранение хэша токена сброса:** Если база данных утечет, злоумышленник с дампом открытых токенов смог бы сбросить пароли всех преподавателей и студентов. Хранение `token_hash` делает токен бесполезным для взломщика.
2. **Нейтральный ответ при сбросе:** Сообщение «Если аккаунт существует, инструкция отправлена» не позволяет злоумышленнику проверить базу данных на наличие email конкретных лиц.
3. **TTL токена и однократность (`is_used`):** Ограничение срока жизни (15 минут) минимизирует окно атаки при перехвате почты. Флаг `is_used = TRUE` защищает от повторного применения ссылки сброса.

| **Открытое хранение пароля** | Критическая уязвимость | **-2 балла** | Пароли запрещено хранить в открытом виде. Задание 1.1 аннулируется до исправления на `salt + hash`. |
| **Хэш без криптографической соли** | Архитектурная уязвимость | **-1 балл** | База данных уязвима к атакам по радужным таблицам. Требуется добавить поле `salt VARCHAR(64)`. |
| **Отсутствие уникальности логина (`UNIQUE`)** | Дефект целостности СУБД | **-0.5 балла** | При дублировании логина авторизация завершится ошибкой множественного результата. |
| **Каскадное удаление `ON DELETE CASCADE` на пользователях** | Дефект целостности данных | **-0.5 балла** | При удалении роли удалятся все пользователи, либо при удалении пользователя сотрется аудит. Использовать `is_active`. |
| **Подсказка «Пользователь не найден» в форме** | Уязвимость User Enumeration | **-0.5 балла** | Форма должна выводить единое нейтральное сообщение «Неверный логин или пароль». |
| **Отсутствие маскирования пароля маркерами** | Дефект эргономики / UX | **-0.5 балла** | Пароль на экране виден окружающим. Использовать `type="password"`. |
| **Игнорирование отраслевой специфики варианта** | Неполнота реализации | **-0.5 балла** | В форме нет селектора филиала, шага 2FA, экранной клавиатуры или окна сброса согласно варианту. |
