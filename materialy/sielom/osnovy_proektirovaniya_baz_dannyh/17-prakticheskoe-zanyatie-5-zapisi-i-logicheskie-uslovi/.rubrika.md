## 2. Критериальная шкала оценивания (Максимум — 4 балла)

В соответствии с локальными нормативными актами колледжа СИЭУиП итоговая оценка за практическое занятие выставляется по 4-балльной шкале (сумма первичных баллов переводится в академическую оценку):

| Критерий | Первичный балл | Требования к ответу студента |
| :--- | :---: | :--- |
| **Критерий 1: Составление условий фильтрации** | **2 балла** | **2 балла:** Предикаты составлены абсолютно верно. Корректно использованы логические связки `AND`, `OR`, `NOT`, соблюден приоритет операций (расставлены круглые скобки при дизъюнкции), применены предикаты `BETWEEN`, `IN`, `LIKE/ILIKE`, `IS NULL`. Синтаксис SQL полностью валиден.<br>**1 балл:** Допущена некритичная синтаксическая опечатка или пропущены скобки при сочетании `AND` и `OR`, не приведшие к фатальному искажению логики (либо верно выполнено только одно из двух условий).<br>**0 баллов:** Грубая логическая ошибка (например, объединение несовместимых предикатов через `AND` вместо `OR`), сравнение вида `= NULL`, отсутствие фильтра `WHERE`. |
| **Критерий 2: Протокол модификации записей** | **1 балл** | **1 балл:** Пошагово зафиксированы состояния строк таблицы «до» и «после» выполнения модификации (`UPDATE`). Корректно определено точное подмножество затронутых кортежей (ни одна лишняя строка не изменена, ни одна целевая строка не пропущена). Вычислены новые значения атрибутов.<br>**0 баллов:** Ошибочно определен состав модифицируемых записей (изменены лишние строки или пропущены целевые), неверно пересчитаны значения полей, протокол не заполнен. |
| **Критерий 3: Учет трехзначной логики (3VL) и самопроверка** | **1 балл** | **1 балл:** Студент продемонстрировал понимание трехзначной логики SQL (`TRUE`, `FALSE`, `UNKNOWN`). Даны верные ответы на контрольные вопросы по поведению `NULL` в логических выражениях (`AND`, `OR`, `NOT`). Предложен регламент предварительного аудита через `SELECT` и транзакции.<br>**0 баллов:** Ошибки в таблицах истинности 3VL, непонимание того, почему `NULL = NULL` дает `UNKNOWN`, отказ от самопроверки. |

### Шкала перевода первичных баллов в академическую оценку:
- **4 балла** — Отметка **«5» (Отлично)**. Безупречное владение DML, составными условиями, трехзначной логикой и регламентом аудита.
- **3 балла** — Отметка **«4» (Хорошо)**. Небольшие недочеты в расстановке скобок или формулировке вопросов самопроверки при верном результате модификации.
- **2 балла** — Отметка **«3» (Удовлетворительно)**. Базовые запросы составлены, но допущены ошибки в протоколировании строк или путаница в логических связках.
- **0–1 балл** — Отметка **«2» (Неудовлетворительно)**. Фатальные ошибки в предикатах, полное непонимание DML и трехзначной логики.

3. ID=3, Название='Омега-3 Комплекс', Категория='Витамины', Остаток=15, Цена=800.00, Годен_до='2026-11-20' *(Годен_до < 2026-12-31)*
4. ID=4, Название='Поливитамины Актив', Категория='Витамины', Остаток=50, Цена=600.00, Годен_до='2028-01-10' *(Остаток = 50 — граница BETWEEN)*
5. ID=5, Название='Ибупрофен Форте', Категория='Обезболивающие', Остаток=30, Цена=150.00, Годен_до='2027-12-31' *(Категория != 'Витамины')*

**Задание:** Повысить цену на 10% для товаров категории 'Витамины' с остатком `BETWEEN 5 AND 50` И датой годности `> '2026-12-31'`.

**Эталонный SQL-запрос предварительной проверки:**
```sql
SELECT product_id, product_name, category, stock_quantity, price, expiration_date
FROM pharmacy_products
WHERE category = 'Витамины'
  AND stock_quantity BETWEEN 5 AND 50
  AND expiration_date > '2026-12-31';
```

**Эталонный SQL-запрос модификации:**
```sql
BEGIN TRANSACTION;

UPDATE pharmacy_products
SET price = ROUND(price * 1.10, 2)
WHERE category = 'Витамины'
  AND stock_quantity BETWEEN 5 AND 50
  AND expiration_date > '2026-12-31';

-- Ожидаемый результат: модифицировано ровно 2 строки (ID 1 и ID 4).
COMMIT;
```

**Протокол модификации до/после:**
- ID 1: Цена 120.00 -> 132.00 (Остаток 25 входит в [5; 50], дата 2027-05-01 > 2026-12-31) — **МОДИФИЦИРОВАНА**
- ID 2: Цена 450.00 -> 450.00 (Остаток 4 < 5, условие ложно) — **БЕЗ ИЗМЕНЕНИЙ**
- ID 3: Цена 800.00 -> 800.00 (Дата 2026-11-20 не превышает 2026-12-31) — **БЕЗ ИЗМЕНЕНИЙ**
- ID 4: Цена 600.00 -> 660.00 (Остаток 50 входит в границу BETWEEN, дата 2028-01-10 > 2026-12-31) — **МОДИФИЦИРОВАНА**
- ID 5: Цена 150.00 -> 150.00 (Категория не 'Витамины') — **БЕЗ ИЗМЕНЕНИЙ**

5. ID=105, Модель='Solaris', Марка='Hyundai', Год=2023, Пробег=9000, Статус='В наличии' *(Марка не Toyota и не Lexus)*

**Задание:** Перевести в статус 'Забронирован' автомобили марки 'Toyota' ИЛИ 'Lexus' с годом выпуска `>= 2023` И пробегом `< 15000`.

**Эталонный SQL-запрос модификации:**
```sql
BEGIN TRANSACTION;

UPDATE dealership_cars
SET status = 'Забронирован'
WHERE (brand = 'Toyota' OR brand = 'Lexus')
  AND year_manufactured >= 2023
  AND mileage < 15000;

-- Ожидаемый результат: модифицировано ровно 2 строки (ID 101 и ID 102).
COMMIT;
```
*Критическая методическая точка:* обязательное наличие скобок вокруг `(brand = 'Toyota' OR brand = 'Lexus')`. Без скобок из-за приоритета `AND` запрос забронирует все автомобили Toyota независимо от года и пробега!

**Эталонный SQL-запрос модификации:**
```sql
BEGIN TRANSACTION;

UPDATE warehouse_stock
SET status = 'Утилизация'
WHERE supplier = 'Логистик-Групп'
  AND (defect_count > 0 OR storage_days > 180);

-- Ожидаемый результат: модифицировано ровно 3 строки (ID 301, ID 302, ID 305).
COMMIT;
```
*Критическая методическая точка:* обязательная группировка условий списания в круглые скобки `(defect_count > 0 OR storage_days > 180)`. Без скобок товары сторонних поставщиков с хранением более 180 дней были бы ошибочно списаны!

## 4. Классификатор типичных ошибок и штрафные санкции

| Код ошибки | Суть ошибки | Последствия в СУБД | Штраф |
| :---: | :--- | :--- | :---: |
| **ERR-01** | Отсутствие секции `WHERE` при `UPDATE`/`DELETE` | Полная перезапись или уничтожение всех кортежей отношения | **-2 балла** (аннулирование критерия 1) |
| **ERR-02** | Сравнение со значением `NULL` через `=` или `<>` (`field = NULL`) | Выражение всегда возвращает `UNKNOWN`, предикат не срабатывает | **-1 балл** |
| **ERR-03** | Отсутствие скобок при совмещении `AND` и `OR` | Нарушение логики из-за более высокого приоритета `AND` над `OR` | **-1 балл** |
| **ERR-04** | Использование синтаксиса `field = 'A' OR 'B'` | Синтаксическая ошибка в SQL (требуется повторение имени поля или `IN`) | **-0.5 балла** |
| **ERR-05** | Неверные границы в операторе `BETWEEN` (`BETWEEN 50 AND 5`) | Предикат всегда возвращает `FALSE`, так как нижняя граница должна предшествовать верхней | **-1 балл** |
| **ERR-06** | Ошибки в протоколе изменений до/после (неверный список ID) | Несоответствие затронутых строк составленному предикату | **-1 балл** |
