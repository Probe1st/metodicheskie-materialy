# Закрытая критериальная рубрика преподавателя — занятие 29

**Не выдавать вместе с рабочим листом студенту.** Оценивать по представленному варианту; максимум — 4 балла.

| Критерий | Баллы | Признаки полного выполнения |
|---|---:|---|
| Выбор типов данных и обоснование | 0–2 | 2 — типы соответствуют смыслу значений; названы точность/погрешность/длина/диапазон; диалект указан для специальных типов. 1 — основная идея верна, но есть одно существенное упущение или слабо обоснованный тип. 0 — выбор приводит к очевидному искажению/потере смысла либо ответ отсутствует. |
| Синтаксис операторов и приведение типов | 0–1 | 1 — выражения синтаксически понятны; CAST и типы согласованы; риски преобразования/диалекта распознаны. 0 — существенная синтаксическая ошибка или некорректное приведение не замечено. |
| Выводы и самопроверка | 0–1 | 1 — сформулирован вывод по заданному сценарию, названа хотя бы одна проверка/ошибка и ограничение. 0 — вывода нет либо он не связан с выбранными типами. |

## Эталоны для быстрой сверки

### Вариант 1 — Финансы

```sql
SELECT CAST(12.30 AS NUMERIC(15,2)) + CAST(7.70 AS NUMERIC(15,2)) AS total;
SELECT CURRENT_TIMESTAMP + INTERVAL '30 days' AS due_at;
```

Деньги — NUMERIC/DECIMAL, не FLOAT: двоичные приближённые значения могут накапливать погрешность и отображаться с неожиданным округлением. `INTERVAL '30 days'` задаёт интервал времени; арифметика конкретных календарных операций зависит от СУБД и временной зоны. Для пени можно сначала определить ставку и основу расчёта, а затем выражение; не считать неопределённую ставку частью условия.

### Вариант 2 — Логистика (PostgreSQL)

```sql
CREATE TABLE parcel (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  coordinates DOUBLE PRECISION[],
  metadata JSONB
);
SELECT metadata->>'status' FROM parcel;
```

UUIDv4 создаётся функцией СУБД/расширения, наличие `gen_random_uuid()` зависит от установленной версии/конфигурации PostgreSQL. `JSONB`, `->>` и массивы — диалект PostgreSQL. Координаты в плавающей точке допустимы, если точность приложения и диапазон согласованы; FLOAT[] в PostgreSQL синонимичен массиву float4, но double precision часто подходит точнее.

### Вариант 3 — Кадры

```sql
SELECT CURRENT_TIMESTAMP - hired_at AS tenure_interval
FROM employee;
SELECT CAST(age_text AS INTEGER) FROM employee;
```

`hired_at` обычно хранит момент в типе временной метки с осознанной семантикой зоны. Разность двух меток даёт интервал/длительность в зависимости от СУБД. Приведение `age_text` упадёт при нечисловой строке или переполнении; проверку/валидацию следует выполнять до CAST. Конкретные безопасные функции проверки зависят от диалекта.

### Вариант 4 — E-commerce

```sql
SELECT TRIM(UPPER(prefix || sku)) AS normalized_code,
       CAST('2026-10-01' AS DATE) AS order_date;
```

`||` — стандартная конкатенация SQL, но отдельные СУБД могут отличаться режимом/поддержкой. `UPPER` меняет регистр, `TRIM` удаляет пробелы по краям. ISO-дата однозначнее многих локальных форматов; преобразование плохой строки вызывает ошибку.

## Частые ошибки и оценивание

- Использование FLOAT/REAL для точной денежной суммы без пояснения — снять 1 балл за выбор типа.
- Хранение момента события как VARCHAR без причины — снять до 1 балла за тип.
- Утверждение, что `::`, JSONB или ARRAY — универсальны для всех СУБД — снять часть балла выбора и/или синтаксиса.
- Смешение строкового литерала `'42'` и идентификатора `42` — ошибка синтаксиса/типа.
- Игнорирование невалидного ввода и переполнения при CAST — 0 за синтаксис/приведение, если это ключевая часть сценария.
- Для кадров считать возраст/стаж в годах обычной разностью timestamp без объяснения календарной логики — частичный балл; требовать назвать неоднозначность «полных лет».
- Не требовать от студента угадывать версию СУБД: достаточно обозначить PostgreSQL и отметить зависимые функции.

**Интерпретация:** 4 — уверенное владение; 3 — в целом верно, отдельная неточность; 2 — частичное понимание, необходим разбор; 0–1 — требуется повторное объяснение базовых принципов.
