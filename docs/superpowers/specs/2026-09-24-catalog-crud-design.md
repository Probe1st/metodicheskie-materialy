# CRUD-каталог учебных групп, предметов и тем

> Исторический проект CRUD-каталога. Правила владения темами предметами, формат JSON v3 и массовое сопоставление определены в [спецификации привязки тем к предметам](2026-09-24-subject-topic-ownership-design.md) и заменяют соответствующие разделы ниже.

## Цель

Дать преподавателю отдельные административные страницы для полного CRUD групп, предметов и тем. Текущий каталог хранится в JSON, но все потребители зависят от стабильного порта хранилища, а не от JSON: впоследствии поставщик заменяется на SQLite или PostgreSQL без изменения HTTP-маршрутов, шаблонов и клиентского кода.

## Границы

- Включены три сущности: группа, предмет, тема.
- Для каждой сущности доступны создание, список, переименование и удаление.
- Включены отдельные страницы: обзор админки, доступы групп, группы, предметы и темы.
- Связи между сущностями не вводятся в этой работе. В частности, группы не связываются с предметами, а темы не принадлежат предметам.
- Существующая страница сдачи сохраняет выбор группы и предмета; список тем становится глобальным, без фильтрации по предмету.
- Не включены импорт/экспорт, сортировка перетаскиванием, архивирование, массовые операции, роли пользователей и PostgreSQL-соединение.

## Доменная модель

### Сущности

| Сущность | Поля | Инварианты |
| --- | --- | --- |
| `Group` | `id`, `name` | Идентификатор UUID; непустое уникальное имя. |
| `Subject` | `id`, `name` | Идентификатор UUID; непустое уникальное имя. |
| `Topic` | `id`, `name` | Идентификатор UUID; непустое уникальное имя. |

Строковые имена обрезаются по краям и сравниваются без учёта регистра. Идентификаторы не меняются при переименовании. Удаление необратимо после подтверждения в UI.

### Совместимость с текущими данными

`catalog.json` мигрирует с текущей структуры `groups: string[]` и `disciplines: { subject: string[] }` в версионированный документ:

```json
{
  "version": 2,
  "groups": [{"id": "...", "name": "ИС 25/9-1П"}],
  "subjects": [{"id": "...", "name": "Архитектура аппаратных средств"}],
  "topics": [{"id": "...", "name": "Логические элементы. Базовые схемы"}]
}
```

При первом чтении JSON-провайдер распознаёт старую структуру, создаёт стабильные UUID для её элементов, объединяет одинаковые темы из разных прежних предметов по нормализованному имени и атомарно записывает версию 2. Миграция не удаляет данные.

Перед первым запуском после обновления сохраните копию `catalog.json`: при первом запросе приложение мигрирует файл на версию 2. Остановите сервис перед восстановлением резервной копии. `CATALOG_PROVIDER=json` выбирает текущий провайдер; значения `sqlite` и `postgresql` до появления реализаций запрещают старт с явной ошибкой, а не переключаются на JSON молча.

`Catalog` в памяти предоставляет упорядоченные `groups`, `subjects` и `topics`. Для совместимости формы сдачи `contains(group, subject, topic)` проверяет независимое существование всех трёх сущностей. Поэтому тема допустима с любым предметом до появления отдельной связи между предметом и темой.

## Порт хранилища

В модуле `app/catalog_store.py` определяется абстрактный `CatalogStore` с операциями:

```python
list_groups() -> tuple[CatalogItem, ...]
create_group(name: str) -> CatalogItem
rename_group(item_id: UUID, name: str) -> CatalogItem
delete_group(item_id: UUID) -> CatalogItem

list_subjects() -> tuple[CatalogItem, ...]
create_subject(name: str) -> CatalogItem
rename_subject(item_id: UUID, name: str) -> CatalogItem
delete_subject(item_id: UUID) -> CatalogItem

list_topics() -> tuple[CatalogItem, ...]
create_topic(name: str) -> CatalogItem
rename_topic(item_id: UUID, name: str) -> CatalogItem
delete_topic(item_id: UUID) -> CatalogItem

snapshot() -> Catalog
```

`CatalogItem` — неизменяемая модель с `id: UUID` и `name: str`. Ошибки порта: `CatalogItemNotFound` для отсутствующего UUID и `CatalogNameConflict` для неуникального имени.

`JsonCatalogStore` — единственная рабочая реализация. Она сериализует изменения между несколькими Gunicorn-процессами через отдельный файл блокировки с `flock` (замок процесса в памяти недостаточен), сохраняет JSON во временный файл в каталоге назначения, синхронизирует файл и выполняет `os.replace`; после сбоя файл каталога остаётся валидным.

`SqliteCatalogStore` и `PostgresCatalogStore` пока определены только как будущие реализации того же порта; конфигурация выбирает провайдер по `CATALOG_PROVIDER=json`. Значения `sqlite` и `postgresql` возвращают ясную ошибку запуска, пока реализации не установлены. Маршруты получают один экземпляр порта из фабрики `create_catalog_store(config)`.

## Группа и доступ к сдаче

Доступы хранятся в существующем `AccessStore`, отдельно от каталога.

Чтение и изменение доступа, административные изменения групп и привязка студенческой сессии к UUID сериализуются отдельным межпроцессным замком `PRIVATE_DATA_DIR/group-state.lock`. Это исключает создание записи доступа под новым именем во время переименования и привязку старого пароля к повторно созданной группе. JSON-провайдер использует свой замок для всех операций каталога; порядок захвата в HTTP-маршрутах: сначала замок состояния групп, затем замок провайдера.

- Создание группы добавляет сущность в каталог; запись доступа создаётся лениво при первой странице доступов либо при первом обращении к `AccessStore`.
- Переименование группы переносит запись `group_access` на новое имя без потери пароля, дедлайна и версии доступа. Все текущие сессии группы инвалидируются повышением версии.
- Удаление группы удаляет её `group_access`; тем самым пароль и дедлайн стираются, а сессии группы перестают проходить серверную проверку. Студенческая сессия хранит UUID группы, чтобы удаление и повторное создание группы с прежним именем не восстановили старую сессию. Файлы в `storage/` никогда не удаляются.
- Удаление предмета или темы не удаляет загруженные файлы. Новая сдача с удалённым значением отвергается текущей проверкой каталога.

## HTTP и страницы

Все административные операции требуют существующей серверной административной сессии; неаутентифицированный запрос возвращает `403`.

| Страница | Назначение |
| --- | --- |
| `/admin` | Обзор и навигация к четырём разделам. |
| `/admin/access` | Нынешняя настройка доступа: пароль, открытость и дедлайн каждой группы. |
| `/admin/groups` | CRUD групп. |
| `/admin/subjects` | CRUD предметов. |
| `/admin/topics` | CRUD тем. |

Каждая CRUD-страница рендерит список сущностей, форму добавления и формы переименования/удаления. Операции выполняются через `fetch` и показывают успех или ошибку в той же строке/карточке. Перед удалением интерфейс запрашивает явное подтверждение с именем сущности. Ошибка конфликта имени или отсутствующего объекта не раскрывает внутренние детали и возвращается как `400` либо `404` соответственно.

Маршруты создают, переименовывают и удаляют сущности по UUID; имя никогда не используется как адресуемый идентификатор. Отдельный JS-модуль каталога переиспользуется для всех трёх страниц и передаёт тип сущности через `data-kind`.

## Навигация и визуальная система

В административной верхней панели остаётся ссылка к сдаче заданий. Внутри админки появляется боковая навигация:

- Обзор;
- Доступы групп;
- раздел «Каталог»: Группы, Предметы, Темы.

Активный раздел выделяется текущим лаймовым акцентом. Страницы используют существующие карточки, типографику и адаптивность; на мобильной ширине боковая навигация становится вертикальным списком над содержимым. Таблицы не используются: список сущностей — доступные карточки/строки с кнопками «Переименовать» и «Удалить».

## Проверка

- Модульные тесты доказывают CRUD каждого метода `JsonCatalogStore`, миграцию версии 1 в 2, атомарность записи и конфликты нормализованных имён.
- Тесты HTTP доказывают требование админ-сессии, успешный CRUD и синхронизацию переименования/удаления группы с `AccessStore`.
- Регрессия сдачи доказывает, что независимые группа, предмет и тема принимаются, а удалённое значение отвергается.
- Browser smoke: вход в `/admin`, переход в каждый раздел, создание, переименование и подтверждённое удаление каждой сущности; отдельная проверка удаления группы подтверждает исчезновение её доступа, а не файлов; desktop и 375px без горизонтальной прокрутки.
