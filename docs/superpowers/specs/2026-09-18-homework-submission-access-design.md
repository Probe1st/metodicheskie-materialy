# Проектирование доступа к приёму домашних заданий

## Цель

Добавить в сервис `homework-submissions` закрытую админку, в которой преподаватель управляет доступом каждой учебной группы к загрузке домашних заданий: задаёт пароль, открывает и закрывает приём, а также устанавливает момент автоматического закрытия.

## Границы и ограничения

- У каждой группы один пароль для всех дисциплин и работ этой группы.
- Доступ к админке защищён отдельным мастер-паролем преподавателя.
- Пароль группы, статус приёма и дедлайн меняются из админки без редактирования `.env` и без перезапуска приложения.
- Файлы состояния размещаются только в `homework-submissions/.private/`; Nginx уже не обслуживает пути, чьи компоненты начинаются с точки.
- `.private/` исключается из Git и имеет права `0700`; файл базы — `0600`.
- Пароли групп хранятся только как стойкие хеши. Исходные пароли невозможно просмотреть после сохранения. Мастер-пароль передаётся приложению через исключённый из Git `.env` и не записывается в SQLite.
- Старый общий `SUBMISSION_PASSWORD` удаляется: без действующего доступа конкретной группы загрузка запрещена.

## Архитектура

SQLite-база `homework-submissions/.private/access.sqlite3` хранит одну запись на группу из каталога: идентификатор группы, хеш пароля, флаг открытия и необязательный момент закрытия в UTC. Модуль доступа отвечает за инициализацию базы, операции администратора и принятие решения о доступе; HTTP-маршруты не выполняют SQL напрямую.

Мастер-пароль передаётся через `ADMIN_PASSWORD` в окружении и проверяется постоянным по времени сравнением. После входа серверная сессия Flask помечается как административная. Админка позволяет для каждой группы сохранить новый пароль, открыть либо закрыть приём и установить/очистить дедлайн. Дедлайн вводится в локальном часовом поясе сервера и сохраняется в UTC. Сохранение нового пароля немедленно аннулирует студенческие сессии этой группы через версию доступа, сохранённую в записи группы.

Студент сначала выбирает группу и вводит её пароль. При успешной проверке браузерская сессия сохраняет группу и версию доступа. При `POST /submit` сервер повторно проверяет: группа в сессии совпадает с формой, группа открыта, дедлайн ещё не наступил и версия доступа не изменилась. Поэтому загрузка отклоняется после закрытия или смены пароля, даже в уже открытой вкладке.

## Компоненты

| Компонент | Ответственность |
|---|---|
| `app/access.py` | SQLite, хеширование паролей, модели состояния и проверка доступа. |
| `app/web.py` | Маршруты студента и администратора, проверка Flask-сессий, ответы HTTP. |
| `app/templates/index.html` | Выбор группы, ввод пароля группы, форма загрузки после успешного доступа. |
| `app/templates/admin.html` | Вход преподавателя и управление доступом каждой группы. |
| `.env.example` | Документирует `ADMIN_PASSWORD`, `PRIVATE_DATA_DIR`; не содержит рабочих секретов. |
| `.gitignore` | Исключает `.private/` из репозитория. |

## Поток студента

1. Студент выбирает группу и вводит её пароль.
2. Сервер проверяет хеш, открытость группы и дедлайн.
3. При успехе сессия получает группу и текущую версию доступа.
4. При загрузке сервер повторяет проверку; отказ возвращает `403`.
5. Новый пароль, ручное закрытие либо наступивший дедлайн делают старую сессию недействительной.

## Поток преподавателя

1. Преподаватель входит на `/admin` по мастер-паролю.
2. На странице отображаются все группы каталога, их статус и дедлайн; пароли никогда не отображаются.
3. Для каждой группы преподаватель задаёт новый пароль, выбирает статус и указывает локальный момент закрытия или отключает дедлайн.
4. Сервер сохраняет изменения, повышает версию доступа и возвращает к таблице.

## Ошибки и безопасность

- Неверный пароль, закрытая группа, истёкший дедлайн или устаревшая студенческая сессия — `403`; подробная причина не раскрывается.
- Неаутентифицированный запрос к административным операциям — `403`.
- Группа берётся из сессии, а не доверяется полю формы загрузки.
- Каталог `.private/` создаётся с ограниченными правами; база создаётся с ограниченными правами.
- В production обязателен сильный `SECRET_KEY` и заданный `ADMIN_PASSWORD`; тестовый режим допускает тестовые значения.

## Проверка

Тесты должны подтвердить: доступ без разблокировки запрещён; пароль действует только для выбранной группы; закрытие, дедлайн и смена пароля отменяют уже выданный доступ; административные операции требуют мастер-пароля; новая конфигурация группы применяется без перезапуска. Smoke-проверка через Flask test client должна пройти путь входа в админку, открытия группы, разблокировки и загрузки файла.
