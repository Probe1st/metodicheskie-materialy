# Дизайн интерфейса приёма домашних заданий

## Цель

Заменить минимальные HTML-страницы сервиса `homework-submissions` на цельный, спокойный и адаптивный интерфейс для студентов и преподавателя. Визуальный стиль — «спокойный и премиальный»: интерфейс должен помогать сдать или настроить приём работы, а не отвлекать декоративными элементами.

## Границы

- Сохраняются Flask, Jinja, существующие маршруты и контракт ответов: `/`, `/unlock`, `/submit`, `/admin`, `/admin/login`, `/admin/logout`, `/admin/groups`.
- Сохраняются все поля, требования к доступу и серверная проверка данных.
- CSS и JavaScript переносятся из шаблонов в статические файлы; шаблоны содержат семантическую разметку и данные Jinja.
- Никакой библиотеки UI, сборки фронтенда или новых сетевых запросов, кроме существующих.

## Визуальная система

### Палитра

| Назначение | Значение |
| --- | --- |
| Основной цвет | глубокий хвойный `#173F37` |
| Базовый фон | молочный `#FBFAF6` |
| Поверхности | белый и бледный серо-зелёный |
| Акцент действия | лаймовый `#D5EF67` |
| Основной текст | тёмный зелёно-чёрный |
| Ошибка | контрастный тёмно-красный на светлой красной поверхности |

Один акцентный цвет служит интерактивным действиям. Ошибка, успех, фокус и открытость группы дополняются текстом и формой, поэтому смысл не зависит только от цвета.

### Типографика и композиция

- Выразительный системный serif применяется только к крупным заголовкам.
- Системный sans-serif используется для всех контролов, статусов, таблиц и вспомогательного текста.
- Страница состоит из верхней панели, ограниченного по ширине содержимого и карточек с тонкими рамками и мягкими тенями.
- Запрещены градиенты, glassmorphism, анимированный фон, декоративные иконки без смысловой функции и несколько конкурирующих акцентных цветов.

### Доступность

- Все поля сохраняют видимые `label`.
- Фокусные состояния клавиатуры заметны на светлом и тёмном фоне.
- Статусы используют `aria-live` и роль, соответствующую результату.
- Контраст текста и элементов управления достаточен для чтения без опоры на цвет.
- Анимация переходов короткая и отключается пользователям с `prefers-reduced-motion`.

## Студенческий сценарий

### Доступ

Главная страница показывает компактную верхнюю панель и центрированную карточку «Сдать работу. Без лишнего». В первом состоянии доступны только выбор группы и пароль. Под формой объясняется, что доступ зависит от настроек преподавателя.

После успешного `POST /unlock` форма доступа заменяется компактным блоком с выбранной группой и кнопкой «Сменить группу». Ошибка разблокировки остаётся у формы доступа и сообщает ровно текущую безопасную причину: доступ закрыт или пароль неверен.

### Данные и файл

Разблокированная форма разбита на понятные секции:

1. Дисциплина и наименование работы.
2. ФИО студента.
3. Файл в зоне загрузки с разрешённым максимальным размером.

Выбор дисциплины обновляет существующий список работ. Выбранный файл отображается в зоне загрузки до отправки. Повторная отправка блокируется на время текущего запроса.

Успех `201` показывает отдельный блок «Работа принята» с возвращённым именем файла и действием «Отправить ещё одну». Ошибка `400`, `403`, `413` либо сбой сети показывает различимый блок ошибки; при этом уже введённые данные не очищаются.

## Административный сценарий

### Вход

Неаутентифицированная страница `/admin` использует тот же каркас и одну небольшую карточку входа с полем мастер-пароля. После корректного ответа `/admin/login` страница перезагружается в панель. Неверный пароль отображается возле поля.

### Управление группами

Аутентифицированная панель включает:

- верхнюю панель с кнопкой выхода;
- итоговые счётчики открытых и закрытых групп;
- адаптивную сетку карточек групп вместо HTML-таблицы;
- в каждой карточке — название группы, статус-чип, переключатель приёма, поле локального дедлайна, поле нового пароля и кнопку сохранения.

Открытая группа имеет явный текстовый статус «Приём открыт», закрытая — «Приём закрыт». Незаполненный дедлайн означает отсутствие автоматического закрытия. Пароль нельзя увидеть после сохранения; пустое поле сохраняет существующий пароль.

Отправка конкретной карточки через `/admin/groups` изменяет только её кнопку на «Сохранение…». Успех или ошибка выводятся в этой карточке; глобальный статус не используется. Карточка остаётся корректной на узком экране без горизонтального скролла.

## Файлы и ответственность

| Файл | Ответственность |
| --- | --- |
| `homework-submissions/app/static/styles.css` | Токены, типографика, каркас, карточки, формы, статусы, адаптивность и reduced motion. |
| `homework-submissions/app/static/student.js` | Разблокировка, список работ, выбранный файл, состояния отправки и результат. |
| `homework-submissions/app/static/admin.js` | Вход, сохранение одной группы, локальные состояния кнопок и статусов. |
| `homework-submissions/app/templates/index.html` | Семантическая разметка студентского сценария, Jinja-данные каталога. |
| `homework-submissions/app/templates/admin.html` | Семантическая разметка входа и карточек групп, Jinja-данные состояния. |

Серверные файлы и HTTP-контракты не меняются.

## Проверка

- Существующий набор `pytest` продолжает проходить без изменения контрактов маршрутов.
- Браузерная smoke-проверка подтверждает: разблокировку, выбор дисциплины, вид выбранного файла, ошибку/успех отправки; вход администратора, сохранение одной группы и локальный статус этой карточки.
- На ширине мобильного экрана обе страницы остаются читаемыми и не получают горизонтальную прокрутку.
