# Комплект материалов ОП.02 «Архитектура аппаратных средств» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать автономный набор из 21 тематической папки и 89 готовых к деплою учебных файлов по ОП.02 «Архитектура аппаратных средств».

**Architecture:** Содержательные данные уроков и реестр источников хранятся отдельно от Python-генератора. Генератор собирает автономные HTML-страницы из семантического шаблона, а затем Google Chrome в безголовом режиме печатает слайдовые HTML-страницы в PDF. Отдельный валидатор сверяет дерево публикации с манифестом и проверяет обязательные признаки качества в каждом документе.

**Tech Stack:** Python 3 standard library, HTML5, embedded CSS, JSON, Google Chrome stable headless PDF printing.

## Global Constraints

- Выходной каталог имеет точное имя `АНПОО_СИЭУиП_11_25_ОП.02_Архитектура_аппаратных_средств`.
- Создаются 21 нумерованная папка: 13 теоретических и 8 практических.
- Теоретическая папка содержит пять файлов: `metodicheskiy_material.html`, `prezentaciya.pdf`, `prakticheskaya_rabota.html`, `prakticheskoe_zadanie.html`, `domashnee_zadanie.html`.
- Практическая папка содержит только `prakticheskaya_rabota.html`, `prakticheskoe_zadanie.html`, `domashnee_zadanie.html`.
- Итого результат содержит ровно 89 публикуемых файлов; лекционные HTML и PDF в практических папках запрещены.
- HTML автономны: UTF-8, встроенный CSS, без JavaScript, CDN, внешних шрифтов, учётных записей или сетевых изображений.
- Текст обращён непосредственно к студенту; в публикационных документах запрещены сведения о классе, типе образовательной организации, длительности занятия и формулировки «пара»/«академический час».
- Любое фактическое утверждение об актуальном стандарте, интерфейсе или изделии опирается на релевантный первичный источник с URL и датой обращения 2026-09-09.
- Задания не требуют платного ПО или приобретения оборудования и не включают опасные действия с включённой техникой, БП, BIOS/UEFI либо непроверенным ПО.

## File Structure

- `research/architecture_sources.json` — список проверенных первичных и академических источников: URL, издатель, разделы применения и дата обращения.
- `content/lessons.json` — полный манифест 21 занятия и все авторские блоки текста, упражнений, критериев и источников для 89 документов.
- `tools/build_hardware_architecture_materials.py` — создаёт каталог публикации, HTML-страницы и слайдовые HTML для последующей печати в PDF.
- `tools/validate_hardware_architecture_materials.py` — проверяет структуру, количество документов, маркеры содержания, отсутствие запрещённых лекционных файлов в практиках и наличие PDF.
- `АНПОО_СИЭУиП_11_25_ОП.02_Архитектура_аппаратных_средств/**` — единственный публикуемый результат.

Манифест занятия в `content/lessons.json` использует следующую форму:

```json
{
  "number": "01",
  "slug": "История_развития_ЭВМ",
  "kind": "theory",
  "title": "История развития ЭВМ",
  "outcomes": ["различать механические, электромеханические и электронные вычислительные машины"],
  "terms": [{"term": "программа", "definition": "последовательность команд, которую выполняет вычислительная машина"}],
  "sections": [{"heading": "От механики к электронике", "body": ["Развитие ЭВМ связано с переходом от ручного привода к электрическим компонентам."], "example": {"title": "Сравнение принципов", "steps": ["Определи источник энергии.", "Определи способ представления данных."]}}],
  "checks": ["Почему реле ограничивало скорость вычислений?"],
  "in_class_task": {"prompt": "Составь шкалу из шести событий.", "deliverable": "таблица с датой, устройством и принципом действия", "rubric": ["шесть достоверных событий", "указаны источники"]},
  "practical_work": {"safety": ["Не разбирай включённое оборудование."], "equipment": ["браузер", "табличный редактор"], "steps": ["Изучи источники.", "Заполни таблицу.", "Проверь даты."], "deliverable": "таблица", "checklist": ["есть шесть строк", "есть ссылки"], "rubric": ["достоверность", "объяснение принципа"]},
  "practical_assignment": {"scenario": "Музей готовит карточку экспоната.", "tasks": ["Выбери устройство.", "Объясни его вклад."], "advanced": "Сравни с предшественником.", "submission": "одна страница PDF", "rubric": ["точность", "обоснование"]},
  "homework": {"required": ["Сравни два устройства из разных поколений."], "advanced": "Объясни изменение элементной базы.", "submission": "текстовый документ", "rubric": ["сравнение", "источники"]},

  "source_ids": ["computer-history-museum"]
```

`kind` принимает только `theory` или `practice`. Для `practice` ключи `sections`, `terms`, `checks`, `in_class_task` и `slides` отсутствуют; генератор не создаёт лекционные файлы.
