Занятие 42. Оформление документации: техническое задание — практическая работа

Ваш результат

Оформляет разделы технического задания с проверяемыми требованиями к программе.

Тема блока: Оформление документации. Ключевые слова: техническое задание, функциональное требование, ограничение, критерий.

Подготовка

Техническое задание пишите через идентификаторы и наблюдаемые критерии. Не используйте слова «удобный» или «быстрый» без сценария, условия и способа проверки.

Команды подготовки

python -m venv .venv
source .venv/bin/activate
python -m pip install pytest
python -m pytest -q

Стартовый фрагмент сервиса бронирования

Сохраните фрагмент в booking_service.py. Он синтаксически завершён; тесты добавляйте отдельным файлом.

booking_service.py

REQUIREMENTS = {
    "REQ-BOOK-01": "Сервис подтверждает бронирование при доступном номере.",
    "REQ-BOOK-02": "Сервис сообщает об отсутствии свободных номеров.",
}


def requirement_ids() -> set[str]:
    return set(REQUIREMENTS)

Обязательная работа

  1. Опишите назначение и границы продукта в двух проверяемых абзацах.
  2. Сформулируйте не менее четырёх требований с идентификаторами и критериями приёмки.
  3. Создайте таблицу трассируемости «требование — тест — результат».

Усложнение

Добавьте одно нефункциональное требование только вместе со способом измерения и условиями сценария.

Ожидаемые артефакты

  • фрагмент технического задания
  • таблица требований
  • матрица трассируемости

Чек-лист сдачи

  • исходные файлы запускаются командой python -m pytest -q
  • ожидаемые и фактические результаты не смешаны
  • каждый тест или раздел связан с конкретным правилом
  • изменения отражены в истории или краткой заметке

Критерии оценки результата

  • правила темы выражены проверяемыми входами, действиями и результатами
  • артефакты полны и согласованы между собой
  • выводы опираются на наблюдение, а не на предположение
