Занятие 29. Управление версиями документации — методический материал

Ваш результат

Организует хранение версий документа и фиксирует историю согласованных изменений.

Тема блока: Средства и технологии документации. Ключевые слова: версионирование, история изменений, согласование, репозиторий.

Методический разбор

Версия документа связывает текст с состоянием продукта и решением об изменении. В истории полезны не только номер и дата: зафиксируйте, что изменилось, почему и какие связанные разделы нужно перечитать.

Понятия для работы

История изменений
Упорядоченная запись о причинах и содержании согласованных правок.
Версионный идентификатор
Краткое обозначение состояния документа, на которое можно сослаться.

Создайте два файла с указанными именами, затем запустите проверку командой python -m pytest -q. Сначала прочитайте ожидаемый результат теста и только затем меняйте код.

booking_service.py

def change_entry(version: str, summary: str) -> str:
    if not version or not summary:
        raise ValueError("Версия и описание изменения обязательны")
    return f"{version}: {summary}

test_booking_service.py

import pytest

from booking_service import change_entry


def test_history_entry_keeps_version_and_reason() -> None:
    assert change_entry("1.1", "Уточнён порядок отмены") == "1.1: Уточнён порядок отмены"


def test_history_entry_rejects_empty_summary() -> None:
    with pytest.raises(ValueError):
        change_entry("1.1", "")

Практический маршрут

  1. Создайте три записи истории для функции бронирования.
  2. Отметьте связанный раздел для каждой записи.
  3. Проверьте, что новая версия не скрывает нерассмотренное замечание.
