Занятие 03. Классификация ошибок программного обеспечения — методический материал

Ваш результат

Вы сможете: различать дефекты требований, проектирования, кода и эксплуатации по их проявлениям.

Тема блока: Ошибки и отладка. Ключевые слова: дефект, ошибка, отказ, первопричина.

Методический разбор

Не смешивайте причину, действие человека, дефект в артефакте и наблюдаемый отказ. Разложение цепочки позволяет исправлять первопричину, а не только маскировать сообщение об ошибке.

Понятия для работы

Дефект
Свойство требования, проекта или кода, которое может привести к неверному поведению.
Отказ
Наблюдаемое расхождение поведения программы с ожидаемым результатом.

Выполнимый пример Python и pytest

Создайте два файла с указанными именами, затем запустите проверку командой python -m pytest -q. Сначала прочитайте ожидаемый результат теста и только затем меняйте код.

booking_service.py

def classify_incident(requirement_known: bool, program_started: bool) -> str:
    if not requirement_known:
        return "неполные исходные данные"
    if not program_started:
        return "отказ запуска"
    return "нужно уточнить наблюдение"

test_booking_service.py

from booking_service import classify_incident


def test_missing_requirement_is_not_named_runtime_failure() -> None:
    assert classify_incident(False, False) == "неполные исходные данные"


def test_start_failure_is_visible_after_requirements_are_known() -> None:
    assert classify_incident(True, False) == "отказ запуска"

  2. Почему одно сообщение об отказе не доказывает единственную первопричину?

Практический маршрут

  1. Опишите цепочку «условие — действие — дефект — отказ» для неверного промокода.
  2. Выберите место в цепочке, где можно добавить проверку до запуска программы.
  3. Запишите ожидаемое и фактическое значения для выбранного отказа.
