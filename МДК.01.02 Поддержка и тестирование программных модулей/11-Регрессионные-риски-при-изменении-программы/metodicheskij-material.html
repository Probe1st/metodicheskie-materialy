Занятие 11. Регрессионные риски при изменении программы — методический материал

Ваш результат

Оценивает вероятность регрессии после изменения требований, кода или окружения.

Тема блока: Регрессия. Ключевые слова: регрессия, изменение, анализ влияния, риск.

Методический разбор

Регрессия возникает как риск после изменения: прежнее ожидаемое поведение может нарушиться даже там, где код не редактировали напрямую. Анализируйте связи изменения с правилами, данными и зависимостями, а не только список изменённых строк.

Понятия для работы

Регрессионный риск
Вероятность нарушения уже подтверждённого поведения после изменения.
Анализ влияния
Поиск правил и сценариев, которые связаны с предполагаемым изменением.

Выполнимый пример Python и pytest

Создайте два файла с указанными именами, затем запустите проверку командой python -m pytest -q. Сначала прочитайте ожидаемый результат теста и только затем меняйте код.

booking_service.py

def apply_promo(total: int, code: str | None) -> int:
    if code == "SAVE10":
        return total - 10
    return total

test_booking_service.py

import pytest

from booking_service import apply_promo


@pytest.mark.parametrize(("code", "expected"), [("SAVE10", 90), (None, 100), ("OLD", 100)])
def test_existing_promo_paths_remain_visible(code: str | None, expected: int) -> None:
    assert apply_promo(100, code) == expected

Практический маршрут

  1. Составьте карту изменения: правило, зависимые сценарии, риск.
  2. Выберите один высокорисковый прежний сценарий.
  3. Добавьте тест, который сохранит его ожидаемый результат.
