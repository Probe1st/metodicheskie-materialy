Обеспечение качества функционирования компьютерных систем

Качество программного обеспечения и риски отказов

Что важно понять

Качество нельзя свести к отсутствию сообщений об ошибке. Пользователь оценивает, достигает ли он цели: оформляет ли заказ, получает ли понятное сообщение, сохраняются ли данные и не исчезают ли деньги со счёта. Поэтому проверка качества начинается с вопроса «какой результат нужен человеку?», а не с вопроса «сколько строк кода написано?».

Цепочка причин помогает говорить о проблемах точно. Неверно понятое условие — это ошибка; неверная проверка в функции — дефект; заказ со скидкой 200 % в интерфейсе — отказ. Один дефект может долго не проявляться, пока не появится подходящее входное значение или конфигурация.

Риск описывают через вероятность и влияние. Редкая проблема с потерей персональных данных может быть приоритетнее частого косметического дефекта. Для учебного сервиса заказов полезно сначала защитить расчёт суммы, доступ к заказам и сохранность статуса, а затем улучшать оформление страницы.

Качество создаёт вся команда: аналитик делает требования проверяемыми, разработчик пишет понятный код, тестировщик ищет несоответствия, а пользователь даёт обратную связь. Тестирование не доказывает абсолютное отсутствие дефектов; оно снижает неопределённость, предоставляя факты о проверенных сценариях.

Рабочий пример

def total_price(quantity: int, price: int, discount: int = 0) -> int:
    if quantity <= 0:
        raise ValueError("Количество должно быть положительным")
    if not 0 <= discount <= 100:
        raise ValueError("Скидка должна быть от 0 до 100")
    return quantity * price * (100 - discount) // 100

После работы с материалом вы объясняете разницу между потребностью пользователя, ошибкой, дефектом и наблюдаемым отказом; связываете риск с последствием.

Ключевые понятия

Качество

Степень, в которой продукт удовлетворяет заявленные и подразумеваемые потребности.

Ошибка

Действие человека, способное породить неверный результат.

Дефект

Недостаток в коде, требовании, настройке или документе.

Отказ

Наблюдаемое несоответствие фактического поведения ожидаемому.

Учебный кейс

Пользователь сообщает: «При скидке 100 % сервис показывает заказ на 0 рублей, но всё равно списывает деньги». Разделите сообщение на возможный отказ, возможный дефект, риск и данные, которые нужно собрать перед выводом.

Исходные данные

def total_price(quantity: int, price: int, discount: int = 0) -> int:
    if quantity <= 0:
        raise ValueError("Количество должно быть положительным")
    if not 0 <= discount <= 100:

Порядок действий

  1. Прочитайте сценарий заказа и выделите ожидание пользователя.
  2. Запишите минимум четыре риска для расчёта стоимости и статуса заказа.
  3. Для каждого риска оцените влияние: низкое, среднее или высокое.
  4. Сформулируйте проверку, которая даст наблюдаемый результат.

Самопроверка

  • Я могу объяснить, какое правило проверяю.
  • Я использую конкретные данные и ожидаемый результат.
  • Мой вывод опирается на наблюдение, а не на предположение.
