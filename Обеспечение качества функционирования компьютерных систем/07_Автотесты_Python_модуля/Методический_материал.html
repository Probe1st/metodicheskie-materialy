Ключевые понятия

Arrange–Act–Assert

Структура: подготовить данные, выполнить действие, проверить результат.

Изоляция

Независимость теста от внешнего состояния и других тестов.

Регрессионный тест

Тест, сохраняющий найденное правило после исправления дефекта.

Падение теста

Факт несоответствия ожидания и результата, требующий исследования.

Учебный кейс

В сервисе появилась жалоба: пользователь отменил уже отправленный заказ. Защитите правило модульными тестами, затем объясните, какой тест должен оставаться после исправления.

Исходные данные

# orders.py
def can_cancel(status: str) -> bool:
    return status in {"new", "paid"}

# Ошибка в исходной версии: статус shipped тоже возвращал True.

Порядок действий

  1. Создайте `test_orders.py` и добавьте импорт `can_cancel`.
  2. Подготовьте параметризованный набор допустимых и недопустимых статусов.
  3. Запустите `pytest -q` и сохраните вывод до исправления.
  4. Исправьте правило только после того, как тест воспроизвёл проблему.
  5. Запустите набор повторно и добавьте тест для неизвестного статуса.

Самопроверка

  • Я могу объяснить, какое правило проверяю.
  • Я использую конкретные данные и ожидаемый результат.
  • Мой вывод опирается на наблюдение, а не на предположение.
Что должно быть готово

Сохраните заполненный артефакт, список проверок и краткий вывод с обоснованием.
