Модульное тестирование на Python с pytest

Что важно понять

pytest находит функции с именем `test_` и использует обычный `assert`. При падении он показывает значения выражения, поэтому тесты остаются короткими и читаемыми. Один тест должен проверять одно важное правило: так причину падения легче понять и исправить.

Фикстура убирает повторяющуюся подготовку. Она не должна скрывать смысл теста: данные, влияющие на правило, оставляйте видимыми в сценарии. Если тест зависит от сети, времени или общего файла, сначала подумайте, как передать контролируемую замену зависимости.

Параметризация полезна для классов эквивалентности и границ. Вместо трёх почти одинаковых функций вы описываете таблицу входов и ожидаемых результатов. Названия параметров и идентификаторы наборов должны объяснять, что проверяется.

Тест на исключение — не тест «на ошибку вообще». Проверяйте конкретный тип и, когда это важно для пользователя или API, сообщение. Не ловите широкое `Exception`: так легко скрыть настоящую ошибку реализации.

Рабочий пример

import pytest

@pytest.mark.parametrize("quantity, price, discount, expected", [
    (1, 500, 0, 500),
    (2, 500, 10, 900),
    (3, 1000, 20, 2400),
])
def test_total_price(quantity, price, discount, expected):
    assert total_price(quantity, price, discount) == expected

def test_total_price_rejects_zero_quantity():
    with pytest.raises(ValueError, match="Количество"):
        total_price(0, 500)

После работы с материалом вы пишете читаемые модульные тесты с `assert`, фикстурами, параметризацией и проверкой исключений.

Ключевые понятия

Модульный тест

Проверка небольшой единицы поведения в изоляции.

Фикстура

Подготовленный ресурс или состояние для теста.

Параметризация

Запуск одного сценария с несколькими наборами данных.

Ожидаемое исключение

Проверка корректной реакции на недопустимые входные данные.

Учебный кейс

Функция расчёта цены уже работает в приложении, но никто не знает, защищены ли границы скидки и количества. Подготовьте минимальный, понятный набор автотестов.

Исходные данные

import pytest

@pytest.mark.parametrize("quantity, price, discount, expected", [
    (1, 500, 0, 500),
    (2, 500, 10, 900),
    (3, 1000, 20, 2400),

def test_total_price(quantity, price, discount, expected):
    assert total_price(quantity, price, discount) == expected

def test_total_price_rejects_zero_quantity():

        total_price(0, 500)

Порядок действий

  1. Создайте файл `test_pricing.py` и импортируйте функцию расчёта.
  2. Запишите позитивный сценарий без скидки.
  3. Добавьте параметризованные сценарии для границ скидки.
  4. Проверьте исключения для нулевого количества и скидки больше 100.

Самопроверка

  • Я могу объяснить, какое правило проверяю.
  • Я использую конкретные данные и ожидаемый результат.
  • Мой вывод опирается на наблюдение, а не на предположение.
