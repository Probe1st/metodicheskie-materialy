Обеспечение качества функционирования компьютерных систем

Дефекты, регрессия, покрытие и метрики

Что важно понять

Полезный отчёт о дефекте позволяет другому человеку воспроизвести проблему без догадок. В нём есть краткое название, окружение, предусловия, точные шаги, фактический и ожидаемый результаты, доказательства и серьёзность. Формулировка «не работает» не даёт команде достаточных данных.

После исправления сначала подтвердите исходную проблему теми же шагами. Затем подумайте, какие соседние правила могла затронуть правка, и выполните регрессию. Эти проверки отвечают на разные вопросы и обе нужны для безопасного изменения.

Покрытие строк показывает, какие строки исполнялись; покрытие ветвей дополнительно показывает, проходили ли разные исходы условий. Высокое покрытие не доказывает корректность ожидаемых результатов: можно выполнить строку без содержательной проверки. Низкое покрытие, наоборот, указывает, где у команды мало наблюдений.

Метрика становится полезной только в контексте решения. Не гонитесь за числом 100 %. Спросите: какие риски остаются непроверенными, какие сценарии чаще падают, какие дефекты повторяются и какая проверка дешевле всего снизит риск.

Рабочий пример

def shipping_fee(total: int, express: bool) -> int:
    if total >= 3000:
        return 0
    if express:
        return 500
    return 250

# Для покрытия ветвей нужны сценарии: total >= 3000,
# total < 3000 + express, total < 3000 + обычная доставка.

После работы с материалом вы оформляете воспроизводимый отчёт о дефекте и интерпретируете покрытие как сигнал, а не как гарантию качества.

Ключевые понятия

Отчёт о дефекте

Факт проблемы с шагами, ожидаемым и фактическим результатом.

Подтверждающее тестирование

Проверка конкретного исправления.

Регрессионное тестирование

Проверка, что изменение не повредило существующее поведение.

Покрытие

Мера того, какие части кода выполнились при тестах.

Учебный кейс

После изменения стоимости доставки тесты проходят, но в отчёте покрытия не выполнена ветвь экспресс-доставки. Объясните, какой риск остаётся и какой тест добавите.

Исходные данные

def shipping_fee(total: int, express: bool) -> int:
    if total >= 3000:
        return 0
    if express:
        return 500
    return 250

# Для покрытия ветвей нужны сценарии: total >= 3000,
# total < 3000 + express, total < 3000 + обычная доставка.

Порядок действий

  1. Оформите отчёт о дефекте по шаблону: заголовок, условия, шаги, ожидаемый и фактический результат.
  2. Разделите подтверждающую и регрессионную проверки.
  3. Нарисуйте ветви функции стоимости доставки.
  4. Подберите три теста, которые выполняют все показанные ветви.

Самопроверка

  • Я могу объяснить, какое правило проверяю.
  • Я использую конкретные данные и ожидаемый результат.
  • Мой вывод опирается на наблюдение, а не на предположение.

Практическая мини-задача

Выполните порядок действий, затем сравните свой результат с критериями самопроверки.

Вопросы для самопроверки

  3. Какие данные делают вывод воспроизводимым?
